# map_surface — поверхность оригинальных карт (ENV-MAPS, трек S-prep)

Статус: **технический кандидат**, художественной приёмки нет. Только CPU (numpy / scipy / PIL):
UE, Blender, GPU и платные сервисы не нужны.

Решения пользователя, на которых стоит трек:
- ENV-U1 «вся иллюстрация + 3D вокруг», вариант A: иллюстрация лежит плоско, 3D только по периметру;
- ENV-U2 «из иллюстрации карты»: игровой слой (круги, разделители зон, связи, ромбы стартов) измеряется
  на самой иллюстрации;
- ENV-U3 «вне git, импорт скриптом»: изображения и все производные текстуры и кадры лежат **вне git**.
  В git попадают только скрипты, sha256 и числа;
- масштаб — **2/3 uu на 1 px** исходника: доска 891,33 × 577,33 uu, круг ≈ Ø84 uu, шаг клеток ≈ 100 uu.

## Запуск

```bash
python -B tools/art/map_surface/build_map_textures.py              # обе карты, ≈55 с на карту
python -B tools/art/map_surface/build_map_textures.py --maps sarpedon
```

По умолчанию входы и выходы лежат в главном checkout (`--images`, `--maps-json`, `--topology`, `--derived`,
`--mocks` переопределяют пути):

| Вход | Путь | Проверка |
|---|---|---|
| Иллюстрация 1337×866 WebP | `scraped-data/images/maps/<key>.webp` (gitignored) | sha256 = `source.sha256` топологии, иначе остановка |
| Топология (центры, зоны, рёбра, старты) | `docs/game-design/evidence/ENV-MAPS/2026-09-30-research/<key>.topology.json` | — |
| SVG зон (углы разделителей) | `scraped-data/api/maps.json` (devalue, декодер `art_board_fixtures.decode_devalue_maps`, только чтение) | — |

Выход — скрипт детерминирован: два прогона подряд дают одинаковые sha256 всех файлов.

| Что | Где | В git |
|---|---|---|
| `T_<Map>_Map_BC_4K.png` — RGB8 sRGB 4096² | `scraped-data/derived/maps/<key>/` | нет |
| `T_<Map>_Map_GameSDF_4K.png` — RGBA16 4096² | то же | нет |
| `T_<Map>_Map_SpaceID_4K.png` — Gray16 4096² | то же | нет |
| `T_<Map>_Map_GameMask_4K.png` — Gray8 4096² | то же | нет |
| Моки K1 `<key>-{a,b,c}.png`, `<key>-ab-split.png`, `<key>-ab-ev.png`, `<key>-logo-before-after.png`, `checks/` | `C:/tmp/envmaps-research/k1-mocks/` | нет |
| `<key>.vector-layer.json` — измеренный игровой слой (только числа) | здесь | да |
| `manifest.<key>.json` — sha256 и размеры всех выходов, параметры, замеры K1 | здесь | да |

Пути выходов в манифесте записаны от канонических корней (`roots`): текстуры —
`scraped-data/derived/maps/<key>/…`, моки и кадры проверки — `<mocks>/…` (артефакты ревью, вне git).
`--derived` и `--mocks` меняют только место записи: манифест от них не зависит, байты опознаются по sha256.
sha256 топологии считается по тексту с LF, то есть по содержимому в git: core.autocrlf выдаёт эти
файлы на Windows с CRLF. `.gitattributes` здесь держит `*.json` в LF, иначе sha256 vector-layer
в манифесте разойдётся с файлом после checkout.

Модули: `vector_layer.py` (замер слоя), `inpaint.py` (закраска логотипа), `raster.py` (SDF / ID),
`k1_mock.py` (пинхол-рендер K1), `png16.py` (запись и чтение PNG 16 бит; PIL не пишет RGBA16).
Тесты: `python -B -m unittest tools/art/map_surface/test_map_surface.py -v`.

## UV и мир

- UV (0,0)–(1,1) — **вся** иллюстрация, растянутая в квадрат. Центр текселя (i, j) = пиксель исходника
  ((j+0,5)·1337/4096, (i+0,5)·866/4096). Плотность 3,0636 × 4,7298 текселя на px (4,595 × 7,095 на uu).
- Координаты исходника непрерывные, как в SVG и топологии: пиксель (i, j) занимает [j, j+1] × [i, i+1].
- Мир UE (как `CellToWorld` в S08, центр доски в начале координат): X = (u − 0,5)·891,333,
  Y = (v − 0,5)·577,333, Z = 0. Верх картинки — дальний край (−Y). Камера K1 с yaw −90 видит карту
  прямо, длинной стороной по горизонтали.

## Слои

**BC.** Логотип «UNMATCHED <MAP>» закрашен на исходном разрешении. Затем один проход Lanczos
1337×866 → 4096×4096: номинально ×3, фактически ×3,06 по X и ×4,73 по Y. После него лёгкий unsharp:
σ = 0,7 px исходника (анизотропно в текселях), сила 0,35.

**Закраска логотипа** (`inpaint.py`):
- exemplar-fill по Criminisi, патч 9 px;
- источники не берутся с кругов (r < 67–72 px) и связей;
- сшивка швов в градиентной области (Poisson).

Настройки по картам:
- Marmoreal — сакуры, заливка без классов;
- Sarpedon — логотип лежит на стыке листвы и травы под частоколом:
  - частокол («тёплые» пиксели) и его серая тень исключены из источников;
  - заливка ведётся по карте классов «листва / трава» (B > R), гармонически продолженной от края дыры,
    с шумом;
  - полосу шва перезаливают вторым проходом.

Кадры «до/после» — `<key>-logo-before-after.png`.

**SDF** (`GameSDF`, RGBA16, линейный). Расстояния евклидовы в **px исходника**, поэтому поле изотропно
на доске, хотя текстура растянута. Кодировка: `d_px = (code − 32768) / 512`, диапазон ±64 px.

| Канал | Что |
|---|---|
| R | знаковое расстояние до объединения дисков радиуса осевой линии обода (≈62,4 / 62,15 px); внутри < 0 |
| G | расстояние до ближайшего луча разделителя зон (от SVG-центра до обода); использовать при R < 0 |
| B | расстояние до ближайшей осевой связи (от обода до обода; прямые и дуги) |
| A | знаковое расстояние до всего игрового слоя: диски до внешнего края обода, штрихи связей (ширина ядра), ромбы стартов |

Пример для материала: обод — `|R| < w_ring/2`, связь — `B < w_line/2 && R > 0`, разделитель — `G < w/2 && R < 0`.
Сглаживание — через `fwidth`. Ширины записаны в `manifest.params.sdf` и `vector-layer.ring / line_width`.

**SpaceID** (Gray16, без фильтрации). 0 — пусто; k — k-я клетка топологии в порядке id (M01 = 1 …).
Диск радиусом до внешнего края нарисованного обода.

**GameMask** (Gray8). 255 внутри игрового слоя, расширенного на 6 px; мягкий край 1 px.

**Центры.** Для слоёв берутся **нарисованные** центры ободов: подгонка кольца по картинке, сдвиг до 2,5 px
от SVG (Sarpedon S33 — 2,48 px, Marmoreal M31 — 2,03 px), контраст обода растёт с 0,77 до 0,88. Центры топологии остаются авторитетными для игры.
Разделители идут от SVG-центра: с ним нарисованные линии совпадают лучше, медиана смещения 0,2–0,26 px.

## vector-layer.json

- `ring` — радиус осевой линии и ширина обода (FWHM);
- `spaces[]` — топологический и нарисованный центр каждой клетки;
- `dividers` — угол, вершина и конец каждого луча, плюс сверка с нарисованной линией;
- `connections` — по ребру топологии:
  - `kind` (`straight` / `arc`), `polyline_px` (дуги — шаг 3 px);
  - у дуг: центр, радиус, начальный угол, размах, стрела;
  - покрытие штрихом, метод;
- `start_diamonds` — центр, полудиагональ и угол ромба на каждом старте;
- `line_width` — ширина ядра линии и профиль яркости.

Трассировка связей:
1. Геодезический путь по маске тёмного штриха (max(R,G,B)) в коридоре между ободами.
2. Субпиксельная осевая: центроид поперечного профиля. Если у короткого зазора между ободами
   на пути меньше 4 отсчётов (`S09-S10`, зазор ≈16 px), профиль берётся каждые 0,5 px вдоль хорды
   по всему зазору, окно центрируется на штрихе (mean shift): подгонка по сырым пикселям пути
   лежала на ≈1,3 px в стороне от штриха (`centreline_source: chord-profile`).
3. Модель по данным: прямая или дуга. Дуга выбирается, если окружность ложится ≤ 0,5 px, в 2 раза лучше
   прямой и стрела ≥ 0,75 px.
4. Если штрих прерван (покрытие < 0,9), берётся лучший прямой отрезок от обода до обода.
   Это `M22-M29` и `M22-M30` под стеклянным мостом.
5. Проверка: `stroke_offset_px` — медиана смещения нарисованного штриха от итоговой линии на 20–80 %
   её длины (для прерванных штрихов не считается). Больше 0,5 px — сборка падает; сейчас не более 0,21 px.

Дуги:
- Marmoreal: M06-M12, M20-M27, M21-M25, M23-M26, а также пологие M16-M19 (стрела 1,1 px) и M30-M31 (2,4 px);
- Sarpedon: S11-S21, S20-S21, S21-S31, S30-S31, а также пологие S06-S15 и S36-S37 (≈0,9–1 px).

Пологие дуги M16-M19, M30-M31, S06-S15 и S36-S37 — замер по картинке, он перекрывает форму из ресерча
(там они «straight» по большинству голосов, у M30-M31 и S06-S15 — решением `adjudications`): для M30-M31
окружность ложится с rms 0,10 px против 0,55 px у прямой. На игру это не влияет, только на отрисовку.

## Моки K1 (`k1_mock.py`)

**Камера** — формула `AS08FlowGameMode::SetupCameraForBoard` для доски 891,33 × 577,33 uu:
- HFOV 35°, 16:9, pitch −55°, yaw −90°;
- D = **1872,2 uu**, камера в (0; 1073,8; 1533,6).

Ориентация как в S08: картинка прямо, север дальний. Старты 1 и 2 на этих картах оказываются
**слева и справа**, а не снизу и сверху, как на решётках S08.

**Сцена:**
- поднос-заглушка из тёмного камня: кромка 60 uu, борт 150 uu;
- в кадр K1 попадает только верх ближнего борта: кадр кончается на 1080 px, низ борта на ≈1170 px;
- ночной фон.

**Варианты:**
- **a** — BC без освещения;
- **b** — ночной грейд:
  - `lit = albedo · 2^−0,7 · холодный тинт`;
  - вне маски `lit` обесцвечен ×0,7;
  - внутри маски `lit + 0,35 · albedo` (unlit-доля);
  - итог: игровой слой ≈ +0,65 EV к декору;
- **c** — b плюс:
  - кольца команд Ø57 uu: золото на старте 1, серебристо-синее на старте 2;
  - серые фигуры 50 uu на базе Ø40.

**Замер экранных px на px исходника.** ID-карта рендерится той же камерой, затем берутся габариты каждого
диска. Горизонталь и вертикаль указаны парой h / v:

| Где | h / v |
|---|---|
| Дальний ряд | ≈1,02 / 0,77 |
| Центр | 1,08 / 0,89 |
| Ближний ряд | 1,17 / 1,02 |

Прямой замер по краям карты на кадре a совпадает: 0,998 по дальнему краю, 1,188 по ближнему.

Экранные углы карты и подноса записаны в `manifest.k1.measurement` — по ним можно совмещать концепт-арт.

## Ограничения

- Sarpedon, закраска логотипа: низ столбов частокола обрезан ровной горизонталью по верху дыры
  (≈30 px исходника), трава заполнена немного повторяющимися патчами. В K1 это ≈1 экранный px на px.
  При художественной приёмке нужна ручная доводка или ИИ-инпейнт; в Marmoreal швов не видно.
- Ореол маски: расширение на 6 px видно в b/c как светлая кайма вокруг кругов и связей.
  Это «подъём читаемости» из брифа; его ширину решает художественная приёмка.
- Моки — геометрическая подложка под концепты, а не рендер UE: нет теней от подноса, TAA и тонмаппинга UE.
