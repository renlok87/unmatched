# tools/art/concept — инструменты этапа 1 (концепт-лист) скилла 3d-model-pipeline

Два CLI для этапа 1 скилла `.agents/skills/3d-model-pipeline`. Их интерфейс зафиксирован решением Р-9 переписывания
скилла. Норма производства — `docs/art-pipeline/BLENDER-MODEL-HANDBOOK.md`: оси описаны в §2.1, рецепт
hero-quality-v1 — в §3.1.

| Файл | Что делает |
|---|---|
| `draft_orthos.py` | 1b: черновые ортопроекции модели Tripo (GLB) через Blender headless |
| `_blender_orthos.py` | Blender-часть `draft_orthos.py`. Отдельно не вызывать |
| `check_concept_views.py` | автопроверки набора видов и лист-сетка `sheet-<key>.png` |
| `tests/` | pytest: синтетические картинки и синтетический GLB с метками сторон |

Зависимости: Python 3.10+, numpy, Pillow, scipy (их же требует HANDBOOK §0.2) и Blender 5.2
(`C:/Program Files/Blender Foundation/Blender 5.2/blender.exe`).

Оба CLI сами переключают stdout/stderr на UTF-8 (пайп cp1251 у Codex/PowerShell и Git Bash агента не роняет печать
«→»; тесты `test_cli_cp1251_*`). `export PYTHONIOENCODING=utf-8` — только страховка для чтения вывода в консоли.
Непойманный сбой `check_concept_views.py` даёт код 2, а не 1 (1 зарезервирован за «есть FAIL»).

## draft_orthos.py

```bash
python tools/art/concept/draft_orthos.py --glb <draft.glb> --out <dir> [--views front,left,back,right] \
    [--aspect 3:4] [--long-side 1536] [--bg 0.18] [--blender "C:/Program Files/Blender Foundation/Blender 5.2/blender.exe"]
```

Выход:
- `<dir>/ortho_<view>.png`: RGB без альфы, ровный фон `round(bg × 255)` (0.18 → 46/255);
- `<dir>/ortho-framing.json` (schema `unmatched.draft-orthos/1`): sha256 GLB и выходов, bounds, `ortho_scale_m`,
  положения камер, `placement_pct` и `prompt_hint`;
- `<dir>/draft-orthos-blender.log`: лог Blender.

Код выхода: 0 — все виды записаны, 1 — ошибка (аргументы, нет GLB или Blender, Blender упал или не уложился в
30 мин).

Как строится кадр (решение скилла):
- **Один кадр на все виды.** Ортокамера с общим масштабом. Центр подставки (центр bbox нижних 3 % роста) стоит на
  x = 50 % кадра. Низ подставки — на y = 94 % высоты. Рост занимает не больше 90 % высоты, ширина вокруг центра
  подставки — не больше 92 % ширины. Если упирается ширина (крылья Harpy), фигура в кадре меньше, но масштаб и
  линия земли у всех видов общие.
- **Верх подставки (`base_top_y_est`).** Слоями по 0,5 % роста вверх от низа, пока непустой слой шире 85 % подставки;
  пустые слои (низкополигональная подставка: вершины только на ободах) пропускаются, пустой разрыв > 15 % роста
  завершает поиск. Merlin h31: retopo-GLB и плотный исходник дают одно и то же 86,8 %.
- **Стороны.** По HANDBOOK §2.1: лицо смотрит в −Y, левый бок фигуры = +X.
  - `front`: камера в −Y;
  - `left`: камера в +X, виден левый бок фигуры, лицо смотрит в кадре влево;
  - `back`: камера в +Y;
  - `right`: камера в −X.

  Импорт glTF от Tripo даёт именно эту ориентацию. Проверено на Merlin и Harpy, а синтетический тест проверяет
  метками.
- **Свет нейтральный и привязан к камере.** Одинаков во всех видах: мир серый 0,5 × 1,0, ключевое солнце 3,0
  (az −35°, el 35°), заполняющее 1,2 (az 50°, el 10°). EEVEE, view transform Standard, фон прозрачный. Ровный фон
  `--bg` подкладывает внешний скрипт.
- **Места в % кадра.** `placement_pct` (верх фигуры, верх и низ подставки, центр подставки) и `prompt_hint` — это
  числа для промптов этапа 1c: «одинаковые места подставки в % кадра».

`--views` — подмножество `front,left,back,right`. Для слота side Tripo берётся `left` или `right` по правилу
концепт-листа скилла. `--aspect 3:4` — портрет. Для крылатых удобнее `4:3`, его использовал прогон Harpy ниже.

## check_concept_views.py

```bash
python tools/art/concept/check_concept_views.py --set <dir> --key <content-key> --views front,side,back \
    [--role hero|creature|prop] [--palette <dir>/palette.json] [--sheet] [--out <dir>] [--min-top-pct 4]
```

Читает `<set>/<key>-<view>.png`. Сырые файлы не меняет: тест сверяет их sha256 до и после прогона. Пишет в `--out`
(по умолчанию `--set`):
- `checks-report.json`;
- `sheet-<key>.png`, только с `--sheet`.

`--out` — дополнение к Р-9. Он нужен, чтобы проверять принятые наборы, не записывая ничего в их каталог, и для
проверок кандидатов и перепроверки запускающего агента (концепт-лист скилла, §3 и §5.5: кандидат — в
`checks/<view>-g<N>/` пакета, перепроверка — вне пакета). Повторный прогон на тех же файлах даёт тот же отчёт, кроме
`generated_at` и пути `sheet` (тест `test_recheck_with_out_matches_without_generated_at`).

`--min-top-pct N` — рамка ядра шага 1a («верхняя точка не выше y 4 %», живой тест 2026-10-09 дал 3,3 % без
сигнала). Верх маски выше y N % — WARN `view.frame_top`; это не FAIL и не повод для ретрая, отклонение видят
приёмщик и запускающий агент. Без флага проверки нет: принятые наборы имеют верх 1,9–4,0 %, а у 1c рамку задают
ортопроекции. Значение пишется в отчёт (`frame.min_top_pct`).

Код выхода:

| Код | Значение |
|---|---|
| 0 | 0 FAIL (WARN допустимы) |
| 1 | есть хотя бы один FAIL |
| 2 | ошибка входа или внутренний сбой инструмента |

Ошибкой входа считается:
- нет каталога или файла вида;
- файл не читается;
- `--key` не в kebab-case;
- `--views` пуст или повторяется;
- неверный `--role`;
- палитра не найдена или с неверным hex.

`--role` записывается в отчёт и на лист. Допуски общие для всех ролей: калибровка показала, что Harpy укладывается
в те же пороги.

### Как меряется

- **Фон.** Модель фона — квадратичная поверхность по каналам (ловит виньетку). Сначала она подгоняется по рамке,
  затем по всему фону, связанному с краем. Остаток на фоне у канона — σ ≈ 1,3–2,8 уровня.
- **Маска фигуры.** Пиксели, которые отличаются от модели фона больше `segment_tone` = 14 и не связаны с краем.
  Компоненты меньше 0,02 % кадра считаются шумом.
- **Размеры подставки** берутся из нижних 6 % роста маски:
  - низ подставки — низ маски;
  - центр — медиана центров строк шириной ≥ 95 % максимальной;
  - верх подставки — оценка: подъём от самой широкой строки, пока ширина ≥ 85 %.
- **Рост** = низ подставки − верх маски, в % высоты кадра.
- **Проценты.** Все позиции меряются в % кадра. Поэтому виды, которые различаются на 1 px, сравниваются корректно.

### Проверки (`checks[]`: id, scope, result PASS|WARN|FAIL, value, limit, message)

| id | scope | FAIL | WARN |
|---|---|---|---|
| `set.size` | набор | размеры различаются > 0,5 % по стороне | — |
| `set.size_exact` | набор | — | размеры различаются хоть на 1 px |
| `view.alpha` | вид | — | есть прозрачность |
| `view.border_uniform` | вид | < 99 % рамки (2 % короткой стороны) в ±20 от медианы | < 99 % в ±12 (число Р-9) |
| `view.bg_neutral` | вид | \|R−G\| или \|G−B\| медианы рамки > 6 | — |
| `view.bg_dark` | вид | — | яркость фона > 96 (не тёмно-серый; например, старый `#808080`) |
| `set.bg_same` | набор | медианы фона видов различаются > 12 | — |
| `view.mask` | вид | маска вне 2–90 % кадра (фигура не найдена или фон не отделился) | — |
| `view.top_margin` | вид | верх маски < 1 % высоты | — |
| `view.frame_top` | вид, только с `--min-top-pct N` | — | верх маски < N % высоты (1a: N = 4) |
| `view.bottom_margin` | вид | низ подставки > 99 % высоты | — |
| `view.side_margin` | вид | маска ближе 1 % ширины к боковому краю | — |
| `view.single_component` | вид | — | есть прочая связная компонента ≥ 0,5 % кадра |
| `set.base_bottom` | набор | разброс низа подставки > 3,5 % высоты | > 1,5 % (Р-9) |
| `set.base_center` | набор | разброс центра подставки > 6,5 % ширины | > 2,0 % (Р-9) |
| `set.height` | набор | разброс роста > 5,0 % от наибольшего | > 3,0 % (Р-9) |

Тонкие элементы (тетива, древко, стрелы) не проверяются. По Р-5.6 это не FAIL: утолщение — работа Blender.

### Отчёт `unmatched.concept-checks/1`

Поля верхнего уровня:
- `schema`, `tool`, `generated_at`, `set`, `key`, `role`, `views`;
- `inputs[]` — view, path, sha256, format, mode, size;
- `raw_files_modified: false`;
- `tolerances`, `tolerances_note`, `frame{min_top_pct}` (null без флага);
- `measurements{view}` — size, mode, alpha, border, background_model, mask;
- `checks[]`, `summary{PASS,WARN,FAIL}`, `verdict` PASS|FAIL;
- `palette{path, swatches[]}`, `sheet`.

`mask` содержит:
- `area_pct`, `filled_area_pct`, `components_kept`, `main_component_pct`, `other_components_pct`;
- `bbox_px`;
- `top_pct`, `bottom_pct`, `left_pct`, `right_pct`, `height_pct`;
- `base_center_x_pct`, `base_width_pct`, `base_top_pct_est`.

У каждого свотча палитры есть справочное поле `figure_share_within_40_pct` — доля пикселей фигуры всех видов в
RGB-расстоянии ≤ 40 от свотча. Это не проверка: палитру оценивает приёмщик по измерению P.

### Лист `sheet-<key>.png`

- **Виды.** Стоят в ряд, каждый масштабирован к высоте 900 px. Файлы видов не меняются: сетка есть только на листе.
- **Линейка слева** — в % высоты кадра: деления через 5 %, подписи через 10 %. Слабая пунктирная сетка через 10 %
  проходит по всем видам.
- **Направляющие #00C8FF:**
  - сплошные «ground» (медиана низа подставки) и «top» (медиана верха фигуры) через все виды;
  - пунктирная вертикаль — медиана центра подставки в каждом виде.
- **Собственные метки вида** (белые засечки) — его верх, низ и центр подставки. Расхождение с направляющей видно
  глазом.
- **Под видами** — их числа: top, ground, height, base x, ширина и оценка верха подставки, поле.
- **Свотчи палитры** — с hex.
- **В шапке** — вердикт и число FAIL/WARN.

### palette.json

Принимаются формы:
- образец прогона Robin Hood: `{"main":[{"name","hex"}], "accent":{"name","hex"}}`;
- `{"colors":[...]}` или `{"palette":[...]}`;
- список `[{"name","hex"} | "#RRGGBB"]`;
- словарь `{"зона": "#RRGGBB"}`.

Без `--palette` берётся `<set>/palette.json`, если он есть.

## Тесты

```bash
python -m pytest tools/art/concept/tests -q
```

31 тест, около 25 с:
- **`test_check_concept_views.py`.** Чистый набор даёт PASS и лист с #00C8FF. Каждая проверка ловит свой дефект:
  низ, центр, рост, поля, фон, размер, рамка, пустой кадр. Умеренный дрейф даёт WARN, а не FAIL. Рамка 1a
  (`--min-top-pct`) даёт WARN только с флагом; перепроверка через `--out` совпадает с отчётом пакета без
  `generated_at` и `sheet`. Ещё проверяются ошибки входа → 2, формы palette.json и код выхода CLI.
- **`test_draft_orthos.py`.** Разрешение по аспекту, ошибки входа → 1. Интеграционный прогон на синтетическом GLB
  проверяет: красная метка на левом боку (+X) справа на front и слева на back; лицо (−Y) смотрит влево на left и
  вправо на right; фон 46/255. Тест пропускается без Blender 5.2.
