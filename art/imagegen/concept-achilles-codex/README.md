# Ахиллес — концепт 1a
Дата: 2026-10-13. Статус: **предложено**.

Создан один фронтальный дизайн коллекционной окрашенной миниатюры для image-to-3D. Использован встроенный image_gen.imagegen: единственный графический вход — эталон качества Медузы, palette.json прочитан как данные. Хеши обоих входов совпали с заданием и остались прежними.

Выбрана **design-front g2**: design/achilles-front.png — её побайтовая копия. Подставка показана с ребра без видимой верхней плоскости, левая рука стала видна, щит отведён от корпуса. Обе исходные генерации сохранены без ретуши, обрезки, ресайза, перекраски и повторного кодирования. Оригиналы инструмента оставлены на месте, их абсолютные пути записаны в generation-records.json.

Использовано **2 из 2** генераций. У g1 не выполнены визуальные пункты строгого вида подставки и ясного отделения руки со щитом от корпуса. CORE во второй попытке сохранён дословно; добавлены только две строки CORRECTION по этим пунктам. WARN по верхнему полю не был причиной ретрая. Орнамент во второй попытке изменился как результат генератора; отдельного требования его менять не добавлялось.

Проверки обоих кандидатов сохранены в отдельных checks/design-front-gN/. Финальная проверка выбранного файла — design/checks-report.json: **код 0, PASS 12, WARN 1, FAIL 0**. Все шесть пунктов визуального CHECKLIST g2 отмечены как выполненные. Оценка приёмщика ещё не проводилась.

Ограничения CORE: верх копья y=2,624% вместо минимум 4% (допустимый WARN view.frame_top); низ подставки y=94,890% вместо 93%; центр подставки x=48,573% вместо 50%. Всё записано в verification.json. Плащ частично заполняет просветы между руками и корпусом; щит наклонён и выглядит овальным при круглой конструкции. Лимит генераций исчерпан, невыполненных пунктов CHECKLIST выбранного файла нет.

Небольшие решения: сохранены бронзовые орнаменты, наклон щита и золотая отделка гребня; side_view для фронтального дизайна равен null. Другие виды не создавались. Все пути в записях, кроме original_path, относительны корню репозитория. Файлы исполнителя записаны только в этот пакет; обязательные оригиналы image_gen находятся в штатной папке инструмента. Git, Unreal, Tripo и SYNTX не запускались.


## Этап 1c — front / left side / back

Дата: 2026-10-13. Статус: **предложено**.

Созданы три окрашенных вида поверх черновых орто. Графические входы — соответствующее орто и утверждённый design/achilles-front.png; back дополнительно использует выбранный achilles-side.png. Шесть входных хешей совпали с заданием до работы и остались неизменны. История 1a сохранена выше и в previous_runs файла verification.json; прежние генерации, дизайн, палитра и их отчёты не изменены.

Выбор:

- **front g1** — сохраняет тёмную каменную базу, окраску, сторону копья и позу. Front g2 приблизил рамку, но сделал базу почти белой и сильнее наклонил правую для зрителя поножу; он отклонён.
- **side g2 (left)** — исправлен расширенный лицевой наконечник side g1: теперь виден узкий профиль по орто. Собственная левая сторона обращена к камере, лицо — к левому краю.
- **back g2** — исправлены ошибочные лицевые львиные рельефы на внутренней поверхности щита и задних панелях поножей back g1. Копьё справа для зрителя, лица не видно.

Использовано **front 2/2, side 2/2, back 2/2** генераций в этом запуске; по 2/4 в общей истории каждого вида 1c. Дизайн-front 1a имеет отдельные 2/4. Размер результатов — 1086×1448, аспект 3:4; инструмент выбрал его сам. Размер не передавался. Все результаты побайтно скопированы в уникальные concepts/achilles-<view>-g<N>.png; оригиналы инструмента оставлены на месте. Выбранные achilles-front.png, achilles-side.png и achilles-back.png — побайтовые копии. Ретуши, ресайза, обрезки, перекраски и перекодирования нет.

Каждый кандидат проверен в собственном checks/<view>-g<N>/; все шесть запусков дали код 0. Два итоговых запуска без --out на выбранных файлах дали **код 0, 33 PASS, 0 WARN, 0 FAIL**. Финальные checks-report.json и sheet-achilles.png сохранены, лист открыт и осмотрен. Промпты и порядок ссылок записаны в prompts.md и prompts/concept-prompts.json.

Не закрыто: **точное кадрирование**. Скрипт проверяет допуски, а не совпадение чисел CORE. Верхняя точка выбранных видов y3,867% / y3,315% / y3,522% вместо y4,0%; низ базы y94,268% / y94,475% / y94,406% вместо y94,0%. Центр, ширина, приблизительный верх базы и отклонения приведены в verification.json. Пункт CHECKLIST о точном совпадении кадрирования отмечен false для всех трёх видов; они перечислены в limit_reached. Лимит текущего запуска исчерпан; лучшие кандидаты сохранены для решения приёмщика.

Небольшие решения: фоновые RGB отличаются до трёх уровней — это визуально тот же нейтральный тёмно-серый фон, set.bg_same PASS; численная разница записана. Исправления ограничены существующими видимыми поверхностями, новых требований дизайна нет. Мелкие рельефы, складки и крепления независимо интерпретированы генератором; попиксельная идентичность не заявляется. В back третьей ссылкой использован выбранный side g2. Повтор front выполнен после общего осмотра листа, потому что точные числа рамки не закрыты визуальным CHECKLIST при PASS скрипта.

Собственные записи ограничены этим пакетом. Проверены входы, сохранность прежних неизменяемых файлов и совпадение копий. Оригиналы инструмента находятся в прямо разрешённом штатном каталоге image_gen. Git-команды, Unreal, Tripo, SYNTX и загрузки не выполнялись. Внешняя приёмка не проводилась.
