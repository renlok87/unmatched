## Почему нет генерации

Разрешение на трату кредитов пришло только в тексте задачи от оркестратора, как цитата пользователя. Сам текст помечен как вывод скрипта без полномочий пользователя. Для субагента это не подтверждение, полученное прямо от пользователя. Правила браузерных действий требуют такого подтверждения перед платной кнопкой («Создать» в Studio). Все бесплатные шаги выполнены. Платную часть можно пройти по [runbook](../../art/pipeline-candidates/ASSET-TABLE-BASE-001/20260928-table-base-tripo-h31/reports/tripo-stage-plan.json) без доработки. Её выполняет сессия, где пользователь сам подтвердил трату. Та же причина остановила фонарь ([prop-lantern-report](prop-lantern-report.md)).

## Открытые вопросы для Blender-этапа

- **Глубина скалы.** По референсу ≈150 uu, а 04 §3.6 предлагает толщину 30–50 uu и обрыв края в 30–60 uu от игровой плоскости. Z-масштаб решать по кадрам игровой камеры 16:9: K1, зум 0,65× и слежение за ближним рядом на 1,2× ([§ Кадр игровой камеры 16:9](#кадр-игровой-камеры-169-измерено)).

### Кадр игровой камеры 16:9 (измерено)

**Исправление.** Первая версия `table_base_preview.py` рендерила кадры «K1» в 1200×900 (4:3). При горизонтальном FOV 35 половина вертикального FOV там 13,30°. Игровой кадр — 16:9 (04 §4.4: вертикальный FOV ≈20° при 16:9; D-07 1080p), половина вертикального FOV 10,06°, как и в [facades-report](facades-report.md). Кадр 16:9 показывает по высоте на 25 % меньше (675 строк против 900). Поэтому выводы «на 12 м режется только ближний край подноса» и «на 18,5 м поднос виден целиком» были неверны. Теперь кадры игровой камеры рендерятся в 16:9 (1200×675). Центральная полоса 675 строк кадра 4:3 совпадает с кадром 16:9: средняя разница пикселей 1,1…1,2 (шум JPEG), при сдвиге полосы на 20 строк — 7,6…9,2.

Углы — от оптической оси, полукадр ±10,06° по вертикали и ±17,5° по горизонтали. Камера на экспортной −Y, наведена на центр доски (в кадрах слежения — на центр ближнего ряда клеток); поворот актора доски в уровне не применён.

### Открытые вопросы Blender-этапа

- **Глубина Z** — решать на реальном меше по кадрам 16:9 и `near_skirt_limit` из `<имя>_preview.json`: 30–50 uu по 04 против ≈150 uu на референсе. В K1 (12 м) скалу спереди не видно вовсе.
