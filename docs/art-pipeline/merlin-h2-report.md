## 2. Игровая модель (стадия `retopo`)

**Метод — коллапс-децимация по частям, а не QuadriFlow** (измерено 2026-09-29, `work/explore`):

- QuadriFlow в Blender 5.2 отказывает на всех частях Tripo («needs to be manifold…»): причина — проверка рёбер короче
  1e-4 в единицах меша; в метрах Tripo таких рёбер много. С масштабом ×100 он работает, но при равном числе
  треугольников отклоняется от high-poly в 5–10 раз сильнее: рукава p99 6,5–8,8 мм против 0,8–0,9 мм, лицо max 7,9 мм
  против 0,8 мм (3k tris). Для раструбов рукавов, лица и резьбы посоха это теряет силуэт.
- Коллапс-децимация идёт **последовательно по частям** (крупнейшая первой) на сваренном объекте: остальные части
  защищены группой вершин (вес 0 × фактор 1000), вершины шва принадлежат обеим сторонам. Затем `beautify` на почти
  плоских рёбрах внутри части (≤ 8°). Острые кромки: гладкое затенение, резкие рёбра только у граней кристалла (> 35°) —
  рельеф несёт карта нормалей.

**Отклонение от high-poly** (мм, метры Tripo; в игре ×0,505, 1 мм Tripo ≈ 0,05 uu):

| Часть | high→low p99 / max | low→high p99 / max |
|---|---|---|
| мантия p0 | 0,85 / 7,68 | 0,96 / 2,29 |
| лицо p9 | 0,24 / 0,37 | 0,30 / 0,45 |
| кулаки p6 / p8 | 0,23 / 0,62 · 0,28 / 0,45 | 0,26 / 0,43 · 0,33 / 0,41 |
| рукава p3 / p4 | 0,78 / 1,11 · 0,77 / 1,59 | 0,88 / 1,11 · 0,85 / 1,23 |
| башмаки p5 / p11 | 0,74 / 2,67 · 0,67 / 1,61 | 0,81 / 1,17 · 0,67 / 0,82 |
| посох p2 / p10 / кристалл p7 | 0,57 / 1,28 · 0,54 / 0,94 · 0,51 / 0,83 | 0,62 / 0,91 · 0,64 / 0,86 · 0,60 / 0,81 |
| подставка p1 | 0,66 / 1,82 | 0,65 / 1,18 |

Выбросы max у мантии (7,7 мм) — в зонах несваренных контактов (крышки вместо поверхности), p99 везде < 1 мм.
Форма треугольников: медиана качества 0,48–0,71, доля q < 0,2 — 2–18 % по частям (децимация, не ретопология руками).

**Сварка швов** (только анатомические, профиль `objects.body.weld_pairs`): капюшон–лицо (петля 518), правая пройма
(p0|p4, z ≥ 0,58), правое запястье (p4|p6), подол–башмаки (p0|p5, p0|p11). **Не сварены** контакты: левый рукав и левый
кулак с мантией (у Tripo это одна общая петля: пройма + весь бок, z 0,43–0,73), правый рукав на боку мантии (петля 211),
кончик бороды на груди. Причина измерена: при сварке всех контактов в позах `arm_l_raise`/`arm_r_raise` между
поднятым рукавом и мантией тянулась «перепонка» кожи. Несваренные стороны закрыты веерными крышками (15 на теле,
4 на подставке, 2 + мост на посохе); при движении конечности видна крышка, а не перепонка.

**Посох** — отдельный меш из p2 + p10 + p7 (p7|p10 сварены). Tripo не смоделировал древко внутри правого кулака: петли
p2|p6 (z 0,613–0,648) и p10|p6 (z 0,670–0,680) соединены мостом (`bridge_loops`, 85 граней, смещение центров петель
0,9–1,2 мм); низ древка (на носке правого башмака) и контакт с подолом закрыты крышками. Посох замкнут: 0 открытых и
0 неманифолдных рёбер.

**Тело**: 0 неманифолдных рёбер от сборки; 6 неманифолдных + 13 рёбер с разным winding — **самокасания Tripo**
(затылок капюшона, подол сзади), они есть в исходнике после сварки; помечены резкими (нормали не усредняются). Одна
открытая цепочка из 3 вершин (дырка исходника на спине капюшона) оставлена открытой. Подставка замкнута.

## 3. UV и атлас (стадия `uv`)

- Прямой Smart UV Project на децимированной сетке дал 3 971 остров тела (2 184 из одного треугольника). Поэтому швы
  выбираются на **сглаженной копии** (Smooth 0,5 × 60, Smart UV 66° по частям, кристалл 30°), мелкие острова (≤ 8
  граней) сливаются с соседом той же части; развёртка — **ABF** по этим швам; свёрнутые треугольники и острова,
  перекрывающие сами себя (растр 8192), режутся и разворачиваются заново (4 прохода тела, 1 посоха).
- Острова: тело 909, посох 223, подставка 31; части и крышки никогда не делят остров.
- Плотность: единая мировая (`average_islands_scale`) × приоритет части; одна упаковка всех трёх объектов (вогнутые
  формы, поворот), отступ 5 px на сторону.

Замер на растре 4096 (стадия `maps`): **0** перекрытых текселей; **минимальный зазор между островами 9,86 px** (≥ 8);
заполнение атласа 54,4 %. Плотность текселей в игре (px 4K на uu): мантия 46,0, рукава 42,0/46,1, башмаки 41,8–41,9,
**лицо 93,4 (×2,03)**, **кулаки 77,0 / 69,2 (×1,67 / ×1,50)**, посох 65,9–68,4 и кристалл 65,8 (×1,43–1,49), подставка
23,1 (×0,50). Отклонение от приоритетов — искажение площадей внутри островов ABF (±10 %).

## 4. Запекание (стадии `bake` и `maps`)

- Cycles на **CPU** (seed 0; профиль `bake.device`), selected-to-active **по частям**. GPU OptiX (RTX 4090) быстрее
  (10–15 мин против ~20 мин на пять карт 4K), но две полные GPU-сборки дали разные байты текстур (раздел 8); по
  float разница GPU/CPU ≤ 4,9·10⁻⁴ (AO max 0,012 в 5 текселях). Запекание: временный объект с гранями части k
  (corner-нормали всего объекта сохранены как custom normals — касательный базис
  тот же, что у экспорта) запекается с
  high-poly части k и её соседей по сварному шву того же объекта. Все high-poly остаются окклюдерами для AO; low-poly
  невидимы для лучей.
- Cage: вынос = max(1,5 мм; 1,5 × p99,9 high→low), луч = max(3 × вынос; вынос + 1,2 × max low→high) — 1,5–2,7 мм /
  4,5–8,2 мм (Tripo).
- Карты: Normal — касательное пространство OpenGL из **геометрии** high-poly (normal map Tripo не используется: она в
  4 раза мельче BC, а 2M-геометрия уже несёт рельеф); AO — Cycles, 256 сэмплов, дистанция 0,08 × высота (как W4-B
  `atlas.ao_bake`); BaseColor, roughness (`RM.G`), metallic (`RM.B`) — эмиссией из PBR Tripo, 16 сэмплов (AA).
- **Промахи**: на поверхности (не крышках) 0,076 % текселей (6 866); крышки и мост (49 200 текселей) почти целиком без
  попаданий — внутри кулака и на подставке у high-poly нет поверхности; все такие тексели и все зазоры заполнены
  ближайшим запечённым текселем (EDT).
- AO не константа (p1–p99 = 0,98); metallic ≈ 0,02 везде (неметалл), roughness мантии 0,96, кожи 0,54–0,63, кристалла 0,57.

Текстуры (`textures/`, PNG, 8 бит):

| Файл (4K мастер / 2K рантайм) | Формат | Для UE |
|---|---|---|
| `T_Merlin_H2_BC_{4K,2K}` | RGB sRGB | TC_Default, sRGB |
| `T_Merlin_H2_N_{4K,2K}` | RGB, **DirectX** (зелёный OpenGL-запекания инвертирован) | TC_Normalmap, `flip_green = false` |
| `T_Merlin_H2_ORM_{4K,2K}` | R = AO, G = roughness, B = metallic, линейно | TC_Masks |
| `T_Merlin_H2_TeamMask_{4K,2K}` | L, линейно: **одежда** | TC_Grayscale; совместимо с W4-B `M_UM_Figure` (lerp по `TeamMask.R`) |
| `T_Merlin_H2_TeamMaskRGBA_{4K,2K}` | R = одежда, G = боковая лента подставки, B = золотая кайма на одежде, A = 255 | предложение волне 4 (TC_Masks) |

Копии нормалей в OpenGL (`N_OpenGL`) больше нет: превью Blender переворачивает зелёный канал `N` в шейдере (`1 − G`).
2K — точное усреднение 2×2 (BC в линейном свете, нормали как векторы с перенормировкой). Маска одежды: части
«ткань» (мантия с капюшоном, рукава) × синий оттенок 195–265°, s ≥ 0,25, v ≤ 0,75, мягкий край; кайма (B) — оттенок
20–60°. Покрытие: мантия 0,82 (кайма 0,12), рукава 0,87–0,89; кожа, лицо, посох, кристалл и башмаки — 0 (проверка).

## 5. Риг и экспорт (стадии `rig` и `probe`)

- **Скелет `UM_HUMANOID_17_v2`**, объект арматуры `SKEL_UM_Humanoid`, `weapon.R` под `hand.R`. В задаче назван v1, но
  контракт v2 (W4-D) закрыл v1 для новых файлов (`validate_clip` даёт FAIL вне `grandfathered_files`), а для Merlin v2
  отличается только именем `weapon.R` — сборка по v2.
- Масштаб: фигура ×0,50485 вокруг центра верха подставки Tripo; **верх капюшона 44,99 uu**, кристалл 49,42 uu;
  подставка нормирована по своим low-poly габаритам ровно в **24 × 24 × 5 uu**, pivot в центре низа (Tripo-подставка
  Ø0,478 × 0,0975 м — почти равномерно: ×0,502/0,508/0,514). Радиус фигуры 13,1 uu (капсула Ø28 — предложение — вмещает).
- Кости поставлены по геометрии H2 (профиль, `placement_note`): запястья — центры общих петель рукав|кулак, лодыжки —
  петли подол|башмак, носки — передние нижние точки башмаков, хват — середина петель посоха у кулака, хвост `weapon.R` —
  верхняя вершина кристалла (Δz −0,006 uu). Плечи, локти, бёдра и колени скрыты тканью — оценка.
- **Веса**: кулаки и башмаки жёстко на свои кости; лицо/борода — bone heat `spine`+`head` с рампой; мантия — heat
  hips/spine/head/ноги/плечи с рампами и потолками (капюшон следует за `head` выше z 0,70–0,76); рукава — spine+руки.
  Вершины сварных швов (193) получают среднее правил своих частей, 751 вершина в радиусе 6 мм (игровой кадр) плавно
  к нему стянуты (seam sync). ≤ 4 влияний, 0 невзвешенных. Посох 100 % `weapon.R`, подставка не скинится.
- **`rig_deform_probe.py`: 7/7 plausible** и на `h2-rig.blend`, и на FBX, прочитанном обратно (`head_turn` z 0,757 при
  пороге 0,70; `arm_r_raise` x −0,649). Листы: `preview/deform/merlin-h2-{blend,fbx}-sheet.png`. После отказа от сварки
  контактов левый рукав поднимается без перепонки; у правой проймы (сварена) ткань тянется от плеча — ожидаемо.

`closeups_sheet`, лист проб FBX): рельеф освещён как раньше, отличие от прежних кадров ≤ 7 единиц в ≤ 2 % пикселей.

- `sbs_front.png` / `sbs_right.png` / `sbs_back.png` — концепт H2 | рендер (фронт ещё | эталон Medusa), кадрирование
  концепта (кристалл и низ подставки на тех же % высоты).
- `closeups_sheet.png` — лицо, правый кулак с посохом, левый кулак, кристалл, середина посоха, ноги/подставка, затылок.
- `sbs_k2_{1p6,5x}_{front,3q}.png` — игровая камера K2 (FOV 35 по горизонтали, −55°, D 1207 / 386 uu, фокус +28 uu),

**Что получилось (сам смотрел кадры):** силуэт, поза, капюшон, борода с перехватом, столы с кельтской вязью и
звёздами, кайма подола и манжет, пояс с пряжкой, резной посох и огранённый синий кристалл читаются как на концепте;
лицо (суровые брови, морщины) и кисти (суставы, ногти) — на уровне концепта в крупном плане. На K2 5× H2 заметно
чище прежнего кандидата: кайма контрастна, кристалл ярко-синий, звёзды и складки видны; на 1,6× читаются кристалл, борода,
вертикали каймы.

**Где недотягивает до концепта / эталона (честно):**

1. **Лицо на игровом ракурсе.** Под капюшоном при −55° лицо почти не видно (как и у прежнего; K2 1,6× — борода и
   брови пятном). Это геометрия капюшона концепта, не запекание.
2. **Посох** — резьба есть, но нет золотой спиральной инкрустации концепта (у Tripo дерево без золота); резной верх
   темнее и «грязнее», чем на концепте.
3. **Башмаки** темнее и проще концептных (шнуровка/строчка не читаются), это BC Tripo 1024².
4. **Подставка** — гладкий тёмный цилиндр с фаской; у концепта грубый камень и шире относительно фигуры (у нас Ø24 uu по
   карточке при высоте 45 uu).
5. **Звёзды на спине** — мельче и больше числом, чем на концепте; на затылке капюшона две звезды рядом (текстура Tripo).
6. **Кристалл** непрозрачный (запечён как BC + roughness 0,57), без глубины и внутреннего свечения концепта — это задача
   мастер-материала (эмиссия/френель), не атласа.
7. **Мелкие артефакты**: на тыльной стороне левой кисти сине-серые полосы между сухожилиями — они есть в BC Tripo
   (`tripo_part_8`, 1024²), запекание их перенесло; у края манжеты над левой кистью — зубчатый шов текселей (контакт
   не сварен, рядом крышка). Радужные «веера» в атласе — это крышки (в покое не видны). Складки в местах самокасания
   Tripo (затылок, подол сзади) затенены резкими рёбрами. Светлая точка на боку мантии в `sbs_right` при увеличении
   оказалась звездой вышивки, не дефектом.
8. До эталона Medusa по микродеталям ткани (тиснение, переливы) не дотягивает: ткань H2 даёт мелкое плетение и складки,
   но без живописной вариации тона эталона.

## 7. Бюджеты — предложение, с обоснованием кадром K2

Замер кадра K2 (1920 px, FOV 35°): на фокусе 7,89 px/uu (5×) и 2,52 px/uu (1,6×).

- **Треугольники: герой 30–45k (предложено), Merlin 34,0k + подставка 2,2k.** p99 отклонения ретопологии < 0,96 мм Tripo
  = 0,34 px на K2 5× и 0,11 px на 1,6× — силуэт суб-пиксельный на максимальном полезном зуме. На K1/K2 1,6× (фигура
  ~94 px) плотность избыточна: для них предложен LOD1 ×0,5 (04 §1), не делался. Прежняя карточка 17 §4.7.4 (8–15k для
  помощника) остаётся ориентиром GD-058; H2 выходит за него сознательно (по решению об «эталоне High»).
- **Атлас 4K мастер + 2K рантайм, ≤ 2 слота (1 у SK + 1 у SM, тот же материал).** На K2 5× 2K даёт 2,9 текселя на
  пиксель экрана на мантии, 5,9 на лице, 4,2 на посохе (1K дал бы 1,5 / 3,0 / 2,1 — тоже ≥ 1). 2K — запас для
  приближения/лобби; 4K — только мастер для пересборки. VRAM 2K-набора BC+N+ORM(+маска) ≈ 5 × 4 МБ (BC7/BC5 с мипами) —
  расчёт, не замер.
- 17-art-production-spec: K-2 «максимальное полезное приближение» обосновывает бюджет героя; «лицо и оружие» должны
  читаться (QA-010) — оружие (посох с кристаллом) читается, лицо под капюшоном — нет (п. 6.1).

## 8. Детерминизм

Всё лежит в [`reports/determinism.json`](../../art/pipeline-candidates/ASSET-MERLIN-001/20260929-h2-bake/reports/determinism.json)
(коммитится; в машинном отчёте — сводка и sha256). Три секции:

**8.1. `full_cpu_rebuild_before_fix` — две полные сборки с нуля (до исправлений, запись).** Цепочка `source` → `sheets`
дважды собрана из исходных GLB на CPU в одной папке, сравнены sha256 всех 72 файлов тогдашних `export/`, `textures/`,
`reports/`, `preview/`. Сравнение делалось разовым скриптом, который не сохранился, поэтому секция — статическая запись
с пометкой `provenance`: повторить её можно только новой полной сборкой (~26 мин CPU) во вторую папку и `determinism.py`.

- **Побайтно одинаковы (36 файлов):** оба FBX; BC, ORM, TeamMask и TeamMaskRGBA в 4K и 2K; отчёты `source`, `retopo`,
  `uv`, `bake`, `build`, `validate-skeletal-mesh`, `preview`; JSON и листы проб деформации; кадры и листы K2.
  Float-запекания AO, BaseColor, roughness, metallic — равны.
- **Не побайтно (объяснение):**
  - **Normal** (`N`): в float отличаются 102 из 9 073 926 текселей не больше чем на 4,9·10⁻⁴ (младший разряд float16);
    в 8 бит — 10 пикселей 4K и 2 пикселя 2K на 1 единицу. Проход нормалей Cycles на CPU не бит-стабилен от запуска к
    запуску (остальные четыре — стабильны); вероятный источник — многопоточный расчёт касательных MikkTSpace low-poly.
    Не исправлено; на вид не влияет.
  - `maps-report.json` и `sheets-report.json` содержат sha256 этих карт и листов.
  - Кадры EEVEE (орто, крупные планы и листы из них): ±1–2 единицы в ≤ 70 пикселях кадра — так и при одинаковых входах.
- **GPU:** две полные сборки на OptiX совпали по мешам, UV, FBX и нетекстурным отчётам, но разошлись в 53 из 72 файлов
  (все текстуры и производные) — поэтому профиль закрепляет CPU.
- Что в этой записи устарело (`superseded_by_the_fix`): FBX тогда совпадали, но оба несли путь хоста; PNG проб
  различались метаданными — теперь метаданных нет; `N_OpenGL` больше не пишется.

**8.2. `fix_vs_pre_fix` — что изменили исправления** (`determinism.py`: прежние выходы, восстановленные из копии и
сверенные по sha256, против нового прогона): 72 файла, 24 побайтно равны, 46 различаются, 2 только в прежнем
(`N_OpenGL`).

- FBX: дерево узлов то же, отличается **1 узел** — `Original|ApplicationNativeFile` (был путь хоста, стал пустым).
- Все 10 текстур — побайтно те же; отчёты `source`, `retopo`, `uv`, `bake` — те же.
- PNG проб FBX — пиксели равны (сняты только метаданные). PNG проб `.blend` — 1 единица в ≤ 19 пикселях: `h2-rig.blend`
  теперь пишется из фабричной сессии (причину глубже не разбирал).
- Кадры H2: ≤ 7 единиц в ≤ 2 % пикселей — переворот зелёного в шейдере вместо файла `N_OpenGL` плюс шум EEVEE;
  кадры прежнего кандидата и силуэт — побайтно те же.
- Отчёты: `build` — 2 новые проверки и sha/размер FBX; `maps` — нет `N_OpenGL`; `validate-skeletal-mesh` — sha/размер FBX.

**8.3. `other_directory` — независимость от папки прогона** (`determinism.py`: исправленный прогон против стадий `maps`,
`rig`, `probe`, `preview`, `sheets`, запущенных ещё раз с `run_dir = work/rerun-b` из тех же `work/h2-uv.blend`,
`work/uv`, `work/bake`): 70 файлов, **49 побайтно равны**, 21 различается.

- Побайтно равны: **оба FBX**, все 10 текстур, все PNG и листы проб деформации, кадры и листы K2, силуэт.
- Различаются только: кадры EEVEE орто/крупных планов и листы из них — ±1–2 единицы в ≤ 62 пикселях (шум EEVEE, как в
  8.1); отчёты — путь профиля (`/profile`) и sha256 этих кадров; JSON проб совпадают после замены папки прогона.

## 9. Как повторить

```bash
python tools/tripo-pipeline/blender/h2_bake_merlin/run.py \
    --profile art/pipeline-candidates/ASSET-MERLIN-001/build-profiles/merlin-segmented-skeletal-h2.json
# стадии: source retopo uv bake maps rig probe preview sheets (все headless; ~30 мин, из них запекание на CPU ~20 мин)

# determinism по умолчанию: <run>/reports/determinism.json; секцию сравнения двух папок пересобирает:
python tools/tripo-pipeline/blender/h2_bake_merlin/determinism.py <run_a> <run_b> <run_a>/reports/determinism.json --section <имя>
```

Сырые GLB (> 50 МБ) не в git: восстанавливаются по `task_url` source-spec и проверяются sha256 стадией `source`.
`work/` (`.blend`-чекпоинты, float-запекания `.npy` 134 МБ × 5) и `logs/` (в т. ч. `timings.json`, `bake-timings.json`)
не коммитятся (`ASSET-MERLIN-001/.gitignore`) и пересоздаются.

**Что коммитить вместе** (машинный отчёт, `commit_dependencies`):

- в том же коммите: `source-specs/tripo-de0654b5-h2.json`, `20260929-h2-tripo/reports/tripo-run.json`,
  `ASSET-MERLIN-001/.gitignore`, концепты `art/imagegen/hero-quality-v1/merlin/{merlin-front,merlin-side,merlin-back}.png` +
  `prompts.md` и эталон `art/imagegen/hero-quality-v1/reference/medusa-quality-reference.png` — на них ссылаются профиль,
  стадия `source` и листы `sbs_*`;
- **порядок:** вместе с W4-D волны 4 или после неё. `validate-skeletal-mesh.json` (PASS на `UM_HUMANOID_17_v2`) и стадия
  `probe` опираются на незакоммиченные `tools/tripo-pipeline/anim/validate_clip.py` (M), `tools/tripo-pipeline/anim/rig_rules.py`
  (новый) и `docs/art-pipeline/rig/rig-contract.json` + `RIG-CONTRACT.md` (v2); в HEAD `validate_clip` знает только v1 и
