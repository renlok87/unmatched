# Путь B: модель с нуля в Blender по чертежам из Codex (эксперимент)

Срез 2026-10-02. Статус: **предложено** (эксперимент пользователя). Все пороги ниже — предложение для первого
прогона; исполнитель их не ослабляет, а записывает измеренное.

**Суть эксперимента.** 3D-модель строит сам агент в Blender (скриптами `bpy`, детерминированно, headless) — **без
Tripo и любых генераторов 3D**. Генератор изображений Codex (`image_gen`) делает только 2D-пакет: размерную спецификацию,
согласованные ортопроекции на общей размерной сетке, плоские albedo-виды, маски силуэтов и палитру зон. Всё, что
дальше (UV, текстуры, риг, клипы, экспорт, импорт в UE), идёт по контракту
[BLENDER-MODEL-HANDBOOK.md](BLENDER-MODEL-HANDBOOK.md) (§2 — числа, §4.5–4.6 — анимации и UE, §7 — edge-кейсы).

Связь с нормативами: это путь решения D-06 «сделать заново» из
[04-blender-production.md](../game-design/04-blender-production.md) (карточки §3: размеры, силуэтные признаки,
слоты, бюджеты). Прецедент модели из кода — `blender/S05/build_medusa.py` (вся геометрия из кода, фиксированный seed,
без ручной правки .blend).

---

## 0. Принципы

1. **Спецификация — источник истины.** Сначала числа (`spec.json`), потом картинки под эти числа, потом модель под
   картинки. Если картинка расходится со спецификацией — перегенерируется картинка, а не правится спецификация.
2. **Всё измеряется скриптом.** «Совпадает» = отчёт JSON с `passed: true`, а не взгляд. Глаза — дополнительно.
3. **Модель — результат скрипта.** `.blend` пересобирается одной командой из `build_<key>.py`; ручная правка .blend
   (в том числе через MCP) не допускается. Живой Blender по MCP — только смотреть.
4. **Детерминизм.** Фиксированные seed; повторная сборка даёт те же FBX (отчёт детерминизма, как в handbook §4.3).
5. **Ничего чужого не трогать.** Если ассет уже есть (например Medusa из Tripo H2), эксперимент живёт в своих
   каталогах и в своей UE-папке (`<Key>SC`), канонический скелет и H2-ассеты героя не меняются.

## 2. Этап A: размерная спецификация `spec.json`

Делает Codex (рассуждением, без картинок), по карточке ассета из 04 §3, стилю 03 (С-1: 5–6 голов) и бюджету высоты.
Схема `unmatched.scratch-spec/1`, единицы — **сантиметры** в осях Blender (лицо −Y, `.L` = +X, Z вверх, z = 0 —
низ подставки):

```jsonc
{
  "schema": "unmatched.scratch-spec/1",
  "asset_id": "ASSET-…-001", "key": "…", "ue_key": "…SC", "kind": "hero|sidekick|prop",
  "status": "предложено",
  "height_cm": 55.0,                 // верх фигуры без оружия, от низа подставки = бюджет uu
  "height_tolerance_rel": 0.01,

  "heads": {"count": 5.5, "head_height_cm": 8.9},
  "landmarks_z_cm": {                // строго возрастают; лишние можно добавить, эти обязательны для гуманоида
    "base_top": 6.0, "sole": 6.0, "ankle": 8.5, "knee": 18.0, "crotch": 27.0, "waist": 33.0,
    "chest": 39.0, "shoulder": 43.5, "chin": 46.1, "eye": 50.0, "head_top": 55.0

    {"zone": "bracers", "class": "gold_antique", "hex": "#B08A3E", "team_accent": false},
    {"zone": "base", "class": "stone_base", "hex": "#3C3C3E", "team_accent": false}

  "triangle_target": {"min": 15000, "max": 25000, "hard_cap": 45000},
  "texture_px": 2048
}
```

Проверки спецификации (скрипт `tools/scratch-model/check_spec.py`, отчёт `spec-check.json`):

- схема и обязательные поля; ориентиры строго возрастают; `head_top == height_cm`; `base_top == base.height_cm`;
- пропорции: `height_cm − base_top` ≈ `heads.count × head_height_cm` (± 5 %);
- суставы внутри силуэта по ширинам (|x| ≤ ширина/2 на своей высоте), `.L` при x > 0, кость оружия у своей стороны
  (handbook §2.6), иерархия и 17 имён (16 у Harpy) — по `docs/art-pipeline/rig/rig-contract.json`;
- палитра: класс — одно из имён таблицы `material-library/README.md` (`steel_blued` … `wood`, индексы 1–15;
  `horn_claw` — класс расширения без глобального индекса, см. там §3a); `team_accent: true` только у классов с
  TeamColor «да» (кожа-материал `leather_*`, ткани `wool_coarse`/`linen`/`silk`, `feathers`), никогда у металлов,
  `skin`, `stone_base`, `wood`, `horn_claw` (handbook §2.9); ни один hex не ближе ΔE 20 к цветам фона и сетки шаблона
  (§3).

## 3. Этап B: размерная сетка (шаблон)

Скрипт `tools/scratch-model/make_template.py spec.json` (Pillow, без генерации) рисует по одному шаблону на вид и
`template.json`.

| Параметр | Правило |
|---|---|
| Размер холста | **ровно один из размеров, которые выдаёт `image_gen`** (проверить в начале работы; обычно 1024×1536 портрет, 1536×1024 для широких фигур/крыльев, 1024×1024) — иначе генератор перемасштабирует кадр |
| Масштаб | целое `px_per_cm = floor(0,85 × высота_холста / (height_cm с учётом оружия выше головы))`; одинаковый для всех видов |
| Начало | z = 0 (низ подставки) на строке `baseline_px`; центр подставки на колонке `center_px`; поле ≥ 8 % со всех сторон по самой широкой проекции |
| Фон | ровный светло-серый `#B4B4B4` (не путать с цветами палитры; на светлом фоне тёмный силуэт отделяется надёжнее) |
| Сетка | линии цвета `#00C8FF` (чистый голубой, не встречается в палитре): тонкие каждые 1 см, толстые каждые 5 см; вертикаль центра; горизонтали всех `landmarks_z_cm`; вертикальные направляющие ±ширина/2 на уровне каждого ориентира |
| Реперы | 4 метки регистрации в углах (чёрный круг Ø 24 px с белым крестом) в известных пикселях — по ним снимается совмещение |
| Подписи | названия ориентиров мелким шрифтом у правого края — только для человека, проверки их не используют |

Виды и камеры (ортографические, ось взгляда — горизонталь):

| Вид | Камера в Blender | Направление взгляда | Что справа в кадре |
|---|---|---|---|
| `front` | на −Y | +Y | `.L` персонажа (+X) |
| `side` | на +X | −X | +Y (персонаж смотрит **влево**) — это левый бок персонажа, слот LEFT |
| `back` | на +Y | −Y | −X |
| `top` (опционально) | на +Z | −Z | +X, верх кадра = +Y |

`template.json`: `px_per_cm`, `baseline_px`, `center_px`, размер холста, координаты реперов, для каждого вида —
матрица «пиксель ↔ (x|y, z) в см». Эти же числа задают камеры в Blender (§5): совпадение кадра модели и кадра
картинки «пиксель в пиксель» — основа всех проверок.

## 4. Этап C: виды в Codex `image_gen` и их согласование

### 4.1 Что генерировать

| Файл | Что это | Как |
|---|---|---|
| `views/<key>-front-shaded.png` | концепт-фронт: расписанная миниатюра, свет студии | edit: изображение 1 = шаблон `front`, изображение 2 = эталон качества `art/imagegen/hero-quality-v1/reference/medusa-quality-reference.png` |
| `views/<key>-side-shaded.png`, `-back-shaded.png` | те же персонаж и костюм | edit: 1 = шаблон вида, 2 = готовый front-shaded (личность, костюм), для back 3 = side-shaded |
| `views/<key>-<view>-albedo.png` | **плоские цвета без света**: без теней, AO, бликов, градиентов освещения; тот же силуэт и рисунок | edit: 1 = `<view>-shaded`, промпт «flat unlit albedo, remove all lighting and shadows, keep every contour and pixel position» |
| `details/<key>-face-{front,side}-*.png` (герой) | лицо крупно: голова на свою сетку (высота головы = 80 % кадра) | edit поверх кропа головы из front/side shaded; для проекции на лицо |
| `details/<key>-weapon-*.png` (если оружие) | оружие в орто на своей сетке | по `weapon` из spec |

Правила промпта (дословно включать по смыслу): «orthographic, no perspective»; строгий ракурс («strict LEFT side
profile, no three-quarter view»); «keep the measurement grid and the four registration marks exactly where they are,
the figure occludes the grid»; «figure fits the guide lines: soles/base on the baseline, head top on the head_top line,
shoulders on the shoulder line»; «same character, outfit and colors as image 2»; «no text, labels, watermark,
cropping, extra limbs or added props»; оружие — по `weapon.description`, в своей руке. Фон — как в шаблоне.

`raw/<key>-<view>-<variant>-try<N>.png` — оригиналы **без правки пикселей** (в git). В `prompts.md` по каждой попытке:
дата, инструмент, `referenced_image_paths` по порядку, точный промпт, итог проверки (§4.3).

### 4.2 Регистрация (`tools/scratch-model/register_views.py`)

Генератор перерисовывает весь кадр, поэтому сетка в результате может сдвинуться или чуть масштабироваться.

1. Найти 4 репера (порог по тёмному кругу + центр масс) → подогнать **только масштаб и сдвиг** (без поворота и
   перекоса) к позициям `template.json`, МНК.
2. Остаток подгонки ≤ 1,5 px на каждом репере; поправка масштаба ≤ 3 %. Больше — вид отклоняется (перегенерировать).
3. Применить преобразование (Lanczos) → кадр ровно как у шаблона → `views/<key>-<view>-<variant>.png`. Записать
   параметры в `views-registration.json`.
4. Нет реперов (генератор их стёр) — попытка не засчитывается.

### 4.3 Маски и проверки согласованности (`tools/scratch-model/check_views.py`)

Маска силуэта: пиксели, далёкие от фона и от цвета сетки (ΔE76 > 12 к обоим), крупнейшая связная компонента +
заливка дыр; реперы исключены → `masks/<key>-<view>.png` (белая фигура на чёрном). Отчёт `views-check.json`
(`checks: {name: {passed, measured, expected}}`):

| Проверка | Порог (предложено) |
|---|---|
| одна связная фигура, касаний края кадра нет | да |
| низ подставки | `baseline_px` ± 2 px |
| верх фигуры (без оружия, по колонкам вне `rows_excluded`) | `height_cm` ± 1 % |
| ширина подставки (front/back/side) | `base.diameter_cm` ± 2 % |
| ширины на ориентирах | `widths_cm` ± 8 % каждая, медиана отклонений ≤ 4 % |
| front ↔ back: профиль ширины по строкам (зеркально) | медиана \|Δw\| ≤ 2 % высоты, p95 ≤ 5 % (строки оружия исключены) |
| front ↔ side: верх и низ | ± 1 % высоты |
| shaded ↔ albedo одного вида | IoU масок ≥ 0,98 |
| albedo «без света» | разброс яркости внутри каждой зоны палитры (после кластеризации к палитре) ≤ 0,12 по L* (иначе в BC запечётся свет) |
| цвет сетки внутри маски | ≤ 0,2 % пикселей маски (фигура закрывает сетку) |

Не прошло — перегенерировать вид, **максимум 4 попытки на вид**. Нет прохода после 4 попыток → остановка с отчётом
(какие проверки, какие числа, превью наложения маски на шаблон).

Контроль глазами (записать в `prompts.md`): строгие ракурсы, одна фигура, оружие в той же руке во всех видах, нет
лишних конечностей и голов, лицо и костюм совпадают.

## 5. Этап D: модель в Blender

### 5.1 Сцена-эталон (`tools/scratch-model/setup_refs.py`, headless)

Из `spec.json` + `template.json`: сцена в метрах; для каждого вида — ортокамера с `ortho_scale` =
ширина_холста / `px_per_cm` / 100 (м), разрешение = холст, положение так, чтобы `baseline_px`/`center_px` попали в
z = 0 / центр; Empty-изображение albedo-вида на плоскости вида (для просмотра). Проверка самой сцены: рендер
куба-эталона с известными размерами попадает в ожидаемые пиксели ± 1 px (`refs-check.json`). Сохраняет
`work/<key>-refs.blend`.

### 5.2 Построение (`<run>/scripts/build_<key>.py`)

Скрипт пишет агент для конкретного ассета. Импортирует общие функции из `tools/scratch-model/` и экспорт из
`tools/tripo-pipeline/blender/candidate_build/core.py` (только чтение). Запуск:
`"$B" -b --factory-startup --python-exit-code 1 --python <run>/scripts/build_<key>.py -- <run>`; маркер
`SCRATCH_BUILD_OK`.

Порядок:

1. **Блокинг по частям** (коллекции = части: тело, голова, волосы/корона, одежда слоями, кисти, стопы, оружие,
   подставка). Размеры и положения — только из `spec.json` (ориентиры, ширины, суставы). Подставка: цилиндр
   `diameter_cm × height_cm` + фаска, центр в (0, 0), низ z = 0.
2. **Посадка силуэта.** Допустимые приёмы (выбор записать в отчёт по каждой части):
   - примитивы + bmesh-правки, профили и вращение (`screw`) для круглых деталей (подставка, браслеты, древко);
   - `skin`-модификатор по графу суставов для конечностей и тела, затем `subdivision`;
   - кривые с `bevel` для ремней, канта, змей, тетивы;
   - **визуальная оболочка** для объёмных масс (плащ, волосы, крылья): пересечение выдавливаний масок front/side/back
     по сетке вокселей (шаг ≤ 0,25 см) → `voxel remesh` → сглаживание; только для частей, где примитивы не
     достают силуэт;
   - `boolean` — только на закрытых сетках, после него проверка манифолдности.
   Запрещено: импорт чужих 3D-моделей (scraped `.glb`, Tripo, Sketchfab и т. п.) как геометрии; подгонка
   модели под картинку правкой пикселей картинки.
3. **Проверка посадки** (`tools/scratch-model/fit_check.py`): рендер маски модели каждой камерой §5.1 (Workbench,
   плоский белый на чёрном, без сглаживания) и сравнение с `masks/<view>.png`. Отчёт `reports/fit-report.json` +
   наложения `preview/fit-<view>.png` (контур модели поверх albedo-вида).

   | Проверка | Порог (предложено) |
   |---|---|
   | IoU силуэта, каждый вид | ≥ 0,92 |
   | граница: p95 расстояния контур↔контур | ≤ 1,5 % высоты фигуры |
   | верх фигуры | `height_cm` ± 1 % |
   | ориентиры (рост ширины по строкам) | строки ориентиров ± 1 % высоты |
   | подставка | диаметр ± 1 %, низ z = 0 ± 0,01 см |

   Итерации — правкой `build_<key>.py` и пересборкой. Записывать в отчёт IoU по итерациям (это одна из метрик
   эксперимента).
4. **Деталь.** Только читаемая с игровой камеры (04 §1: «силуэт важнее деталей»): складки крупные, лицо — объём носа,
   надбровья, скул; пальцы — монолитом кисти (костей пальцев нет). Мелкий рисунок даёт текстура (§6), а не геометрия.
5. **Чистота сетки:** все части закрыты или их открытые края спрятаны внутри других частей; нормали наружу
   (проверка ray-escape, handbook §7.2); нет треугольников < 1e-4 см²; трансформы применены; без отрицательного
   масштаба.
6. **Бюджет:** `triangle_target` (герой 15–25k по 04, жёсткий потолок 45k); при превышении — `decimate` по частям с
   приоритетом лица, кистей и оружия, затем повтор fit_check (IoU не должен упасть ниже порога).
7. **Low и high.** `low` — то, что экспортируется. `high` — копия с `subdivision` уровня 2 и фасками — только источник
   нормалей для бейка (§6.3).

## 6. Этап E: UV и текстуры

### 6.1 UV

- Швы по частям (по границам частей и вдоль скрытых сторон), `uv.unwrap(method="ANGLE_BASED" или "MINIMUM_STRETCH")`,
  `uv.pack_islands(rotate=True, margin_method="FRACTION", margin=…)`; 0 перекрытий; зазор ≥ 8 px на 2K.
- Приоритет плотности текселей как в H2: лицо ×2, кисти ×1,75, оружие ×1,5, подставка ×0,45.
- Второй канал `UV1_m` (метры, центры островов в 0,0) — как требует `M_UM_Figure_v2` (handbook §2.5).

### 6.2 BC: проекция albedo-видов (`tools/scratch-model/project_bake.py`)

Ортопроекция линейна, поэтому перенос делается в numpy, без шейдерных трюков:

1. Бейк в атлас UV0 (Cycles CPU, EMIT): **мировая позиция** и **мировая нормаль** каждого текселя (как карта
   rest-позиций стадии `aux` H2).
2. Для каждой камеры §5.1: буфер глубины модели (рендер Z-pass в разрешении холста). Тексель видим из вида, если его
   глубина совпадает с буфером (± 0,05 см).
3. Цвет из albedo-вида по пиксельной проекции позиции; вес = видимость × max(0, n·(−d))², нормировка по видам.
   Правый бок (камеры нет): из `side` зеркально только если `pose` симметрична по X, иначе из front/back.
   Лицо — из `details/` с весом ×2 там, где они есть.
4. Невидимые и слабые (сумма весов < 0,3) тексели — цвет зоны палитры по ближайшей части (метка части в атласе) →
   затем пул-пуш-дилатация ≥ 16 px.
5. Отчёт `reports/project-report.json`: доля текселей с весом ≥ 0,3 (порог: ≥ 85 % площади, видимой с игровой
   камеры −55°), швы между видами (ΔE на границе смены доминирующего вида; p95 ≤ 10), `preview/bc-atlas.png`.

### 6.3 Остальные карты

- **Зоны → MatID/ORM:** каждый тексель BC относится к ближайшей зоне палитры (ΔE в Lab, после медианного фильтра);
  зона → класс → MatID (`класс × 16 + 8`), roughness/metallic по классу библиотеки материалов (металл ровно 1, прочее 0;
  roughness по таблице класса). Отчёт: доли площадей зон.
- **Нормаль:** бейк `high → low` (selected-to-active, Cycles CPU, cage по отклонению ×1,5), OpenGL → DirectX (`G =
  255 − G`). `N_OpenGL` — служебная копия.
- **AO:** Cycles CPU, 128 samples, distance 0,08 × рост, подставка — окклюдер; гейты как у H2
  (p99 − p1 ≥ 32; ≥ 2 % текселей < 250).
- **ORM** = (AO, Roughness, Metallic). **TeamAccent** — зоны `team_accent: true`, проверка покрытия 5–12 % и
  ≤ 20 % на часть (handbook §2.9).
- Выход: 2K (`texture_px`) в git; мастер 4K не нужен (проекция не даёт больше деталей, чем у видов).

## 7. Этап F: риг, экспорт, отчёты для UE

- **Риг:** `SKEL_UM_Humanoid`, `UM_HUMANOID_17_v2`, головы костей = `spec.joints_cm` (см → м), хвосты — голова
  ребёнка или явный `tail`. Rest = поза миниатюры.
- **Веса:** жёстко (100 %) — оружие, голова с волосами/короной, кисти, стопы, подставка не скинится; остальное —
  `ARMATURE_AUTO` (bone heat) по частям с выключенными чужими костями (как `rig.py` режим `heat`), затем очистка:
  ≤ 4 влияния, < 0,01 → 0, нормировка, снап к 1/255. Сглаживание весов не применять (handbook §7.4).
- **Пробы:** `tools/tripo-pipeline/anim/rig_deform_probe.py` (7/7 plausible) на .blend и на FBX;
  `validate_clip.py --kind=skeletal-mesh --character=<Hero> --skeleton=UM_HUMANOID_17_v2` → PASS.
- **Экспорт:** только функциями `candidate_build/core.py` (`transform_for_fbx`, `export_fbx`, `patch_fbx_units`,
  `make_fbx_deterministic`) — UM_FBX_v1, лицо +X. `bpy.data.filepath` пуст перед экспортом.
- **Отчёты для `skeletal-adopt`:** стадия adopt CLI читает отчёты сборки в известных форматах
  (`tools/tripo-pipeline/skeletal_adopt.py`, `REPORT_FORMATS`; адаптеры героев — `skeletal_adopt_formats.py`).
  Сборка пишет `reports/rig-report.json` и `reports/textures-report.json` в формате родного H2 bake (образец —
  `art/pipeline-candidates/ASSET-MEDUSA-001/20260929-h2-bake/reports/`). Если формат не ложится — **новый** адаптер
  `scratch_sc1` в `skeletal_adopt_formats.py` (существующие форматы не менять), плюс запись в PIPELINE.md.
- **Анимации:** handbook §4.5, цель — `SK_<Key>_SC1.fbx`; шаблоны тайминга — клипы ближайшего героя.
- **UE:** handbook §4.6 с ключом `<Key>SC` (свой канонический скелет `/Game/PipelineCandidates/<Key>SC/Rig/…`).

## 9. Edge-кейсы пути B

| Симптом | Причина | Действие |
|---|---|---|
| Генератор рисует перспективу или 3/4 | промпт без жёсткого ракурса / слабый шаблон | повторить с «strict orthographic … no three-quarter»; проверить по front↔back и верху/низу |
| Сетка «уплыла», масштаб другой | генератор перерисовал кадр | регистрация по реперам (§4.2); > 3 % масштаба — перегенерация |
| Реперы стёрты | генератор «почистил» кадр | попытка не засчитывается; в промпте явно «keep the four registration marks» |
| Фигура выше `head_top`, подставка уже | генератор игнорирует направляющие | перегенерация; спецификацию **не** подгонять под картинку |
| В albedo остались тени | генератор оставил свет | проверка разброса L* по зонам; перегенерировать albedo |
| Голубые линии сетки внутри фигуры | фигура полупрозрачна для генератора | ≤ 0,2 % маски, иначе перегенерация |
| front и back не зеркальны | разные пропорции в видах | порог профиля ширины; исправлять перегенерацией вида с бо́льшим отклонением от spec |
| Оружие в другой руке на side | генератор зеркалит | глаза + `weapon` из spec; перегенерация |
| IoU не растёт выше 0,85 | грубый блокинг / не та часть «вылезает» | наложение `fit-<view>.png`: найти часть по месту ошибки; для мягких масс — визуальная оболочка |
| Визуальная оболочка «квадратная» | у масок мало видов | добавить `top` или сгладить + `voxel remesh` мельче; проверить fit снова |
| Проекция «двоит» на боках | весовое смешение front и side на 45° | степень веса 2→4, швы — в `project-report` |
| Лицо мыльное | 1 px вида = ~0,4 мм, лицо мелкое | `details/` лица на своей сетке, вес ×2 |
| Тёмные полосы на стыке частей | AO подставки/частей + дилатация | фон AO = 1,0, дилатация до бейка ORM |
| Bone heat не сходится («Bone Heat Weighting: failed») | открытые/пересекающиеся части | веса по частям, закрыть части; при неудаче — `axis_blend`/`chain` правила как в H2 |
| adopt отказывает по формату отчёта | отчёты не в формате H2 | новый адаптер `scratch_sc1` (§7), старые не менять |
| В UE изменился скелет существующего героя | импорт в `<Key>`, а не `<Key>SC` | только `<Key>SC`; снимок до/после покажет |
