Статус: **одобрено** пользователем 2026-10-03 (ответы на вопросы — §12).
Работа идёт **прямо в основной копии на `fix/admin-panel`** (решение пользователя 2026-10-03: «а ты можешь работать
сразу в ветке»): без worktree, без копирования `Content`, без `safe-integrate.sh` и `sync-staged-build.ps1`.
Сессия ENV-MAPS (`C:/tmp/wt-envmaps`) вливается через `safe-integrate.sh`; поэтому коммичу сразу после каждого шага, ничего
не оставляю в индексе, после её вливания с `unreal/` пересобираю редактор.
Задание: [ART-TUNER-SESSION-PROMPT.md](ART-TUNER-SESSION-PROMPT.md).

## 0. Что выяснило исследование (коротко)

- **Сервер.** `-Bench` уже обходит бэкенд: в `BeginPlay` выходит до логина (`S08FlowGameMode.cpp:312`), снапшот берёт из
  `Config/Bench/S08Bench<Map>.json` (Cobble / Marmoreal / Sarpedon; 6 фигур) и строит доску обычным
  `SyncBoardFromApplied()`. Режим просмотра — это тот же init без пошагового автомата видов и без `RequestExit`.
- **Камера.** `ACameraActor` + `FS08CameraZoom` (`S08ArtHud.cpp:59-162`): колесо ×1.25 за щелчок, Space — обзор, фокус на
  выбранном герое при зуме ≥ 1.2×. **Поворота и панорамы нет** (наклон 55° и рыскание −90° зашиты). Колесо и Space работают
  только в стадии `Started`, в bench они отключены.
- **Ввод.** Прямой опрос `PC->WasInputKeyJustPressed` в `Tick`, без Enhanced Input. Свободны: Tab, H, P, F1–F9, 0.
  Заняты в живой игре: F10 (отладочная панель), M E A N R G X D I, 1–9, Enter, Esc, ЛКМ / ПКМ. В режиме без сервера
  стадия не `Started`, поэтому игровые клавиши там молчат и не мешают.
- **UI.** Основной HUD — Slate через `SNew`, добавлен в `GameViewport` (`S08FlowGameMode.cpp:3961, 4132`); art-слой —
  `UUserWidget` на C++. Слайдеров нет. Шрифт `FCoreStyle` (Roboto) кириллицу показывает. Снимок **с UI** уже есть:
  `FScreenshotRequest(bShowUI=true)` (`:3505-3539`).
- **«Активный» герой.** Отдельного «чей ход» нет: подсветка `Active` = выбран или атакует
  (`S08FighterActor.cpp:915`). Tab = `SelectFighter(следующий живой)` — тот же путь, что у bench.
- **Перечитывание (live tune `reload`).** 25–60 мс, но сносит и пересоздаёт всё: свет, туман, Niagara, пропсы, **фигуры**
  (анимации начинаются заново, Niagara прогревается). Для ползунка это заметный «щелчок».
- **Прямое применение возможно** почти для всего света: компоненты лежат в массивах с устойчивым порядком
  (`ArtLights`, `ConceptLights`, `HeroLights[0/1]` у фигуры), подсветка героев пересобирается дёшево через
  `UpdateHeroLights()`. Ловушки: мерцание огней Sarpedon перезаписывает `SetIntensity` каждый кадр (нужно менять базу в
  анимационном компоненте); `ApplyArtLights` пропускает работу, если id профиля тот же.
- **Sarpedon скрывает свои туман и огни раскладки** (`lit3d.hide = fog, layoutLights`): ползунки тумана там ничего не
  меняют — панель покажет это явно.
- **Материалы.** «Яркость острова» (`BakedTint`) и ветер (`WindAmp`, `WindHeight`…) — параметры material instance,
  ставятся только коммандлетом `ue_scene_material.py`. Рантайм-пути нет; есть прецедент per-slot MID (`AddWind`).
  MPC `MPC_EnvScene` содержит только `Live` и `Emissive`, менять его граф = новый ассет и перезапуск.
- **JSON-указателей и overrides в коде нет.** Ни один инструмент не правит `S08ArtBoardProfiles.json` текстом с сохранением
  форматирования (все пересериализуют копию) — `art_tuner_fold.py` пишется с нуля.
- **Эталон рендера.** Любой путь профиля, кроме pak, даёт `profilesSource=override` → кадр `reference=0`. Для тюнера это
  нормально (это не приёмочный кадр); без флагов ничего не меняется.

## 2. Архитектура

**Выбор: Slate на C++** (`SCompoundWidget`), в том же viewport, что и существующий HUD.

- Работает в собранной игре и в редакторе `-game`; код читается, диффится и тестируется агентами.
- UMG-виджеты на C++ проекту тоже знакомы, но для формы из десятков строк Slate проще (нет `.uasset`, нет WBP).
- **Не** Editor Utility Widget / Blueprint: бинарные `.uasset`, агенты их не читают и не диффят, в собранной игре не
  работают.
- **Не** Remote Control (веб-страница): плагин + HTTP-сервер, свои пресеты в `.uasset`, в собранной игре настраивается
  отдельно, и это лишний процесс; данные всё равно надо было бы сводить в наш JSON.

**Новые файлы** (всё в `Source/Unmatched/S08/`):

| Файл | Что |
|---|---|
| `S08ArtView.h/.cpp` | режим без сервера: выбор фикстуры, свободная камера, клавиши |
| `S08ArtTuner.h/.cpp` | модель: реестр параметров, JSON-указатели, overrides (чтение/запись), применение |
| `S08ArtTunerPanel.h/.cpp` | Slate-панель (только UI, вся логика в модели) |
| `S08ArtTunerTests.cpp`, `S08ArtViewTests.cpp` | автотесты |
| `Config/ArtTuner/S08ArtTunerParams.json` | реестр: группы, подписи по-русски, указатели, диапазоны, шаги, способ применения |

Реестр — данные, а не код: подписи в UTF-8 JSON (нет проблем с кодировкой исходников), агенты могут добавить строку без
C++. Указатели — шаблоны: `{profile}` = id профиля доски, `{board}` = индекс доски, `*` = каждый элемент массива (подпись
берётся из его `id`/`name`). Тест сверяет диапазоны реестра с C++-парсером (§9), чтобы они не «выдумывались».

**Флаги:**

- `-ArtView=sarpedon|marmoreal|cobble` — просмотр без сервера.
- `-ArtTuner` — включить панель (в `-ArtView`; в живой игре — тоже, по Shift+F10).
- `-ArtTunerFile=<abs>` — куда писать и откуда накладывать overrides.
- Без этих флагов: ни один новый код-путь не выполняется (`Enabled()` по флагу, как у `S08LiveTune`), игра бит-в-бит
  прежняя. Это проверяется тестом `OffByDefault` и кадром `-Bench` K1 (§ M6).

## 3. Применение на лету

Один путь для ползунка, live tune `tune` и загрузки overrides:

1. Модель держит документ профиля как `FJsonObject` (база = файл профиля на старте или после `reload`).
2. Изменение = запись значения по указателю в копию документа → `FS08BoardArtData::ParseJson` (**тот же парсер и та же
   валидация, что на старте**; 58 КБ ≈ 1–2 мс). Ошибка → значение не применяется, строка подсвечивается, текст ошибки внизу.
3. Успех → новые данные подменяют `ArtData` и `ActiveProfile` доски (новый мутирующий сеттер в `AS08BoardActor`), затем
   вызывается применение по «области» из реестра:

| Область | Что делается | Отклик |
|---|---|---|
| `heroLight` | `UpdateHeroLights()` — компоненты переиспользуются | сразу |
| `profileLights` | луна, небо (интенсивность/цвет), точки профиля, экспозиция → прямо на `ArtLights` (+ `SetFogDensity` и т. п. для тумана) | сразу |
| `mapGrade` | `ApplyMapGrade()` на MID плоскости карты | сразу |
| `conceptLights` | `SetIntensity/Radius/Color` на `ConceptLights[i]` + новая база мерцания в анимационном компоненте | сразу |
| `materials` | параметры на runtime-MID (§5, M4) | сразу |
| `rebuild` | всё прочее (небо `lowerHemisphereIsBlack`, `seaZUU`, `waterfallScaleZ`, `anims`) → общий путь `reload` из памяти (новая перегрузка `ReloadArtData` от текста), ≤ 4 раз/с при перетаскивании + финальный при отпускании | 25–60 мс + «щелчок» |

- Частота применения при перетаскивании ограничена 30 Гц; цель отклика ≤ 0,2 с.
- `AppliedRender` (RENDER-отпечаток) обновляется вместе с прямым применением, чтобы трасса не врала.
- Расхождение панели и JSON исключено по построению: сцена всегда строится из распарсенного документа, а сохраняется
  разница этого же документа с базой. Тест: после серии `tune` полная пересборка из документа даёт те же значения
  на компонентах.
- Строки трассы подсветки героев при перетаскивании пишутся не чаще 1 раза в секунду.
- Экспозиция: на панели одна строка «EV100», она пишет `ev100` и `minBrightness = maxBrightness = 2^ev100`
  (парсер требует min == max).
- Не на панели (жёсткие правила): поворот луны (ключ сцены −55, 30, 0), добавление/удаление огней (бюджет 6 точек
  уже исчерпан на Sarpedon), позиции огней.

## 4. Модель сохранения

- «Сохранить» пишет **только изменённые** значения в
  `unreal/Unmatched/Config/ArtBoards/S08ArtTuner.overrides.json` (путь задаёт `-ArtTunerFile`; pak только для чтения):

  ```json
  {"schema": "unmatched.art-tuner-overrides/1",
   "savedAt": "2026-10-03T12:04:31+05:00",
   "board": "sarpedon-original", "profile": "sarpedon-night",
   "baseProfilesSha256": "…", "baseRevision": 20,
   "anchors": {"/boards/4/id": "sarpedon-original"},
   "entries": [
     {"pointer": "/lightProfiles/sarpedon-night/heroLight/key/lux", "value": 7.5, "was": 7},
     {"pointer": "/boards/4/conceptPaste/lit3d/lights/1/intensityCd", "value": 95, "was": 80}]}
  ```

  - Запись атомарная (`.tmp` → rename, `S08LiveTune::WriteFileAtomic`). Значения округлены до шага ползунка — в файле
    `7.5`, а не `7.4999998`.
  - `anchors` защищают указатели с индексами массивов: если доска 4 больше не `sarpedon-original`, запись не применяется.
  - Один файл хранит все карты: при сохранении записи другой доски сохраняются.
- **Старт с `-ArtTunerFile`**: overrides накладываются на профиль тем же путём (§3), панель открывается уже с ними.
  Нет файла — пусто. Битая запись (нет указателя, вне диапазона, якорь не совпал) пропускается, на экране и в трассе
  предупреждение; игра не падает.
  - Если в профиле значение по указателю уже не равно `was` (его поменяла сессия ENV-MAPS) — запись всё равно
    применяется, но помечается «база изменилась: было X, стало Y».
- **Файл не в git** (`.gitignore`): это рабочий черновик пользователя, он не мешает `safe-integrate.sh`.
- **`tools/art/art_tuner_fold.py`** вносит overrides в `S08ArtBoardProfiles.json` **правкой текста**:
  - свой маленький сканер JSON находит точный диапазон символов значения по указателю и заменяет только его;
    форматирование, порядок ключей, длинные однострочные записи и концы строк (CRLF/LF) не трогаются;
  - проверяет якоря и `was` (расхождение → отказ с объяснением, `--force` берёт значение пользователя);
  - ключа нет (новый необязательный блок, напр. `materialOverrides`) → вставляет его текстом перед `}` родителя в том же
    стиле;
  - `--dry-run` / `--check` печатают унифицированный дифф; результат перепроверяется `json.loads` и сравнением всех
    остальных значений с исходником;
  - после внесения файл переносится в `docs/art-pipeline/art-tuner-saves/<дата-время>.overrides.json` (в git), чтобы было
    видно, что и когда внёс пользователь; `revision` профиля +1.
  - Так ИИ «подхватывает» значения: агент запускает fold → дифф → коммит.

| Плотность | P/fog/density | (0–1] | 0,01 |
| Спад по высоте | P/fog/heightFalloff | (0–2] | 0,01 |
| Высота, uu | P/fog/heightZ | ±100000 (ползунок ±2000*) | 10 |
| Начало / конец, uu | P/fog/startDistanceUU, endDistanceUU | 0–100000 / 0 или (начало–1e6] | 50 |
| Макс. непрозрачность | P/fog/maxOpacity | 0–1 | 0,01 |
| Цвет (линейный) | P/fog/colorLinear | 0–10 (ползунок 0–2*) | 0,01 |

**Тон карты** (`mapGrade`, сразу; только карты с `mapGrade`): `nightEV` −4–2, `nightSaturation` 0–1,5, `lift` 0–20,
`nightTintLinear` 0–4, `maskSaturation` / `liftSaturation` 0–3, `maskInverseTintLinear` 0–4.

**Огни Sarpedon** (`conceptLights`, сразу; по строке на огонь: fire-fort, fire-brazier, lantern-left, lantern-bay,
lantern-deck-se): сила L/intensityCd 0–10000 кд (ползунок 0–300*, шаг 1), радиус L/radius 1–5000 uu (шаг 10),
цвет L/colorSrgb, мерцание L/flicker/amp 0–0,5 и L/flicker/hz 0–20 Гц.

**Сцена Sarpedon** (`rebuild`, ⟳): уровень моря `…/lit3d/seaZUU` −1000…−3 uu, высота водопада `…/lit3d/waterfallScaleZ`
0,25–4.

**Материалы сцены** (`materials`, новое, M4). Новый **необязательный** блок профиля:

```json
"conceptPaste": {"lit3d": {…, "materialOverrides": {
   "Island":  {"tintGain": 1.0},
   "Ship":    {"tintGain": 1.0},
   "FrameWood": {"tintGain": 1.0},
   "Foliage": {"windAmp": 8, "windHz": 0.35, "windHeight": 120, "windFlutter": 1.5}}}}
```

- Ключи — «образы» материалов коммандлета: `Island, Ship, Fort, Palisade, Piles` (`MI_Env_S_*`),
  `Rock, RockWet, Wood, Ground, Foliage` (`MI_EnvScene_Proj_*`), `FrameWood, FrameIron`.
- `tintGain` 0–4 — множитель к `BakedTint`/`AlbedoGain`, уже стоящему в MI («яркость острова»); `tint` [r,g,b] 0–4 —
  необязательный оттенок поверх. Относительный множитель выбран намеренно: если агенты перезапекут MI коммандлетом,
  ручная правка не превращается в устаревшее абсолютное значение.
- Ветер: `windAmp` 0–40 uu, `windHz` 0–3, `windHeight` 10–1000 uu, `windFlutter` 0–5 — пишутся в те же скаляры MI.
  Эти диапазоны новые (у C++ проверки нет): **предложено**, подтвердить в M4 по виду.
- Применение: при сборке доски (`ApplyLit3d`/`ApplyScene`) для слотов пропсов, чей материал (или его родитель) — нужный MI,
  создаётся MID (как `AddWind`), ставятся параметры; MID запоминаются → ползунок меняет их сразу.
- Без блока ни одного MID не создаётся — вид прежний бит-в-бит (тест + кадр).
- Перед реализацией проверю на трассе/в коде, что остров действительно рисуется `MI_Env_S_Island`, а листва —
  `MI_EnvScene_Proj_Foliage` с WPO-ветром (скаляры в MI, `Live` из MPC). Если нет — M4 сузится, скажу заранее.

**Не на панели в v1:** параметры `fx[].user` раскладок, `grade` паст-режима, `anims` (только `rebuild`, можно добавить
строками реестра позже).

## 6. Просмотр без сервера

- `-ArtView=sarpedon|marmoreal|cobble` → фикстура `Config/Bench/S08Bench<Map>.json` (уже в pak) → тот же init, что у
  `-Bench` (`S08FlowGameMode.cpp:6762-6791`), затем **свободный шаг**: без автомата видов, без замера, без `ProfileGPU`,
  без `RequestExit`, без обязательных `-BenchOut/-BenchViews`.
- Эффекты: `-Bench` в командную строку не передаётся → Niagara, ветер, мерцание, дыхание живые (фриз только по P).
- Камера: зум и Space разблокируются в `-ArtView` (гейт `Started` обходится только при флаге). Поворот (рыскание ±180°,
  наклон 20–85°) и панорама — смещения поверх текущего рига, только в `-ArtView`; клавиши 1–5 и Space их сбрасывают.
  Подсветка героев от поворота камеры не меняется (её азимут — параметр профиля).
- Tab: цикл `SelectFighter` по живым бойцам. Клик по своей фигуре сейчас покажет «ENEMY» (пустой user id) — в `-ArtView`
  подставлю `benchViewerId`.
- H — `heroLight.enabled` только в рантайме, P — `SetFxOptionsOverride(freeze)` + пауза анимационных компонентов без
  пересборки, F1 — справка (Slate-оверлей).
- Live tune (`-ArtLiveTune`) работает и в `-ArtView` (тот же опрос в Tick) — для автоматизации и тестов.
- Окно `-windowed -ResX=1920 -ResY=1080`, лимит 60 FPS (как в обычном клиенте, AGENTS.md «Unreal GPU load»).
- Профиль: лаунчер передаёт `-ArtBoardProfiles=<репо>/…/S08ArtBoardProfiles.json` и `-ArtEnvLayouts=<репо>/…/EnvLayouts`
  — тюнер начинает с **текущего** профиля из репозитория (ENV-MAPS мог его поменять после упаковки). Не парсится (новые
  поля требуют более нового C++) → откат на pak и предупреждение на экране.

## 9. Тесты

- **C++ automation** (`Unmatched.S08.ArtTuner.*`, `Unmatched.S08.ArtView.*`):
  - `Pointer` — чтение/запись по указателю в `FJsonObject`, массивы, ошибки (нет ключа, тип, `~0`/`~1`).
  - `Registry` — реестр парсится; для каждой строки значение на границах диапазона проходит C++-парсер, за границей —
    нет (диапазоны не расходятся с C++).
  - `Overrides` — разбор файла, якоря, `was`, битые записи пропускаются с предупреждением, округление до шага.
  - `Apply` — `tune` в мир с доской: значения на компонентах (spot, point, fog, MID) равны значениям документа;
    полная пересборка из документа даёт те же значения.
  - `SaveFile` — содержимое сохранения: только изменённое, другие доски не теряются, атомарность.
  - `MaterialOverrides` — блок парсится, без блока MID не создаются, с блоком — параметры стоят.
  - `OffByDefault` — без флагов: панели нет, реестр не грузится, `ArtView` выключен, overrides не читаются.
  - `ArtView` — фикстура → доска и 6 фигур; Tab меняет выбранного; виды 1–5 совпадают с bench.
  - Весь набор `Unmatched.S08+Unmatched.S09+Unmatched.S10` — зелёный.
- **pytest** `tools/art/tests/test_art_tuner_fold.py`: внесение в копию **реального** профиля — меняются только нужные
  байты (дифф = N строк), остальное идентично; идемпотентность (второй прогон — ноль изменений); CRLF и LF; вставка нового
  ключа; якорь/`was` не совпал → отказ; `--check`. Плюс `test_live_tune.py` для новых действий.

## 11. Этапы

Порядок «сначала польза»: после M3 у тебя уже есть рабочая панель со светом (герои, сцена, туман, тон карты, огни
Sarpedon) и сохранением. Материалы и fold — следом.

| Этап | Что | Готово, когда | Оценка |
|---|---|---|---|
| M1 | `-ArtView`: фикстура, свободный шаг, камера (поворот, панорама, 1–5), Tab, H, P, F1 | `-game` открывает доску без сервера; тесты `ArtView`, `OffByDefault` | 2–2,5 ч |
| M2 | модель: указатели, реестр, документ, применение по областям, overrides чтение/запись, `tune`/`tunerState`/`tunerSave` | тесты `Pointer/Registry/Overrides/Apply/SaveFile`; `tune` меняет сцену ≤ 0,2 с | 3 ч |
| M3 | Slate-панель: группы, ползунки, поля, цвет, кнопки, состояние, Ctrl+S, F10 | панель работает в `-game`; кадр с UI | 3 ч |
| M4 | `materialOverrides`: парсер, MID, ползунки острова/корабля/рамы/ветра | тест `MaterialOverrides`; без блока вид прежний | 2 ч |
| M5 | `art_tuner_fold.py` + pytest, лаунчеры, `tools/art/ART-TUNER.md`, `LIVE-TUNE.md` | pytest зелёный, fold на копии — минимальный дифф | 1,5 ч |
| M6 | упаковка (один раз), проверка на собранном клиенте, evidence | всё из «Готово, когда» задания | 1,5–2 ч |

Итого ≈ 9–10 ч. Первая оценка (20 ч, затем 13–14 ч) исходила из 4–10 мин на пересборку — это было неверно.
Замер по логам UBT (`%LOCALAPPDATA%/UnrealBuildTool/Log-backup-*.txt`): инкрементальная сборка редактора с
`S08FlowGameMode.cpp` и ещё 25 файлами — **36 с**, одного файла — 10–17 с (adaptive unity: изменённые файлы собираются
по отдельности).

Куда реально уходит время:
- написание кода: ~2500–3500 строк C++ (режим просмотра, модель, панель, тесты) + ~400 строк Python;
- проверки в запущенном клиенте: кадры, отклик ползунка, сохранение и перезапуск;
- UE-тесты: старт редактора без рендера + прогон — несколько минут; внутри этапа только целевые
  (`Unmatched.S08.ArtTuner`), полный `S08+S09+S10` — в конце этапа;
- упаковка клиента — один раз в конце.

Чтобы пересборок было меньше:
- новая логика — в новых небольших файлах (`S08ArtView.cpp`, `S08ArtTuner*.cpp`), в `S08FlowGameMode.cpp` — только
  точки подключения;
- подписи, диапазоны, шаги и группы — в `S08ArtTunerParams.json`: их правка не требует сборки, панель перечитывает реестр
  по live tune `reload`;
- значения параметров — по существующему live tune без перезапуска (AGENTS.md «Iteration speed»).

**Проверка M6** (из задания): `-ArtView=sarpedon -ArtTuner -ArtLiveTune` вне экрана → `tune` трёх параметров (lux ключа,
сила огня, тон острова) → кадры с панелью и без → `tunerSave` → перезапуск с `-ArtTunerFile` → значения на месте →
`art_tuner_fold.py --dry-run` на копии. Без флагов: `-Bench` K1 Sarpedon против
`C:/tmp/envmaps-research/lightcheck/sarpedon/bench-K1-1920x1080.png` — средняя разница ≤ 0,5, `render_fingerprint.py`
`reference=true`. Evidence: `docs/game-design/evidence/ART-TUNER/art-tuner-<дата>/`. Вливание не нужно (работа уже в `fix/admin-panel`).

Статус результата будет «технически импортировано / измерено»; «художественно принято» — только твоё решение.
