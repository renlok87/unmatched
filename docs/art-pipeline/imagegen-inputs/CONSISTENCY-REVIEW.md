Срез: 2026-09-28. Задача T2 (P0.2) пайплайн-трека. Внешние генерации в этом проходе: **0** (ImageGen не вызывался, Tripo не вызывался, кредиты не расходовались).

Правка того же дня по ревью P0 (верификатор va): исправлено направление анизотропии Harpy, базовая линия y=917 отнесена только к видам персонажей и ортографическим видам пропсов, высота Harpy ≈44 uu помечена как ручная оценка. В `check_inputs.py` 1.1.0 добавлена проверка покрытия выбора (раздел «Итог автопроверок»).

Статусы в этом документе строго разделены:

- **предложено** — рекомендация или порог, не утверждённый владельцем;
- **измерено** — число, полученное скриптом или замером по PNG;
- **технически импортировано** — здесь не применяется: этот проход не создаёт и не импортирует меши;
- **художественно принято** — здесь не применяется: ни один комплект не принят художественно; четырёхвидовая приёмка пользователем из `PRODUCTION-NOTES.md` по-прежнему не выполнена.

### Повтор

```bash
# из корня репозитория; Python 3.13, Pillow 12.1, NumPy 2.4, SciPy 1.17
python tools/tripo-pipeline/check_inputs.py --compare-root C:/Users/ren/.codex/worktrees/art-foundation/unmached
# только проверка без записи файлов:
python tools/tripo-pipeline/check_inputs.py --check-only
```

Код возврата 1, если хотя бы одна проверка уровня FAIL сработала на **рекомендованном** виде, на комплекте или в покрытии выбора. Покрытие выбора: каждый вид из `generation-inputs.json` (`characters[].views`, `characters[].candidateViewsExcluded`, `props[].referenceViews`) обязан иметь запись нормализации того же ассета и роли и существующий файл. Раньше вид без записи нормализации молча выпадал из `manifest.json` без FAIL. Повторный запуск на тех же PNG даёт байтово тот же `manifest.json` и `checks-report.json` (в отчёте нет меток времени).

Числа по видам и комплектам не изменились по сравнению с версией 1.0.0; `manifest.json` байтово тот же (`2b928f42…`).
- SHA-256 всех 36 файлов совпадают с журналами нормализации, с `generation-inputs.json` и с рабочей копией арт-чата; SHA-256 исходников (`*-raw.png` и предыдущих версий) совпадают с записанными.
- Все файлы: PNG, RGB без альфы, 1024×1024, ≤ 20 MB (фактически 0,17–0,66 MB), рамка 16 px — однородный #808080, одна связная фигура, поле ≥ 10,3 % со всех сторон (минимум по 36 видам).
- Базовая линия (нижняя строка силуэта): у всех видов персонажей y=917; у ортографических видов пропсов (front/side/left/right/back бочки, фонаря и основания) y=917±1 (916 у `lantern left`). Виды `top` и `three-quarter` по базовой линии не нормализуются: barrel top 837, barrel three-quarter 916, table-base three-quarter 780.
- Ширина подставки у персонажей совпадает с целевой шириной нормализации в пределах 3 %; центр подставки x≈512.

Предупреждения:

| Где | Проверка | Значение | Что значит |
|---|---|---|---|
| Harpy v5 front (рекомендован) | `normalization-isotropic` | scaleXY 0,9975 / 0,9639, анизотропия \|sx/sy − 1\| = 3,5 % | Коррекция v3 **сжала** Harpy front по Y на 3,6 % (498 → 480 px) при X ≈ 1,0. Относительно ширины изображение сплющено по вертикали примерно на 3,5 %. Геометрию крыльев и тела это не выравнивает |
| Harpy v5 right (кандидат) | то же | 0,815 / 0,860, анизотропия 5,3 % | Обратное направление: по X сжато сильнее, чем по Y, поэтому вид относительно **вытянут** по вертикали (sy/sx ≈ 1,055). Вид не в рекомендованном наборе |
| Table base v3 front / side | `silhouette-edge-contrast-vs-background` | 18 % / 12,8 % пикселей внутренней кромки ближе 30 к #808080 | Серая скала на сером фоне: риск, что автоматическое удаление фона в Tripo съест часть кромки |
| Комплекты Barrel, Table base | `non-multiview-roles-present` | роли `top`, `three-quarter` | У multi-view Tripo нет таких слотов; эти виды — только человеческий референс |

Что автопроверки **не доказывают**. Одинаковые холст, базовая линия и ширина подставки получены нормализацией: скрипт выравнивал именно эти величины. Совпадение не доказывает, что виды описывают одну и ту же 3D-форму. Диагностика «IoU силуэта front против зеркального back» (например, Medusa 0,93, Arthur 0,91, Merlin 0,89, Harpy 0,94) — ориентир на перспективных изображениях. Низкое значение указывает на расхождение позы или реквизита, а высокое не подтверждает геометрию.

## Способ просмотра изображений

Изображения просмотрены **напрямую инструментом Read** (PNG рендерился как картинка в этой сессии). Для этого собраны временные контактные листы и увеличенные кропы в `C:/tmp/t2-sheets/` (вне репозитория): все текущие виды каждого комплекта рядом при 512², «front против зеркального back» для Medusa и Arthur, кропы ног Medusa (front / left / right v6), увеличение плафона фонаря (4 вида). Это просмотр 2D-референсов. Он не заменяет контрольные кадры из UE и осмотр меша. `zai analyze_image` не использовался, так как рендер Read сработал.

Соглашение о сторонах проверено по оружию и браслету. **Во всех четырёх комплектах персонажей `left` означает левый бок персонажа, обращённый к камере** (лицо смотрит влево по кадру). Примеры: у Medusa лук в левой руке ближе к камере в `left`; у Arthur меч в правой руке виден поверх груди, ближняя левая рука пустая; у Merlin посох в правой руке ближе к камере в `right`; у Harpy браслет на левой ноге виден в `left`. В пилоте Medusa `d562f057` эти же имена подавались в одноимённые слоты Tripo Studio; README пилота фиксирует сохранённый контур трёх видов и отсутствие второго лука. Для остальных персонажей соответствие слотам Tripo **не перепроверено**.
