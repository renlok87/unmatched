## 3. Классы (MatID) по зонам

Зоны строятся на 4K-растре атласа H2.1. Прежде чем что-то считать, `lookdev_state.build()` повторяет шаги `maps.py`
(растр UV, заполнение гаттеров, маски команды, позиции текселей, классы H2.1). Затем 8-битные карты, записанные из
этого состояния, сверяются с 4K-мастерами H2.1 на диске: **все пять совпадают попиксельно** (проверка
`h21_state_reproduced`). То есть классы лежат ровно на тех текселях, которые выпустил H2.1.

| Зона | Правило | Класс (индекс) | Доля покрытой площади 4K |
|---|---|---|---|
| wool — мантия, капюшон, рукава | части 0/3/4 минус классы ниже | `wool_coarse` (9); цвет команды — только по TeamAccent (§10) | 50.4 % |
| embroidery — золотая вышивка, звёзды, кайма | класс H2.1 embroidery (= TeamMaskRGBA.B) | `silk` (11), **без TeamColor** | 5.4 % |
| belt — пояс и свисающий конец | класс H2.1 leather_belt | `leather_worn` (8) | 0.76 % |
| buckle — пряжка | класс H2.1 metal_buckle (= ORM.B = 1) | `bronze` (6) | 0.07 % |
| boots — сапоги | части 5/11 | `leather_worn` (8) | 3.8 % |
| beard_wrap — кожаная обмотка бороды | часть 9, s ≥ 0.22 и z < 0.70 м (источник) | `leather_worn` (8) | 0.70 % |
| wood — посох и когти навершия | части 2/10 | `wood` (15) | 17.5 % |
| crystal — кристалл | часть 7 | `legacy_bake` (0) | 3.4 % |
| face_skin — лицо | часть 9, s ≥ 0.22 и z ≥ 0.70 м | `skin` (13) | 1.1 % |
| hands_skin — кисти | части 6/8 | `skin` (13) | 5.2 % |
| beard — борода, брови | часть 9, s < 0.22 | `legacy_bake` (0) | 5.0 % |
| base — подставка | часть 1 | `stone_base` (14) | 6.6 % |

Как разделена часть 9 (лицо и борода вместе). Замер BC H2.1: волосы — s p50 0.09 (серо-белые). Кожа — s ≥ 0.22,
тон 22°, V 0.62, выше z 0.70. Насыщенный коричневый ниже z 0.70 (тон 25°, s 0.48, V 0.35) — кожаная обмотка бороды
из концепта. Без правила по z она ушла бы в кожу лица.

**Вышивка — ткань, не металл и не цвет команды.** В LUT героя у `silk` переопределено `teamDyeAllowed = 0`. TeamMask
на текселях вышивки = 0 (проверка `team_mask_zero_on_embroidery_core`). Итог в LUT: `teamDyeAllowed = 1` только у
`wool_coarse` (проверка `lut_team_dye_only_wool`). Шероховатость нити — 0.42 [0.32, 0.58]: глаже шерсти, но не
гладкое «плато» шёлка. Sheen — полностью в цвет нити (tint 1.0, intensity 0.5), поэтому блик ткани золотой.

**Кристалл и борода — MatID 0 (`legacy_bake`).** В библиотеке v1 нет классов «самоцвет» и «волосы», а свободных
индексов нет (README §10). Оба берут запечённые BC/ORM:

- **кристалл**: ORM H2.1 — диэлектрик, roughness 0.12–0.18; BC насыщенно-синий, тон подогнан к концепту (§4);
- **борода**: ORM.G переназначена в матовый диапазон волос, `0.75 + 0.5·(r − 0.617)` с зажимом [0.68, 0.85]. p5/p50/p95
  было 0.49/0.62/0.81, стало 0.69/0.75/0.85. ORM.G изменена только на текселях бороды (проверка
  `orm_g_changed_only_on_beard`).

**MatID 2K, а не 1K.** README предлагает половину атласа. Замер: при 1K 7.5 % текселей вышивки уходят в шерсть, а
границы классов идут ступенями 2 × 2 по BC. 2K стоит 4 МБ G8 вместо 1 МБ. Класс берётся как argmax весов классов
после бокса 4K → 2K. Правило README «вес < 0.5 → MatID 0» **не применено**: на стыке трёх классов оно вставило бы
legacy-пиксели с roughness шерсти 0.96. Гаттеры получают класс ближайшего покрытого текселя.

Пряжка по MatID совпадает с металличностью ORM: 1 535 / 1 530 текселей 2K, расхождение 5.

## 4. Тон по концепту

Эталон — концепт `art/imagegen/hero-quality-v1/merlin/merlin-{front,side,back}.png`, а не прошлая итерация.

**Как мерили концепт.** По каждому виду и зоне взяты пиксели внутри прямоугольников профиля, прошедшие HSV-фильтр
материала: синий, золото, коричневый, кожа, белый, самоцвет, камень. Медиана считается в линейном свете. Наложения
для проверки: `preview/ld_concept_zones_{front,side,back}.png`.

**Как мерили модель.** Текстуры H2.1 отрендерены в том же студийном свете Blender и в кадрировании концепта (ортогональ
front/right/back). Зоны модели берутся из ID-прохода той же камеры: эмиссия карты зон, Closest, 1 сэмпл, Raw; эрозия
2 px. 100 % непрозрачных пикселей декодируются в зону.

**Коэффициенты.** Для каждой зоны `gain = chroma × luma`:

- `chroma` — отношение «концепт / модель» по каналам, нормированное так, чтобы сохранить яркость медианы зоны. Переносит
  тон и насыщенность концепта; зажим [0.6, 1.6].
- `luma` — отношение яркостей, делённое на экспозицию k = 1.103 (медиана по зонам: экспозиция концепта неизвестна);
  зажим [0.75, 1.35].

Зажим яркости нужен, потому что концепт несёт свой свет. Пример — одна и та же кожа: у лица отношение 0.84–1.18, у
кистей 1.71–1.78.

**Применение.** Коэффициенты применяются к BC в линейном свете на 4K по карте зон со сглаживанием 3 × 3. 2K — точный
бокс 2 × 2. Пряжку не трогали: это металл, её цвет задаёт F0 пресета.

## 5. LUT героя

`T_Merlin_H2LD_MatLUT.exr`, раскладка README §4: 16 столбцов (классы) × 8 строк. Собрана из
`um-material-presets-v1.json`, переопределений профиля (`lut_overrides`) и измерений героя.

- **Строка 0 (BC typical)** диэлектрических классов Merlin — медиана BC класса после подгонки по концепту. Например:
  wool (0.0148, 0.0217, 0.0737) — глубокий синий, Y 0.024, тон 229°; silk/вышивка (0.296, 0.159, 0.075); skin (0.391,
  0.215, 0.127); wood (0.071, 0.033, 0.016); stone (0.032, 0.027, 0.028). В режиме `bake-clamped` шейдер берёт цвет из
  BC-текстуры, поэтому строка 0 — справочная (превью и отладка). Сам тон концепта живёт в BC.
- **Металл (bronze)**: строка 0 = F0 пресета. `Ymed_class_hero` = 0.178 (медиана яркости запечённого BC пряжки)
  записана в **строку 7.R** столбца металла. README §4 называет Ymed данными LUT, но ячейки ему не даёт; у металла
  зажим яркости диэлектрика не используется, поэтому 7.R свободна. Это предложение, см. решения.
- **Плитки 512 px** (skin, silk): `tilesPerMeter` / 2 (15.5 и 12.5), потому что в срезе 1K массива они повторены 2 × 2.
- **Столбец 0** (`legacy_bake`) — нули: шейдер его не читает.

Проверки:

- EXR читается собственным парсером бит-в-бит;
- **декодер EXR Blender** даёт те же значения float16: `ld_render_after`, `lut_exr_blender_readback`, max |Δ| = 0;
- metallic ∈ {0, 1};
- Cloth только у шерсти и шёлка;
- TeamColor только у шерсти.

## 6. UV1 в метрах

Острова UV0 — рёберно-связные треугольники с одинаковыми UV0 по обе стороны ребра: тело 909, посох 223, подставка 31.
Каждый остров масштабируется на `sqrt(площадь 3D / площадь UV0)` в метрах финального кадра, так что 1 единица UV1 =
1 м объекта (= 100 uu). Отношение площадей UV1 / 3D по каждому острову = 1.000000. Внутри острова по треугольникам
p5–p95 0.61–1.39 у тела: это ABF-искажение самой развёртки, UV1 его наследует. Центр бокса острова переносится в
(0, 0). Зеркальных треугольников UV0 нет.

- **Без поворота (все классы, кроме дерева).** UV1 острова — подобие UV0 без поворота. Касательный базис UV1 совпадает с
  базисом UV0, поэтому нормаль детали можно смешивать в касательном пространстве нормали героя без лишней работы в
  шейдере. Ориентация нити шерсти по островам произвольна. На шаге 1.5 мм с игровой камеры это не видно (деталь уходит
  в мипы).
- **Дерево (113 островов посоха).** Острова дополнительно повёрнуты так, что главная 3D-ось острова (PCA) идёт вдоль +U —
  по волокну тайла `wood` (волокна тайла горизонтальны, проверено по `wood_DetailRMH.png`).
  **Следствие для UE:** у этих островов базис UV1 повёрнут относительно UV0. Нормаль детали дерева нужно либо переводить
  в базис UV1 (касательная по производным `ddx/ddy(UV1)`, подход surface gradient), либо принять повёрнутый рельеф

  крупных плана (1485 / 7840 / 8688 px);

Материалы: H2LD Neutral / Blue / Red. Для H2 (v1): временный MID от `MI_Merlin_H2` с TeamDye 0 и TeamColor
белым (без красителя) и его Blue.

**Две экспозиции.** Neutral H2LD и H2 снимаются в измеряемых ракурсах второй раз при `r.ExposureOffset −1.5`, у этой
экспозиции свой k. LUT, подогнанный на плече тоновой кривой одной экспозиции, так случайно пройти не может: это и
произошло на r3. Зона проходит, только если она в допуске на обеих (`tolerance_both_exposures` в метриках).

**Усреднение.** Измеряемый кадр — среднее трёх последних захватов в линейном свете. Мелкий металл шумит от кадра к
кадру (отражения Lumen, TSR): тот же кадр torso на r3 давал пряжке 1.10, а на пробе p3 — 0.65.

**Маска зон.** MI `MI_Merlin_H2LD_DebugZones`: в слоте MatID лежит ZoneID, в слоте LUT — ZoneLUT, DebugView 7,
DebugBakeFromLUT 1. Каждая из 12 зон look-dev получает плоский насыщенный цвет. Эти цвета выбраны жадным max-min в
sRGB: минимум 40 уровней между любыми двумя.

- Эталонный цвет каждой зоны берётся из калибровочного кадра: `DebugMatIDOverride = id`, вся фигура одним цветом.
- Фигура отделяется от фона разностью с кадром-«плитой», где фигура скрыта.
- Пиксель относится к ближайшему эталону, если расстояние ≤ 38 уровней. Маска каждой зоны эродируется на 2 px.
- Маски одинаковы для H2 и H2LD: геометрия, UV0 и поза совпадают.

**Метрика** — метод LDM-6 Blender-стадии:

- медиана зоны в линейном свете, тон и насыщенность медианы в sRGB HSV;
- концепт мерится прямоугольниками и HSV-фильтрами профиля look-dev (`lookdev.concept_zones`);
- **пряжка — только рамка** (`ue_measure` в `merlin-h2-lookdev-ue-lut.json`). Три узких прямоугольника на верхней,
  левой и нижней планках: [566, 535, 599, 540], [565, 538, 572, 568], [566, 564, 589, 570]; тон 5–50°, s ≥ 0.12,
  v ≥ 0.2 (тёмные контуры отброшены). Итог: 299 px, Y 0.0666, тон 24.0°, s 0.435. Прямоугольник r1–r3
  [567, 537, 592, 568] с v ≥ 0.3 захватывал кожу ремня внутри рамки: Y 0.0798, s 0.391;
- экспозиция концепта неизвестна, поэтому яркость UE умножается на **k** = медиану отношения «концепт / UE» по
  зонам и ракурсам front/side/back/torso (без подставки). k своя у каждой экспозиции;

  кистей. Остальные зоны — справочно.

## U6. Что не попало и почему (с числами)

- **Контраст тоновой кривой против концепта — главный остаток, и материалом он не снимается.** На одном и том же
  ассете:
  - при EV100 1.3 (фигура примерно в 3 раза ярче концепта, k 0.34) светлые зоны сидят на плече кривой: вышивка 0.83,
    лицо 0.76, кисти 0.71, насыщенность −0.11…−0.20, тон вышивки +6.8°;
  - при −1.5 EV (k 1.26) тёмная шерсть уходит в «носок»: 0.76, насыщенность +0.13; кисти 1.29.
  - Концепт мягче по контрасту, чем кривая UE на обеих экспозициях. Отношение «светлая зона / шерсть» у UE растёт при
    снижении экспозиции.
  - Яркость вышивки и кожи зависит от доступных ручек монотонно: sheen шёлка, полоса яркости класса. Поэтому значения,
    которое держит обе экспозиции, нет. У H2 та же картина: при EV100 1.3 вышивка −0.21 и кожа −0.20…−0.21.
- **Материал в этом остатке тоже есть, и часть уже исправлена:**
  - блеск Cloth шёлка давал до +70 % яркости вышивки (UE-3: sheen 0.5 → 0.09);
  - белый specular шёлка обесцвечивал золото (0.35 → 0.2).
  - Остаток вышивки при EV100 1.3 — яркость 0.83 и насыщенность −0.14. Тон +6.8° против +2.1° у H2 — регресс по тону:
    H2LD светлее, поэтому глубже в плече кривой.
- **Кожа.** Альбедо — концептный бейк Blender-стадии: в LUT v2 для диэлектрика есть только полоса яркости, множителя
  нет. Поднять кожу при EV100 1.3 (0.71–0.76) значит ещё сильнее поднять кисти при −1.5 EV (уже 1.29). Красный тон
  полостей 0.55 немного поднял насыщенность: лицо −0.126 → −0.113. Лицо и кисти расходятся между собой: при −1.5 EV
  0.95 против 1.29. Кисти в концепте высветлены (Blender-стадия: отношение лица 0.84–1.18, кистей 1.71–1.78).
  Разделить их можно только отдельным классом или правкой бейка.
- **Что с этим делать** — вопрос экспозиции и тоновой кривой фигур на доске (5b-R) **и** решения, какой кадр
  эталонный. Остаток передаётся 5b-R **не как чисто световой**. Правки материала, которые его уменьшали, сделаны. То,
  что осталось, — несовпадение контраста кривой и концепта; его нельзя закрыть одним значением LUT (LDMU-6).
- **Пряжка** проходит в медиане трёх ракурсов на обеих экспозициях. По отдельным ракурсам: torso 0.75 и под 35° 1.33
  вне допуска по яркости, в лоб 1.04 в допуске. У H2 разброс тот же.
- **Кристалл (1.85)** — legacy-класс без самоцветного шейдера (LDM-3), его высветляют отражения купола. Класс
  «самоцвет» — вопрос v1.1.
- **Сапоги (1.24, −0.17)** — зажим яркости Blender-стадии плюс общий `leather_worn` с поясом.
- **Шерсть сбоку** — 1.28 при EV100 1.3: складки на боку ловят купол.
