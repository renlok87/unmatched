### Масштаб, pivot, оси

- **Высота** от низа подставки до верха хохолка — **42,0 uu**, верхняя граница предложенных 35–42 uu (04 §3.2). Масштаб фигуры ×0,65698 вокруг верха исходной подставки. Фигура стоит на верху новой подставки, когти уходят в неё на 4,9 мм, как и в исходнике.

Для 76 % граней голос единогласный. После голоса оценка головы +0,975, но несогласованных рёбер 274: тонкие перья хохолка дают неоднозначный ближайший треугольник.

- **Заглушки (fan fill)** на открытых петлях сегментации:

### Материал, текстуры, TeamColor, три экземпляра

- **Атлас 2048²**: 8 частей в родном размере, крылья и голова по 1024. Зазор 8 px, ячейки покрывают 96,9 % атласа. Карты:
  - `BC` — sRGB, `baseColorFactor` 0,8 умножен;
  - `N` — DirectX для UE (`flip_green = false`), плюс `N_OpenGL` для Blender;
  - `ORM` — linear, R = 255 (у Tripo нет AO), G = roughness, B = metallic.

  Плотность текселей 15,5–26,8 px/см. У частей 3/7/8 плотность занижена площадью заглушек, у которых нет UV. Растровое перекрытие UV ≤ 1 %.

- **TeamColor** (03 С-11: «только на подставках/кольцах/маркерах») — боковая полоса подставки, канал `UM_Mask.R`. Маску для фигуры не делал. Цвета С-11 в профиле записаны как linear: золото (0,807; 0,527; 0,144), серебро (0,347; 0,539; 0,686). В профилях Merlin/Arthur под видом «linear» стоят sRGB-значения hex/255.

  - **1** — •;
  - **2** — • • (с разрывом посередине);

Первый сохранённый `logs/build.log` (сборка `92a8632d…`) заканчивался 25 строками `Windows fatal exception: access violation` / `<no Python frame>`. Сборка тут ни при чём, и это **измерено** [`probe_blender_exit_faulthandler.py`](../../art/pipeline-candidates/ASSET-HARPY-001/scripts/probe_blender_exit_faulthandler.py) → `reports/blender-exit-faulthandler-probe.json`. Проба — 8 + 8 запусков `blender -b --factory-startup` (5.2.2) со скриптом, который ничего не делает:

| faulthandler | Запусков с сообщениями | Сообщений за запуск | Код выхода | Где |
|---|---:|---:|---|---|
| вкл | 5 из 8 | 0–27 | 0 | главный поток; после конца скрипта, до `atexit` Python |
| выкл | 0 из 8 | 0 | 0 | — |

На Windows faulthandler ставит векторный обработчик исключений. Поэтому он печатает и исключения первого шанса (first-chance), которые процесс потом обрабатывает сам: Blender после них доходит до `atexit` и выходит с кодом 0. Выход Blender такие исключения даёт и без нашего кода, их число меняется от запуска к запуску.

Исправление:

- faulthandler в сборке по умолчанию выключен;
- включается только для диагностики: `run_harpy_build.py --faulthandler` или `HARPY_BUILD_FAULTHANDLER=1`. Такой прогон пишет `logs/build-faulthandler.log`, а не лог стадии;
- если строка `Windows fatal exception` появится в `build.log` при выключенном faulthandler, `run_harpy_build.py` считает сборку упавшей.

`logs/build.log` пересоздан: сообщений нет, 44 из 44 проверок, те же FBX.
