## Код-пробелы (не исправлялись: объём D2b — документы)

1. **Workflow-приёмщик со строгой выходной схемой не записан в репозитории.** Схемы `asset-acceptance-2.output-{model,concept,anim}.schema.json`
   есть (`_output_schema.py`), A&B §8.3 теперь передаёт их в `agent()`. Но скрипта Workflow в `tools/art/acceptance/` нет
   (F102 ссылается на `model-second-acceptor`, его в репозитории нет), и живой вызов `agent()` с выходной схемой не
   подтверждён записью. Поэтому очистка строк `"null"` (`finish_second.py`) оставлена страховкой, а не удалена.
2. **Замера зазора «наездника» нет** ни в rest (F137), ни в клипе (F133): `clip_contact_check.py` и h2_bake такой
   проверки не имеют. HB §4.4 п.4 велит мерить разовым скриптом.
3. **Съёмка приёмки не снимает** позу «рука вперёд» со спины (F129), второй ракурс `pose-04` (F77), крупный план атакующей
   кисти при `WEAPON_HAND: none` (F74).
4. **Схема карточки не хранит исполнителя** (механизм, effort, RA-21): только `executor_session_id`. Факт пишется в
   `STAGE5[]` заявки (SKILL §7.2, D2a). Поле в схеме — отдельное решение (схема `additionalProperties: false`).

## Решения D2b по делегированию (для ревью)

- Повторная приёмка (RC-19): изменённые кадры получает только второй приёмщик (как в строке W2-d), баллы — по всем
  кадрам.
- HB §0.3 п.7: опция инструмента со старым дефолтом, закрывающая FAIL без смены нормы (`cloth_shell`, `part_offsets_m`,
  `base.flatten_bottom`), — класс «разбор оркестратором» с файлом решения; мост-цилиндр, новая кость или класс — вопрос
  пользователю (согласовано с SKILL §5 пп.5–6).
- Очистка (RC-03): сразу удаляются только каталог повтора и свои scratch-каталоги (`-stage3-check`, `-scout`,
  `work/smoke`); `work/` прогонов не удаляется до решения пользователя — его читает `--reuse-from`.
- Чек-лист «Сдача модели»: полный повтор детерминизма — не на сдаче r1, а один раз на прогоне для UE (после pass, до
  7a), как в SKILL этап 3 п.4 (D2a).
