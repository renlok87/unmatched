## Главное

- Знание пилота осело в NOTES, промптах и одноразовых скриптах, а не в скилле. Справочники этапов 4–7 после пилота не
  менялись: около 63 правок не перенесены (RA-06), исправления инструментов не описаны в документах (RA-05).
- Порядок этапов 6 и 7a замкнут по кругу: приёмке клипов нужен импорт в UE, а импорт требует принятых клипов (RA-01).
- Гейт «стоп до ответа пользователя» срабатывает на каждом FAIL инструмента и противоречит делегированию (RA-02).
- Шаблон приёмщика Sol даёт оценку по кракозябрам: рабочий блок OEM вписывали руками (RA-03).
- Тесты красные на HEAD, потому что читают живые данные (RB-03); полноту регистрации героя не проверяет никто (RB-04).
- Половина агентского времени Leshen и Achilles ушла на доработки: дефекты модели находила только приёмка клипов
  (RC-06), доработка «только веса» гнала всю цепочку заново (RC-07/RC-08).

## Очередь доработки (решения — по делегированию 2026-10-06)

**Волна 1 · инструменты без UE (параллельно, непересекающиеся файлы)**
- W1-a · инфраструктура: `ledger.py` — `until: null` = окно открыто, тесты на синтетике (RB-01, RB-03); UTF-8 во всех
  точках входа (RB-11, F47); `ue_lock` heartbeat (RB-21).
- W1-b · анимация и регистрация: `de010/de011 --only <Key>`, мастер не сохранять при той же `graph_signature` (RB-02,
  F157); `clip_review_sheet` — обязательные `--heroes/--cards`, отказ писать лист без кадров, пропуск только по штампу
  сборки, карта фикстур на героя, `--k1-from` (RB-12, F159, RC-09), тесты на фикстурах (RB-03); `clip_manifest check` —
  4 записи на героя (RB-07), переопределение спеки (F103).
- W1-c · приёмка: `_tone.py` — оттенок только для хроматических медиан + CLI (RB-06, RB-19); `validate_card` — всегда
  читать `tone.json`/`frames.json` (RB-16), пересчёт G-TOPO/G-RIG/G-UV/G-TEX/G-NAMES из отчётов (RB-05).
- W1-d · Blender: `st_lookdev` пишет FBX через staging (RB-13); вердикт детерминизма с допусками (RB-14); обязательные
  ключи профиля нового героя (RB-15); `run_h2_bake --reuse-from` (RC-07, RC-08); пробы рига — правая рука, голени,
  стопы, кисть оружия, кость оружия, нормировка по телу (RB-08, F59); `clip_contact_check` — доп. части оружия, стопа
  без вершин не PASS (RB-09, F113, F127).

**Волна 2 · перенос клея в tools и UE-инструменты**
- `tools/art/registration_check.py` (RB-04); проверка ракурса в `check_concept_views` (F8), `grip_check`, скрипты
  задач 7a, раннеры пачки и Codex-полос — в `tools/` с тестами (RA-12, RB-18, RC-15); раннер полосы завершает задание
  по файлу `-o` и гасит своё дерево (RC-11).
- `h2anim_ue`: обновление меша превью (F145), дефолт `--base` (F96), камера (F136); `ue_hero_lookdev apply-mi` (RC-10).
- Очередь пилота: маска кольца команды по высоте для двухъярусной подставки (F143, F150), плоский низ и кромка
  подставки (F83, F104), перекраска полосы контакта (F107), металл F0 из концепта (F138), прогрев и шумовая полоса
  UE-кадров (F153, F155), повторная приёмка по изменённым кадрам (F151, RC-19), пара кадров шва Idle (F154), выдержка
  ключей G-NAMES для приёмщика (F152).

**Волна 3 · документы скилла (после волн 1–2, по группам файлов)**
- Порядок 6/7a (RA-01), два класса стопа (RA-02), блок OEM для Sol в шаблонах (RA-03), строки новых опций
  инструментов (RA-05), перенос F этапов 4–7 с отметкой Applied/отклонено (RA-06), рецепт агентского редактора и
  один 7a за раз (RA-07, RC-05), маршрут «клип вскрыл дефект модели» и счётчик позднего фикса (RA-08, RC-06), единый
  чек-лист сдачи модели (RA-09), плейсхолдеры шаблона приёмщика и выходная схема Workflow (RA-10, RA-11), правила
  коммита — JPEG, бенч в `$W` (RA-13), полная команда замера (RA-14, F160), базовая линия реестра до de010 (RA-15),
  `um_masters` (RA-16), неоднозначности (RA-17), паттерн библиотеки как источник движения по умолчанию (RA-18,
  RC-02), раздел «Пакетный режим» с таблицей ресурсов (RA-20, RC-15), мелочи RA-22…RA-27, очистка диска (RC-03),
  бюджет Codex (RC-12), `index.lock` (RC-21), кадры приёмки 1200 px (RC-22), GPU-токен (RC-23), 4–5 полос (RC-24).
- Один агент ревью на документы и код вместе, затем коммит.
