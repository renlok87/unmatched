## 3. Хвост упаковки (ДС-3e)

Ночь 2026-10-20/21: UAT `AutomationTool exiting … Success` в 23:17:13 и 01:54:38 (весь UAT 3 мин 10 с и 3 мин 32 с:
сборка 117–137 с через XGE standalone, кук 30 с, stage), `BuildStamp.json` `builtAt` 02:08:25 — 13 мин 47 с после выхода
UAT. Причина — `Start-Process -Wait` (PowerShell 5.1 ждёт и потомков). Синтетика: пакетный файл оставляет потомка на
25 с — прежний способ вернулся через 26,5 с, новый (`WaitForExit` по дескриптору) через 0,1 с и назвал выжившего
потомка строкой `UAT_SURVIVORS`. Реальной упаковкой не проверено: следующая упаковка волны A покажет `UAT_SECONDS` и
`UAT_SURVIVORS`.

## 4. Сборка C++ и Live Coding

- Инкрементальная сборка `UnmatchedEditor` после правки самого большого файла проекта (`S08FlowGameMode.cpp`):
  30,5 с (UBA, 4 действия). В пилоте — 16–24 с. Игровой target после touch `Unmatched.Build.cs` — 264,5 с (пилот),
  один раз на упаковку окна 7b.
- Live Coding компилирует тот же файл столько же; экономит перезапуск (≈ 10–20 с), а не сборку. Регистрации героя он не
  подходит (статическая таблица `Specs()`, упакованный `-Bench`, мьютекс Live Coding во всех checkout) — подробно в
  решении, раздел «Сборка C++ и Live Coding».

## 6. Открыто

- Пиковый рабочий набор слота с героем (импорт, look-dev, кадры клипов) — первый прогон волны со слотами пишет его
  сюда; третий слот — если сумма с Blender волны меньше ≈ 48 ГБ.
- Blender: `-t N` (`H2_BAKE_THREADS`) и до 4 прогонов — после волны A и по замеру (`run_h2_bake.py` в отпечатке кода
  `reuse.py`, правка посреди волны заставила бы пересчёт).
- Таблица героев в JSON (`Config/Heroes/S08HeroesV2.json`) — регистрация героя без C++ и `-SkipBuild`-упаковка.
- Tripo API вместо кликов Studio — ключ, кредиты и решение пользователя (решение, раздел «Tripo API»).
- Одна фикстура на волну (все новые герои на одной сцене) — один K1 на доску вместо одного на героя
  (`env_bench_fixtures.cts` пока ставит одного нового бойца на вариант).
