# QA-010: инструменты доказательств (этап 3, T1.3)

Статус: **инструменты и предложенные пороги**. Ничего здесь не является приёмкой QA-010, K1–K3 или GD-058. Приёмку QA-010 выносят проверяющий и независимый зритель ([10](../../game-design/10-acceptance-tests.md), стр. 129), GD-058 — автор. Агент в роли зрителя помечается как суррогат (критика этапа 3, E5).

Код: `tools/art/qa010/qa010.py` (CLI), библиотека `tools/art/qa010/qa010lib/`, тесты `tools/art/qa010/tests/`, фикстура новой трассы `tools/art/qa010/fixtures/`, предложенные пороги `tools/art/qa010/thresholds.proposed.json`, пример на реальных кадрах `tools/art/qa010/examples/2026-09-28-real-frames/`.

## Запуск

Требования: Python ≥ 3.10 (проверено на 3.13.4); для команд с изображениями — numpy (проверено 2.4.0) и Pillow (12.1.0). Команды `plate`, `project`, `checklist` и парсер трасс работают на stdlib без numpy/Pillow.

```bash
python tools/art/qa010/qa010.py derive  FRAME_OR_DIR... --out DIR [--json MANIFEST]
python tools/art/qa010/qa010.py luma    FRAME... [--region NAME=KIND:ARGS]... [--trace T [--shot S]] [--stride N]
python tools/art/qa010/qa010.py c9      FRAME --game SPEC... --decor SPEC... [--exclude SPEC]... [--trace T] [--accept-proxy]
python tools/art/qa010/qa010.py plate   --trace T [--shot S] [--frame PNG] [--plate-bbox x0,y0,x1,y1] [--reachable "x,y;x,y"] [--cells reachable|all] [--overlay OUT.png]
python tools/art/qa010/qa010.py icon    FRAME (--bbox x0,y0,x1,y1 | --trace T [--shot S]) [--mask PNG] [--sizes 24,32,48]
python tools/art/qa010/qa010.py project --trace T [--shot S | --all] [--frame PNG]
python tools/art/qa010/qa010.py checklist --config CFG.json --out-md X.md --out-json X.json
```

Общие флаги: `--thresholds FILE` (по умолчанию `thresholds.proposed.json`), `--json OUT` у каждой команды (JSON печатается и в stdout, UTF-8). Входные кадры и трассы только читаются; выходы пишутся только по указанным путям.

Коды выхода: `0` — измерено, pass (или команда без вердикта); `1` — измерено, fail; `2` — ошибка аргументов или входа; `3` — недостаточно данных, в том числе **«требуется новая трасса»**, `plate` без проверенных клеток или без видимой плашки и `c9` на маске-прокси (без `--accept-proxy`).

Тесты (112, синтетические изображения с известными ответами, негативные случаи, плюс две проверки на реальных данных, которые пропускаются без дерева evidence):

```bash
cd tools/art/qa010 && python -m unittest
# или из корня репозитория
python -m unittest discover -s tools/art/qa010 -t tools/art/qa010
```

### Трактовка С-9 (записана явно)

Самый свежий документ — [17](../../game-design/17-art-production-spec.md) (сводка 2026-09-25, обновления 2026-09-27). Он разделяет С-9 так: условие «ярче» — НОРМАТИВ (через QA-010), диапазон +0,3..+0,7 EV — ПРЕДЛОЖЕНИЕ из 03 (AD-AC-33). Метод — «средний luma по маскам слоёв» из отдельного прохода custom stencil (§11.10). [03](../../game-design/03-art-direction.md) С-9 (v0.1 от 2026-09-18) добавляет «и насыщеннее» и «декор в холодных приглушённых тонах».

Реализация:

- EV — логарифм отношения экспозиций, поэтому разница считается в линейном свете: `ΔEV = log2(mean Y_game / mean Y_decor)`. Y — относительная яркость, Rec.709-коэффициенты на линейном RGB после точного декодирования sRGB. Слово «luma» в §11.10 прочитано как «мера яркости»; Y′ на гамма-значениях для EV не годится. Статистику можно переключить на медиану (`--statistic median`); в выводе всегда есть обе ΔEV.
- Вердикты: `brighter` (ΔEV > 0; НОРМАТИВ) → `result_normative`; `ev_range` (0,3 ≤ ΔEV ≤ 0,7) и `more_saturated` (средняя C\*ab игрового слоя больше, чем у декора; метрику выбрал инструмент) → `result_proposed`; `decor_cool` (средняя b\* декора < 0) — только информативно.
- Маски — вход: `mask:` из stencil-прохода (когда он появится), `bbox:`/`poly:` (ручная маска) или маски из трассы. `trace-cells:all` (объединение спроецированных клеток, слой L2 «игровая плоскость» по 03 §4.1) — хорошее приближение игрового слоя. HUD исключается через `--exclude`. Перекрытие масок игрового слоя и декора — ошибка (или `--allow-overlap`). Порог числа пикселей слоя — 2000 (предложено).
- **Прокси-маски не дают нормативного результата.** С-9 сравнивает игровой слой с декором L3 (фасады, фонарь, ящики; 03 §4.1). Прокси по построению (правила в `qa010lib/layers.py`, решает вид региона, а не его имя): для декора — `trace-ring` (кольцо вокруг доски = поднос или рамка, слой L4 «фон»), `trace-cells` (клетки = L2) и `frame`; для игрового слоя — `trace-ring` и `frame`. Если хоть один регион — прокси, `c9` всё равно считает числа, но пишет `result_normative: "proxy"` и `result_proposed: "proxy"`; вердикты, которые получились бы, лежат в `result_on_proxy`, а причина и список регионов — в `layer_basis`. Код выхода 3. Флаг `--accept-proxy` меняет только код выхода (0/1 по замеру на прокси), JSON остаётся ненормативным (`proxy_accepted_by_flag: true`). `mask:`/`bbox:`/`poly:` инструмент прокси не считает: принадлежность такой маски слою L3 утверждает вызывающий, и это записано в `layer_basis.note`.

## Форматы

### Производные (`derive`)

- Серый: `Y′ = 0.2126 R′ + 0.7152 G′ + 0.0722 B′` на 8-битных sRGB-значениях. Округление половины вверх, Y′ копируется в три канала. Нейтральные цвета сохраняются точно (тест на всех 256 уровнях).
- Deuteranopia: Machado, Oliveira, Fernandes 2009, severity 1.0. Цепочка: `M = [[0.367322, 0.860646, −0.227968], [0.280085, 0.672501, 0.047413], [−0.011820, 0.042940, 0.968881]]`, декодирование sRGB → линейный RGB по IEC 61966-2-1 (порог 0,04045) → `M` → обрезка в [0, 1] → кодирование sRGB → округление половины вверх. Контрольные значения: красный (255, 0, 0) → (163, 144, 0) (в гамма-пространстве вышло бы (94, 71, 0)); зоны С-7 red #D9483F → (149, 134, 58) и green #3FA65C → (154, 143, 97) почти сливаются.
- Альфа-канал отбрасывается без композитинга: у UE-скриншотов альфа бывает 0 на непрозрачных пикселях.
- Выход: `OUT/<путь>.gray.png` и `OUT/<путь>.deuteranopia.png` плюс манифест `qa010-derive-manifest.json` с SHA-256 входов и выходов и описанием метода. Каталоги обходятся рекурсивно с сохранением относительных путей; уже производные файлы пропускаются. Одинаковые имена из разных прогонов (`phase2-board-host-1920x1080.png` есть в каждом прогоне) получают префикс из родительских каталогов. Повторный прогон даёт побайтно те же PNG.

### Регионы (`--region`, `--game`, `--decor`, `--exclude`)

`NAME=bbox:x0,y0,x1,y1` (пиксели, полуоткрытый интервал) · `NAME=poly:x,y;x,y;x,y` · `NAME=mask:PATH.png` (размер как у кадра; альфа ≥ 128, если у PNG есть неполная альфа, иначе серый ≥ 128) · `NAME=trace-cells:all` или `trace-cells:x,y;x,y` · `NAME=trace-ring:IN,OUT` (в клетках от края доски) · `NAME=frame`. Регионы из трассы масштабируются, если PNG отличается от viewport трассы.

### Luma (`luma`)

Для кадра и каждого региона: `luma_mean`, `luma_p50`, `luma_p90`, `luma_min/max`, `dark_under_30_pct`, `bright_over_150_pct`, `rel_luminance_mean`. Перцентиль — `sorted[floor(n·q)]`, как в `s05_frame_measure.ps1`. `--stride 4` воспроизводит опубликованные числа S05 (K1: mean 101,9, p50 61,0, p90 204,1). Это регрессионный тест на реальных кадрах.

### Трассы: существующие поля

Используются реальные строки `FS08Trace` из `unreal/Unmatched/Source/Unmatched/S08/S08FlowGameMode.cpp`:

- `BOARD WxH cells | control points: (0,0)=(x,y,z) (W-1,H-1)=(x,y,z) | neighbor pair (dist D uu)` — `SyncBoardFromApplied`, геометрия INT-019 (`CellToWorld`, клетка 100 uu, центр доски в начале координат);
- `SHOT ctx viewport=WxH viewTarget=… cam=(x,y,z) rot=(pitch,yaw,roll)` — `TakeEvidenceShot`, камера в момент кадра;
- `SHOT fighter ID pos=(cx,cy) world=(x,y,z) screen=(sx,sy) projected=0|1 alive=0|1` — собственная проекция клиента (`ProjectWorldLocationToScreen`);
- `SHOT requested: … -> PATH` — закрывает блок и связывает его с именем PNG (`--shot` по имени или `#N`; без `--shot` берётся блок с именем кадра);
- `ARTPREVIEW selection … reachable=N fighterId=…` и `ARTPREVIEW camera focus requested zoom=Z …` — информативно. В `project` зум из флага выводится как `zoom_source` (E4: такой кадр помечается «тестовый флаг»).

Модель камеры: FRotationMatrix UE, **горизонтальный** FOV 35° (`SetupCameraForBoard`), экранная система с началом в левом верхнем углу. Каждый кадр сверяется с парами `SHOT fighter`. На 669 блоках трасс evidence остаток не больше 1,34 px с камерой из трассы. На K2 5× трасса печатает камеру с округлением до 1 uu, поэтому остаток 3,45 px. Режим `auto` в этом случае подгоняет только позицию камеры (метод Гаусса–Ньютона) и доводит остаток до ≤ 0,62 px. Кадр с остатком больше допуска (предложено 2 px) или с `cam=(0,0,0) rot=(0,0,0)` (так бывает в реальных трассах, например у `s09-combat-defense-open.png`) геометрически не оценивается: статус `insufficient_input`.

### Новая трасса (требуется) — плашка, достижимые клетки, иконка

В существующих трассах **нет** ни bbox плашки или иконки, ни списка достижимых клеток: есть только счётчик `reachable=14`. Поэтому `plate` и `icon --trace` на текущих кадрах возвращают `requires_new_trace` (код 3). Минимальный формат: три строки внутри блока SHOT, между `SHOT ctx` и `SHOT requested`, в пикселях viewport, в той же системе, что и `SHOT fighter … screen=`:

```text
SHOT reachable fighter=<fighterId> n=<N> cells=(x,y)(x,y)...
SHOT plate fighter=<fighterId> bbox=(x0,y0,x1,y1) [overlapReachable=<N>]
SHOT icon fighter=<fighterId> bbox=(x0,y0,x1,y1)
```

Предложение для клиента (T2.2): в `AS08FlowGameMode::TakeEvidenceShot` после цикла `SHOT fighter`:

```cpp
FS08Trace::Write(FString::Printf(TEXT("SHOT reachable fighter=%s n=%d cells=%s"), *FighterId, Cells.Num(), *CellsText)); // CellsText = "(x,y)(x,y)..."
FS08Trace::Write(FString::Printf(TEXT("SHOT plate fighter=%s bbox=(%.0f,%.0f,%.0f,%.0f) overlapReachable=%d"), *FighterId, X0, Y0, X1, Y1, N));
FS08Trace::Write(FString::Printf(TEXT("SHOT icon fighter=%s bbox=(%.0f,%.0f,%.0f,%.0f)"), *TargetId, X0, Y0, X1, Y1));
```

Требования к полям. `n` должно совпадать с числом пар, иначе трасса отвергается. bbox задаётся в пикселях viewport, а не в единицах Slate: для UMG переводить геометрию через `USlateBlueprintLibrary::LocalToViewport`, иначе DPI-масштаб исказит координаты. Для world-space подписи и иконки брать проекцию углов компонента. `overlapReachable` необязателен; если он есть, `plate` сверяет его со своим подсчётом, и расхождение даёт fail. Отдельные строки `PLATE …`/`REACHABLE …` вне блока тоже принимаются как последнее состояние (`source: standalone-latest`). Фикстура `tools/art/qa010/fixtures/new-trace-k2-plate.trace.txt` состоит из реальных строк ctx/fighter из K2 1,6× и синтетических новых строк. Она покрывает случаи «чисто», «перекрытие», «расхождение с клиентом», «строк нет», «камера не инициализирована» и четыре случая «ничего не проверено» (ниже). Расширение `.txt` выбрано потому, что `*.log` в `.gitignore`.

**Ничего не проверено — не pass.** `plate` возвращает `insufficient_input` (код 3), а не pass, если: список достижимых клеток пуст (`n=0 cells=`); площадь bbox плашки нулевая; плашка целиком за пределами viewport (видимая площадь 0); все проверяемые клетки за экраном. Все найденные причины перечисляются в `reason`. **Нулевая геометрия виджета — ошибка трассы, а не pass.** У свёрнутого или ещё не размеченного UMG-виджета `LocalToViewport` даёт `bbox=(0,0,0,0)`; клиент тогда тоже напишет `overlapReachable=0`, и перекрёстная сверка совпадёт, поэтому такой случай ловит только эта проверка. Клиенту (T2.2) стоит писать строку `SHOT plate` после того, как виджет хотя бы раз отрисован (у `GetCachedGeometry()` ненулевой `GetLocalSize()`), а нулевую геометрию писать как есть, не пропуская строку: инструмент пометит её как ошибку трассы. Если часть клеток выбора или часть плашки за экраном, замер делается по видимой части, а в `issues` записываются непроверенные клетки и видимая площадь плашки.

Без новой трассы можно передать `--plate-bbox` и `--reachable` вручную, или взять `--cells all` (строже нормы: проверяются все клетки). Источник всегда записывается в вывод.

### Иконка (`icon`)

bbox иконки задаётся в пикселях кадра (полуоткрытый интервал). Кольцо фона — 25 % от стороны bbox, не меньше 2 px. Маска иконки задаётся через `--mask` (по размеру кадра или bbox). Без маски используется авто-режим: порог Оцу по Y′ внутри bbox, иконкой считается класс, чьё среднее дальше от медианы кольца (эвристика). Для каждого размера S из 24/32/48 кроп масштабируется в линейном свете box-фильтром так, чтобы длинная сторона bbox стала S px. Затем пиксели делятся по покрытию маски: ≥ 0,75 — иконка, ≤ 0,25 — фон, промежуточные исключаются. По медианам считаются WCAG-контраст и `luma_delta` (Y′ иконки минус Y′ фона; знак показывает полярность). Дополнительно выводятся контраст против кольца и контраст после deuteranopia. Проверка не проходит, если при данном S не осталось ни одного пикселя иконки (тонкие штрихи «схлопнулись»), если её доля меньше 2 % или если контраст ниже 3:1. `upscaled: true` означает, что иконка в кадре меньше S; такой замер не репрезентативен.

### Чек-лист (`checklist`)

Конфиг задаётся в JSON: `frames.K1..K3.path` (и `provenance` из `classify_evidence`, T0; без него берётся подсказка по пути, и строка `ALL.provenance` помечает кадр как «не годится для приёмки»); `results[]` — пары `{k, path}` с JSON команд; `manual{id: {status: да|нет, note}}`; `viewer{kind: human|agent, note}`; `elements[]` — `{frame, id, status: есть|отложено, reason, norm}`. Выход — markdown и JSON: 17 признаков K-1..K-3 с источником и статусом нормы, таблица из 16 элементов кадра (фасад, фонарь, поднос и тьма, туман, виньетка, пиктограммы зон, HUD, счётчик теней = 1, 6 фигурок; фасад при зуме, плашка, подставка; позы, инспектор 2D, прицел и иконка, урон и итог) и сводка. Статусы: «измерено: pass/fail (порог …)», «нет данных: требуется новая трасса», «нет данных: результат по другому кадру», «нет данных: декор — прокси (нужна stencil- или ручная маска L3)», «открыто (ручная проверка)», «ручная: да/нет», «суррогат (агент)». Статус «принято» генератор не выставляет никогда (тест `test_never_declares_acceptance`). Пример конфига: `tools/art/qa010/examples/2026-09-28-real-frames/checklist-config.json`.

Привязка к кадрам. Метка `k` в `results[]` только выбирает строку; значение попадает в строку, только если результат снят на кадре `frames.K*.path` этой строки. Кадр результата берётся так: `c9` и `icon` — `frame.path` (а если маски или bbox взяты из трассы, ещё и SHOT-блок должен быть от этого кадра, поле `trace.shot_matches_frame`); `luma` — `frames[].path`; `derive` — `entries[].input`; `plate` и `project` — `frame.path`, если команда запущена с `--frame` (с `frame.matches_shot`), иначе имя SHOT совпадает с именем файла кадра и трасса лежит в каталоге этого кадра или выше. Пути сравниваются по суффиксу (имена кадров повторяются в разных прогонах). Не совпало — «нет данных: результат по другому кадру», в деталях указан кадр результата. `plate` и `project` для чек-листа лучше запускать с `--frame`. Строка `ALL.provenance` учитывает и результаты: «ок» только если кадры K1–K3 классифицированы как packaged-live и каждый результат из конфига снят хотя бы на одном из них; иначе в статусе «результаты по другим кадрам», а в деталях файл результата, его кадр и подсказка происхождения (`-editor-`, `-ue-editor-`, `-blender-` → `editor-or-blender (hint)`). Строка С-9 на прокси-маске получает «нет данных: … — прокси», замер на прокси остаётся только в деталях с пометкой «не норматив».

## Пороги — все «предложено»

Файл: `tools/art/qa010/thresholds.proposed.json`. Порог меняется правкой файла через ревью или флагом CLI; флаг записывается в вывод.

## Ловушки

- **FLinearColor = линейные значения.** `FLinearColor(1, .25, .25)` даёт на экране байты около (255, 137, 137), а не #FF4040. Ожидаемые цвета сравнивать через `color.expected_srgb_bytes_from_linear()`; для точных байтов в UE использовать `FLinearColor(FColor(…))` (memory `ue-pipeline-traps`, п. 9).
- Палитра 03 (#E8C06A и др.) задана в sRGB-байтах и сравнивается с пикселями PNG напрямую; для EV и WCAG всё декодируется в линейный свет.
- Имена кадров повторяются в разных прогонах: `derive` добавляет каталог прогона, а `checklist` сравнивает пути по суффиксу, а не по имени файла.
- Метка `k: K1` в конфиге чек-листа ничего не доказывает: результат, снятый на другом кадре (например, на редакторном `combined-k1-editor-2026-09-27.png`), в строку K1 не попадает, а `ALL.provenance` перестаёт быть «ок».
- Имя региона ничего не меняет: `--decor decor=trace-ring:…` — такой же прокси, как `--decor tray_proxy=trace-ring:…`.
- В реальных трассах встречается `SHOT ctx cam=(0,0,0) rot=(0,0,0)`: камера ещё не назначена, геометрия такого кадра не оценивается.
- `*.log` игнорируется git: фикстуры трасс хранятся как `*.trace.txt`.
- Luma p50 кадра K1 равна 0: большую часть кадра занимает чёрный фон (С-10). Сравнивать нужно регионы, а не только весь кадр.

## Пример

`tools/art/qa010/examples/2026-09-28-real-frames/` содержит прогон всех команд (версия 1.1.0) на packaged-live кадрах K1, K2 (1,6×) и K3 от 2026-09-28: JSON-выводы, конфиг и сгенерированный чек-лист.
