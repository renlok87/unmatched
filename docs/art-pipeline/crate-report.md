## 2. Как собран кандидат

Сборка идёт в Blender 5.2.2 headless, одним процессом (`crate_build.py`).

1. **Геометрия.** 61 замкнутая оболочка с фасками, одна деталь — одна оболочка:
   - 4 стойки, 8 железных оковок углов, 16 досок стенок, 4 поперечины (спереди и сзади, сверху и снизу);
   - 6 элементов X-раскосов: на каждой стороне один сплошной «/» и две половины «\»;
   - 4 доски крышки, 1 доска дна;
   - 18 заклёпок (low-poly купола, по 8 сегментов).
   
   Соседние детали входят друг в друга на 0,04–0,3 uu, поэтому ни одна вершина не совпадает с вершиной другой оболочки. Сварка 1 мкм в readback не склеивает детали.
2. **Канонический порядок.** Меш пересобирается в каноническом порядке элементов. `bmesh.ops.bevel` упорядочивает новые элементы по внутренним хеш-таблицам, и от прогона к прогону менялись триангуляция, порядок островов и байты FBX/PNG.
3. **Скрытые грани.** Определяются BVH-лучами. Сетка точек с шагом 0,5 uu на каждой грани, до 128 направлений верхней полусферы, лучи вниз блокирует земля z = 0. Грань скрыта, если ни один луч не ушёл. Результат: 896 из 1760 граней (до триангуляции), 42,7 % площади: 3634,7 из 8514,3 uu².
4. **UV0.** Каждая деталь проецируется точно на плоскость той оси своего кадра, которая ближе к нормали грани, без зеркал. Купола заклёпок проецируются вдоль своей оси. Острова не смешивают видимые и скрытые грани. Острова только из скрытых граней уменьшены до ×0,25. Упаковка — детерминированный skyline-пакер в скрипте: ≥ 8 px между островами и ≥ 4 px до края при 1024.
5. **Текстуры 1K.** Запекаются в Cycles (CPU, seed 0) из процедурного шейдера «окрашенное дерево и железо»:
   - волокно вдоль длины каждой доски;
   - светлый износ на выпуклых фасках (маска: локальный AO, чтобы канавки между досками не светлели);
   - зенитная подсветка верхних граней;
   - bump.
   
   BC = цвет × (1 − 0,35 × (1 − AO)): светотень в альбедо «умеренно», 03 С-4.
6. **Экспорт.** UM_FBX_v1 хелперами `tools/tripo-pipeline/blender/static_prop_candidate.py` (файл не менялся). Путь к текстуре относительный: `../textures/…`.
7. **Превью.** EEVEE, JPEG ≤ 1200 px.

Readback выполняется в отдельных свежих процессах: `check_static_prop_fbx.py` (без изменений) и `crate_readback.py`.

## 4. UV и плотность

| Метрика | Значение |
|---|---|
| Острова / покрытие растра 1024 | 475 / 58,9 % |
| Плотность видимых граней | **10,99 px/uu** (скрытые 2,76 px/uu) |
| Растяжение видимых (по площади): анизотропия p50 / p95 / max | 1,00 / 1,414 (фаски 45°) / 2,89 (крутой пояс купола заклёпки) |
| Отношение площадей p05 / p50 / p95 (видимые) | 0,751 / 1,062 / 1,062 |
| Перекрытия между/внутри островов, зеркальные, нулевые UV-треугольники | 0 / 0 / 0 / 0 |
| Мин. зазор (оценка при 1024) | 9 px; пар островов ближе 4 px — 0; при 2048 пар ближе 8 px — 0 |

Для K-1 нужно ≈ 3,3 px/uu (см. §7), то есть на K-1 плотность в 3,3 раза выше нужной. Плотность ниже, чем у бочки (18,5 px/uu на 1K). Причина: 475 островов досок на одной 1K-текстуре без перекрытий (04 §1: UV0 без перекрытий). «Плотность согласована внутри класса» на 1K для такого числа деталей недостижима. Варианты — решение арт-чата (followups).

Что пробовалось и отброшено (записано в params):

- **Smart UV 66°.** Усреднённые векторы проекции давали плоским доскам анизотропию ~1,28 (p50).
- **`bpy.ops.uv.pack_islands`** (CONCAVE и AABB). Покрытие ~47 %, и результат дрожал на ~1e-6 между прогонами, так что байты не воспроизводились.
- **5 точек на грань** при классификации скрытых граней. Пропускались участки досок между раскосами: на проверочном превью они были красными.

## 9. Ограничения и отклонения

- **Оковки углов.** 8 железных оковок добавлены по брифу стиля B («окованные углы»). В концепте углы деревянные, есть только заклёпки. Раскос добавлен и на тыл. Оба пункта записаны в `source/sources.json`.
- **Нормаль.** Normal map — запечка процедурного bump, а не high-poly. Рельеф намеренно слабый: p95 8°.
- **AO дважды.** AO учтён дважды: умеренно в BC и полностью в ORM.R. В UE AO материала влияет только на непрямой свет и небо; проверить в контрольной сцене.
- **CLI.** `static-candidate adopt` CLI не запускался: профиль требует зарегистрированный Tripo-источник и отчёт `static-prop-candidate/1`, а у ящика их нет. `tripo_pipeline.py` сейчас меняет другая задача. Контракт импорта записан в `build-profiles/decor-crate-static-um-fbx-v1.json`, статус proposed, профиль не исполняемый.
- **Плотность.** Ниже, чем у бочки (§4).
