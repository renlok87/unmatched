## Диагноз (подтверждён чтением кода)

1. Инжест колод: `game-initialization.service.ts:197` берёт `Card.effects` из БД как есть —
   рантайм-парсинга текста нет. Backfill (`prisma/backfill-card-effects.ts`) стартует ТОЛЬКО от
   полей `effect*`. У 6 scheme-карт (A Momentary Glance, Winged Frenzy, The Lady of the Lake,
   Prophecy, Command the Storms, Restless Spirits) весь текст лежит в `textEn`, `effect*` пусты →
   в БД и в рантайме `effects: []` — молчаливый no-op (нарушение ACC-013 «молчаливый no-op не
   считается успехом»).
2. Medusa ability — `turn-damage` auto-target без выбора/отказа (нарушение R-14).
3. Arthur ability отсутствует в `ABILITY_CONFIGS`: attack-boost для King Arthur запрещён
   (`boostAllowed` не находит handler); Merlin-гейт и R-16 cancel-семантика не покрыты;
   `combatInfo.attackValue` хранит printed+boost и уходит защитнику (`av`) до reveal —
   утечка значения face-down boost.
4. Hounds «Move each Harpy…» парсится в один pending со всеми fighterIds → двигается только
   одна гарпия (нарушение «each»).
5. Возврат побеждённой Harpy (Winged Frenzy) и урон «any one fighter in Medusa's zone»
   (A Momentary Glance) не моделируются вовсе.

## Изменения

### Модель (`card.model.ts`, `game-state.model.ts`)
- `EffectTarget` += `EACH_OWN_FIGHTER`, `ANY_FIGHTER_IN_ZONE`.
- `EffectType` += `RETURN_DEFEATED`.
- `CardEffect` += `canPassThroughEnemies?`, `zoneFighterName?`.
- `PendingEffect.type` += `TARGET_FIGHTER`; поля += `targetFighterIds?`, `damage?`,
  `canPassThroughEnemies?`, `zoneFighterName?`, `restoreFullHealth?`.
- `CombatState` += `boostValue?` (card+ability boost суммарно), `abilityBoostCardId?`,
  `cardBoostCardId?`; `attackValue` хранит ТОЛЬКО printed значение.

### Парсер (v8)
- «Deal N damage to any one fighter in X's zone» → DAMAGE/ANY_FIGHTER_IN_ZONE (fighterName = X).
- Winged Frenzy compound → MOVE/EACH_OWN_FIGHTER (canPassThroughEnemies) + RETURN_DEFEATED
  (fighterName Harpy, zoneFighterName Medusa, optional).
- parseFighterRef: «each of your fighters» → EACH_OWN_FIGHTER (не NAMED_FIGHTER-мусор).

### Инжест source→runtime (узкий фикс)
- Backfill: `hasTexts` расширяется fallback — SCHEME-карта без `effect*`, но с непустым
  `textEn` → парсить `textEn` как `after` (нераспознанное честно едет как UNSUPPORTED).
- `game-initialization`: после `normalizeCardEffects`, если effects пусты и есть
  `card.text`/`textEn` при cardType SCHEME → тот же fallback-парсинг в рантайме
  (новые матчи получают эффекты без перезапуска backfill).

### Executor (`card-effect-executor.service.ts`)
- DAMAGE c target ANY_FIGHTER_IN_ZONE: цели = ВСЕ живые бойцы в зоне бойца `fighterName`
  (включая своих — буквальный текст); ≥1 → TARGET_FIGHTER pending (mandatory, damage=N);
  0 → «No valid targets» fizzle.
- MOVE с множественными целями (EACH_OWN_FIGHTER, NAMED_FIGHTER «each»): по одному
  sequential pending на живого бойца (fighterIds=[id]) — «each» = отдельное решение,
  0-шаг легален, revalidation доски на каждом резолве.
- MOVE pending наследует `canPassThroughEnemies` (враги не блокируют путь, конечная клетка
  всё равно свободна).
- RETURN_DEFEATED: побеждённые бойцы владельца по fighterName; есть → optional PLACE pending
  (fighterIds=[кандидаты], zoneFighterName, restoreFullHealth); нет → skip («if any»).

### `game-action-executor.service.ts`
- Резолв TARGET_FIGHTER: fighterId ∈ targetFighterIds, живой → damage, terminal-check, drain.
- Резолв MOVE: `canPassThroughEnemies` → пустые blockedPositions.
- Резолв PLACE: `zoneFighterName` → клетка обязана делить зону с указанным бойцом;
  `restoreFullHealth` → разрешён defeated боец, health=maxHealth, isDefeated=false
  (identity/id сохраняются — четвёртая гарпия не появляется).
- Attack: `attackValue` = printed; boost-карты уходит в discard как раньше, но сумма boost
  пишется в `combatInfo.boostValue` (+ cardBoostCardId/abilityBoostCardId). Новый
  `abilityBoostCardId` в AttackDto — второй независимый boost Arthur (Noble Sacrifice
  «in addition»: карта-BOOST + способность одновременно, две разные instance-карты).
- `boostAllowed`: cardAllows — как раньше; ability-путь → атакующий обязан быть HERO-бойцом
  с heroSlug === heroId handler'а (Arthur бустит только атаку King Arthur, не Merlin).
- resolveCombat: attackValue для расчёта = printed + (cancelled ? 0 : boostValue) —
  R-16: Feint защитника сбрасывает ability boost без значения, printed остаётся.

### Способности (`ability-config.ts` + generic handler)
- Medusa: `turn-damage` заменён на новый kind `pending-target-damage` (turn-start,
  enemy-in-zone, value 1): есть цели → optional TARGET_FIGHTER pending (выбор ИЛИ отказ);
  нет целей → no-op, ход не блокируется. Persistent (pendingEffects в state) → reconnect ок.
- Arthur: config с флагом `allowsAttackBoost: true` (boost-гейт по слагу атакующего в
  boostAllowed; cancel-семантика — через combatInfo.boostValue в resolveCombat).

### Visibility
- `filterPrivateData`: пока phase COMBAT (защита не сыграна) НЕ-атакующему отдаётся
  `attackValue` (printed) без `boostValue` — значение face-down boost не утекает;
  карты boost лежат в discard c isVisible=false (уже так — discardCard).
- После COMBAT_RESOLVE (reveal) итоговые значения видны обоим.

### API / adapters (новый choice type TARGET_FIGHTER)
- GraphQL: AttackDto += `abilityBoostCardId`; ResolvePendingEffectDto уже несёт fighterId
  (для TARGET_FIGHTER x/y не требуются).
- AI (`ai-decision.service`): TARGET_FIGHTER → вражеская цель с min HP; только свои/нет
  врагов и optional → decline; mandatory → первая.
- Web (`gameStateAdapter`, `remoteGameStore`, `GameView`): WirePendingEffect += TARGET_FIGHTER
  + новые поля; клик по бойцу из targetFighterIds → resolvePendingEffect(effectId, fid);
  revive-PLACE (restoreFullHealth): выбор бойца кнопками в баннере (defeated не рендерятся
  на доске) + клик по клетке; ability-boost: модалка выбора boost-карты при атаке Arthur
  (ability) и карт с BOOST-эффектом (card), обе независимы.
- Admin Game Tester: `peffect <id> <f>` без координат для TARGET_FIGHTER.
