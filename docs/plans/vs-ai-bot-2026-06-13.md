# VS_AI бот — архитектура и план (2026-06-13)

ИИ-оппонент для одиночной игры. `GameMode.VS_AI` существует
(`backend/src/games/dto/create-game.dto.ts:13`), но движка нет: игра в этом
режиме даже не инициализируется — `initializeGameState`
(`game-initialization.service.ts:99`) требует ≥2 `GamePlayer` с выбранными
героями, а второго (бота) никто не создаёт.

## Что уже есть (точки интеграции)

- **Старт**: `game.service.startGame` (`game.service.ts:637`) — для VS_AI
  пропускает проверку opponent (`:660`), но НЕ создаёт второго игрока.
- **Действия**: `GameActionExecutorService` (`game-action-executor.service.ts`)
  — публичные `executeManeuver/executeAttack/executePlayDefense/
  executeResolveCombat/executeEndTurn/executePass/executePlayScheme/
  executeResolvePendingEffect`, все принимают `(dto, ActionContext{userId,
  currentState})` и возвращают `{success, gameState, metadata}`.
- **Центральный хук мутаций**: `game-actions.resolver.executeMutation`
  (`:137`) — выполняет мутацию, затем `saveState` + `publishGameUpdate` +
  `recordGameAction`. **Сюда вешается запуск хода бота** после действия
  человека.
- **Состояние хода**: `state.currentTurnPlayerId`, `state.phase`
  (ACTION_MANEUVER/ACTION_ATTACK/COMBAT/COMBAT_RESOLVE/GAME_OVER),
  `metadata.actionsRemaining` (getActionsRemaining), `metadata.combatInfo`
  (defenderId при ожидании защиты), `metadata.pendingEffects` (MOVE/PLACE/
  CHOOSE_ONE — выборы бота).
- **Realtime**: `gameSubscriptionService.publishGameUpdate` — каждый шаг бота
  публикуется, человек видит ходы без F5 (realtime-баг починен в 09117e2).
- **Эвристики-данные**: `adjacencyService.getReachableCells`, `getFighterMovement`,
  `bannerAllows`, карты в руке (cardType/attackValue/boostValue/bannerName).

## Идентичность бота

Сид-юзер `ai@unmached.local` (username «AI Bot», role USER, рандомный пароль) —
по образцу `prisma/seed-admin.ts` (upsert). Реальная User-строка нужна, т.к.
`GamePlayer.userId` — FK. Хелпер `getAiUserId()` кэширует id. Признак бота в
игре: `game.opponentId === AI_USER_ID` (или `GamePlayer.userId === AI_USER_ID`).

## Инкременты

### Inc 1 — Сетап VS_AI (ФУНДАМЕНТ, разблокирует всё)
- Сид AI-юзера (`prisma/seed-ai.ts`, добавить в `seed.ts`).
- `game.service`: при `createGame(mode=VS_AI)` (или в `startGame`) автодобавить
  AI вторым `GamePlayer` (opponentId=AI), автовыбрать ему героя (рандом из
  `prisma.hero`), `isReady=true`. Тогда хост ready+start → `initializeGameState`
  видит 2 игроков.
- **Проверка**: создать VS_AI игру через GraphQL, start → состояние
  инициализируется (2 бойца-героя, колоды), без ручного join.

### Inc 2 — Движок решений (чистая функция, юнит-тестируемо)
`AiDecisionService.decide(state, aiUserId): AiAction` где `AiAction` =
`{kind:'maneuver',fighterId,path} | {kind:'attack',attackerId,targetId,cardId} |
{kind:'defense',cardId|null} | {kind:'resolveCombat'} | {kind:'resolvePending',
effectId,...} | {kind:'endTurn'} | {kind:'pass'}`.
Эвристики v1 (greedy):
1. phase COMBAT и AI=defender → лучшая по value DEFENSE/VERSATILE карта (или
   null=без защиты) → затем resolveCombat.
2. AI-pending: CHOOSE_ONE → выгодная опция (HEAL>DRAW>прочее); MOVE → клетка к
   врагу из reachable; PLACE → свободная клетка у врага.
3. Ход AI, actionsRemaining>0: смежен с врагом + есть атак-карта (banner ок) →
   attack лучшей; иначе manoeuvre 1 шаг к ближайшему вражескому HERO; нет хода →
   endTurn.
- **Тест**: фикстуры GameState (как `card-effect-executor.service.spec.ts`) →
  ассерты на kind/выбор. Без интеграции.

### Inc 3 — Оркестрация хода бота (интеграция + realtime)
`AiTurnService.runAiTurns(gameId)`: грузит state; ПОКА (AI=currentTurn ИЛИ
AI=defender в COMBAT ИЛИ у AI есть pending) И phase≠GAME_OVER И шагов<LIMIT(40):
decide → соответствующий `executor.execute*` → saveState → publishGameUpdate →
recordGameAction. Вызов из `executeMutation` ПОСЛЕ хода человека в VS_AI-игре
(если по итогу ход/защита за ботом). Анти-залип: лимит шагов + обязательный
прогресс seq.
- **e2e**: создать VS_AI, человек манёвр→атака, бот отвечает (защита/свой ход),
  игра доходит до осмысленного состояния; Playwright — realtime-ходы бота.

### Inc 4 — Полировка
AI как защитник от pending-эффектов человека, выбор героя по «силе», лучшие
эвристики атаки (учёт boost/после-боя), сложности (random/greedy/lookahead).

## Риски
- Бесконечный цикл оркестрации → жёсткий LIMIT шагов + проверка роста seq.
- Бот «застревает» (нет валидного хода) → fallback endTurn/pass всегда доступен.
- Оптимистик-лок saveState: каждый шаг бота +1 seq, как у человека.
- AI должен ходить и когда вкладка человека закрыта — оркестрация серверная
  (в executeMutation), не клиентская.
