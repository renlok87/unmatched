## Метки уверенности (используются во всём пакете)

| Метка | Значение |
|---|---|
| `ФАКТ` | Подтверждено исходником/проверкой; рядом указан источник |
| `РЕШЕНИЕ` | Выбрано автором; дата и формулировка в реестре решений ниже |
| `ПРЕДЛОЖЕНИЕ` | Рекомендация, автором ещё не утверждена |
| `ВОПРОС` | Без ответа решение принять нельзя; см. `11-open-questions-and-risks.md` |

Отдельно различаются: **правило настольной игры**, **текущее поведение сервера** (по `docs/backend-api/`), **желаемое поведение цифровой версии**. Расхождения фиксируются в реестре расхождений (`08-integration-decisions.md`, таблица GAP).

## 1. Описание игры

Unmatched — пошаговая карточная дуэльная игра (1×1) по правилам настольной Unmatched: два героя с помощниками на небольшой клетчатой доске; каждый ход — 2 действия (манёвр, атака, схема, пас); бой разрешается картами атаки/защиты с бустами. UE-версия — объёмная стилизованная диорама с фигурками персонажей вместо 2D-спрайтов: та же серверная логика, новая подача с атмосферным светом, лёгкими анимациями и звуком. `ПРЕДЛОЖЕНИЕ` (формулировка к утверждению автором).

## 2. Аудитория

- Сам автор и небольшие партии «друг против друга» по приглашению (приватная комната).
- Знание настольных правил Unmatched желательно, но не обязательно: базовое обучение — после MVP, в MVP — текстовые подсказки и читаемые причины недоступности действий. `ПРЕДЛОЖЕНИЕ`

## 3. Принципы дизайна

`ПРЕДЛОЖЕНИЕ` — к утверждению. Пронумерованы, на них ссылаются документы пакета.

- **P1. Поле читается с основного угла.** Все обязательные выборы (клетки, цели, зоны) различимы с фиксированной стартовой камеры без вращения (следствие D-10).
- **P2. Игрок понимает, почему действие недоступно.** Любая заблокированная кнопка/клетка объясняется короткой причиной («не ваш ход», «нет действия», «недостижимо»).
- **P3. Красота не мешает решению.** Анимации/VFX не блокируют ввод дольше 1 с, пропускаемы; сетевой результат никогда не зависит от завершения ролика.
- **P4. Сервер — единственная истина.** Клиент не считает правила; локально — только подсказки и оптимистичная подсветка; дедупликация обновлений по `sequenceNumber`.

## 4. Что UE-версия даёт по сравнению с веб-клиентом

`ПРЕДЛОЖЕНИЕ` (на основе ФАКТов веб-клиента, см. `_sources/facts-web-ux.md`):

1. Объёмная диорама вместо плоских спрайтов: свет, фактуры, глубина (в вебе — 2D Phaser-сцена).
2. Персонажи с лёгкими анимациями (idle/выпад/урон/смерть) вместо статичных картинок.
3. Звук и музыка — в веб-клиенте их нет вовсе.
4. Новая подача карт (рамка/инспектор в стиле диорамы) при сохранении существующих 2D-иллюстраций (D-09).
5. Нативное Windows-приложение со стабильным кадровым бюджетом (D-07).

## 5. Основной цикл сессии

Запуск приложения → вход (JWT) → лобби (список/создание приватной комнаты или создание VS_AI) → комната (выбор героя, готовность, старт хостом) → партия (ходы: 2 действия, бой с картами) → экран результата → возврат в лобби → следующая партия. Матчмейкинг, рейтинг, профиль — вне MVP.

## 6. Целевые длительности

`ПРЕДЛОЖЕНИЕ`, сверено с серверными таймерами (`_sources/facts-backend.md`, раздел 1):

- Матч: 15–40 минут (зависит от темпа игроков; серверного лимита на партию нет).
- Ход: 2 действия (ФАКТ: `ACTIONS_PER_TURN = 2`); целевой темп 1–3 мин/ход; серверного таймера на ход нет.
- Окно защиты: **30 с** — ФАКТ (`DEFAULT_DEFENSE_TIMEOUT`, дедлайн в `metadata.combatInfo.timeoutAt`).
- Подтверждение резолва: 10 с (`DEFAULT_RESOLVE_TIMEOUT`).
- Ожидание соперника в комнате: не ограничено сервером; UI показывает presence-статус.

## 7. Границы первой версии

### MVP (первая законченная версия)

- Windows 10/11, мышь + клавиатура, 1080p @ 60 FPS на среднем ПК (D-05, D-07).
- Русский и английский интерфейс (D-08).
- Вход существующим аккаунтом (email+пароль); обновление токенов; `ВОПРОС` Q-005 о регистрации.
- Лобби: список доступных игр, создание приватной комнаты по коду, вход по коду.
- Режимы: приватная комната 1×1 и **VS_AI** (D-12).
- Герои: **Medusa (+3 гарпии)** и **King Arthur (+Merlin)** — кандидаты из проверенных материалов; пригодность механик Medusa требует проверки (см. риски).
- Доска: **Cobble City** — геометрия требует проверки живой партией (`boardState` — источник истины). *Поправка D-03 от 2026-09-30: для Medusa × King Arthur — оригинальные карты Marmoreal и Sarpedon, Cobble — регрессионная доска (§8).*
- Полный цикл партии: манёвр, атака/защита/резолв, схемы, отложенные эффекты, пас/конец хода, победа/поражение.
- Восстановление соединения в партии без повторного расхода карт.
- Экраны: загрузка, вход, лобби, комната+выбор героя, игровой HUD, инспектор карт, потеря связи, настройки (минимальные), результат.
- Ассеты: 4 модели персонажей с лёгким ригом, доска-диорама, подставки/маркеры, UI-семейства, звук минимального набора, VFX минимального набора.
- Одна модель и участок доски доводятся до эталонного качества как визуальный ориентир (D-04).

### После MVP (не блокирует первую версию)

- Матчмейкинг (сервер уже поддерживает: очередь, `matchFound`, accept/decline — `ФАКТ` из `docs/backend-api/03`).
- Геймпад; третий-четвёртый герой и вторая доска; обучение/туториал; чат в комнате; лидерборд/профиль/друзья (есть в вебе); presence-индикаторы в лобби.
- Расширенные настройки доступности и графики; кинематографические вставки камеры (если захотятся).
- Синхронный кросс-плей UE ↔ веб-клиент (веб-клиент остаётся рабочим — `ФАКТ`).

### Не планируется в обозримой версии

Весь каталог 84 героев/880 карт как цель первой версии; мобильные платформы; VR; магазин/сезоны/коллекционирование; кампания; реплеи и наблюдение; dedicated server UE и перенос правил на C++ (архитектура «тонкий клиент» уже решена прежним ADR и не пересматривается — см. раздел 10).

## 10. Ключевые факты-ограничения (выжимка; подробно в `_sources/`)

1. Сервер — арбитр: 11 игровых мутаций, все возвращают `GameMutationResult` с новым состоянием и `sequenceNumber`; HTTP-ответ и подписка `gameStateUpdated` дублируют одно и то же — дедупликация по номеру обязательна (`ФАКТ`, `docs/backend-api/04`).
2. JSON-внутри-строк: `state`, `players/fighters/handZones/boardState/metadata` — двухфазный парсинг в UE (`ФАКТ`, 04/06).
3. Auto-resolve при таймауте защиты **не применяет урон** (TODO на сервере) — для MVP нужен обход или серверная задача (`ФАКТ`-ограничение, 10/11).
4. `playerJoined/playerLeft` в игровой фазе не публикуются; `decks/discardPiles` в подписку не входят (`ФАКТ`, 04).
5. Скрытая рука соперника фильтруется сервером (`"???"`, `isVisible:false`) — не восстанавливать по каталогу (`ФАКТ`, 04).
6. `contentVersion` — константа `'2.0.0'`; админ-мутации не инвалидируют Redis-кэш (TTL 1 ч) — политика обновления контента требует решения (GAP).
7. Обработчики уникальных способностей в коде есть у arthur/daredevil/ms-marvel; у Medusa — проверить (`ФАКТ` отсутствия файла + `ВОПРОС` о generic-обработчике).
8. Геометрия Cobble City: код — 6×4=24 клетки; бриф проверил через API 5×6=30 cells. Истина для клиента — `boardState` живой партии; модель доски блокируется до проверки (GAP).
9. Арты карт medusa/king-arthur отсутствуют в `public/assets/decks` — прогнать `sync-card-assets.mjs medusa king-arthur` (задача).
10. Матчмейкинг описан как рабочий, но PubSub `matchFound` in-memory (один инстанс) — не блокирует MVP (матчмейкинг вне MVP).
11. Веб-клиент: регистрация отключена (роут закомментирован) — как создавать аккаунты для UE MVP, вопрос Q-005.
12. Прежние планы Unreal противоречат актуальным докам в ряде пунктов (Int vs Float скаляры, `eventsSince`, WS-коды, `combatInfo.timeoutAt`) — сверка поимённо в `08-integration-decisions.md`; всё это планы, не код.
