## R-01 — сервер: публичный журнал эффектов боя в снимке

**Итог:** done. Коммит 6115fb80. Основание: CLOSEOUT §2 строка DE-018 и §7, C-2026-10-04.md «Сработавшие строки
эффекта», ревью C п. 4; RESEARCH-2026-10-05 выводы 5–6 (журнал «эффект → исход» с причинными блоками, фильтр скрытого
на сервере для каждого зрителя).

**Что было (HEAD 480e4c66).**
- `appliedEffects` (`EffectResult`: `effectId`, `targetIds`, `valueApplied`, `message`) жили только в ответе мутации
  `resolveCombat` и в серверной `combatResolutionProgress`, которую `filterPrivateData` вырезает. В снимке не было ни
  записи боя, ни строк эффектов: клиент подавал `lines=0` (`S08FlowGameMode.cpp`), и +600 мс на строку (F-01) вживую
  не играли.
- В `EffectResult` не было источника: ни владельца, ни карты, ни этапа, ни связи «выбор → опция».
- Предложенного журналом C поля `metadata.lastCombat` не существовало — создано с нуля по образцу `lastMovement`
  (MS-T-14) и `skippedEffects` (DE-016).

**Что сделано.**
- **Модель** (`game-state.model.ts`): `LastCombat` и `CombatEffectLogEntry`, поле `GameStateMetadata.lastCombat`.
  Запись боя: `n`, `seq`, бойцы, игроки, карты, `finalAttack` / `finalDefense` / `defenderDamage` / `attackerWon`,
  отмены карт, `appliedEffects`. Запись эффекта: `i`, `timing` (`IMMEDIATELY` / `DURING` / `AFTER`), `side`,
  `playerId`, `source` (`CARD`: instance id, каталожный id, имя), `effectId`, `kind`, `outcome`
  (`APPLIED` / `CHOICE` / `NO_TARGETS` / `MANUAL` / `FAILED`), `value?`, `targets`, `text?`, `parent?`, `hidden?`.
- **Источник у каждого результата** (`card-effect-executor.service.ts`): `applyOneEffect` ставит
  `EffectResult.source` — владелец, карта, тип, печатный текст, id выборов, которые эффект открыл, и id выбора, чей
  резолв его вызвал (`executeChosenEffects` получает `pending.id` от `executeResolvePendingEffect`). Так причинность
  берётся из сервера, а не из разницы снимков.
- **Сборка журнала** (`effects/combat-effect-log.ts`, чистые функции): `buildCombatEffectLog` — этапы reveal / during
  / after в порядке применения, опции CHOOSE_ONE получают `parent` = `i` записи CHOOSE_ONE; в `targets` идут только
  id бойцов и игроков, остальное (instance id карт) и заметка движка — в `hidden`. `projectLastCombat` — проекция
  зрителя.
- **Запись** (`executeResolveCombat`): в снимок, который завершил бой, в том числе при `GAME_OVER` и после
  возобновления с паузы выбора (`drainAfterChoice` → тот же путь). `seq` = номер этого снимка, `n` растёт от прошлой
  записи. Запись живёт до следующего боя, как `lastMovement`.
- **Приватность** (`game-state.service.ts` `filterPrivateData`): `hidden` остаётся только у записей зрителя-владельца.
- **Сохранение**: ключ `lcr` в `serialize` / `deserialize`; сейвы без ключа — «записи нет».
- **Контракт**: [16-network-contract.md](../../../16-network-contract.md) §5.1 и строка в матрице §5;
  [CUE-DISPATCHER.md](../../../../unreal/contracts/cue-dispatcher/CUE-DISPATCHER.md) §3.1 — источник строк для
  постановки; комментарий в `docs/unreal/snippets/unreal/Ops/subscriptions.graphql`.

**Решения.**
- **Место поля — `metadata.lastCombat.appliedEffects`, как предложил журнал C.** `metadata` уже идёт строкой JSON и в
  `gameState`, и в `gameStateUpdated`, поэтому GraphQL-схема не меняется, а старые клиенты поле не замечают (§8
  контракта). Отдельный поток событий в духе Power-пакетов Hearthstone сейчас избыточен: снимок приходит ровно один на
  мутацию, и журнал боя едет в нём.
- **В журнал идут только сработавшие эффекты карт.** Условие `when` не выполнено или карта отменена — записи нет: это
  и есть «сработавшая строка» F-01. Эффект, открывший выбор, пишется с `outcome=CHOICE`, его опции — дочерними
  записями. Какие исходы считать строкой (+600 мс) — решает клиент в R-02, сервер отдаёт исход каждой записи.
- **Способности героев в журнал не пишутся.** Модификаторы и хуки после боя не дают `EffectResult` и не являются
  печатной строкой карты; их показ — CUE-014 / GD-044. Поле `source.kind` оставлено расширяемым.
- **Бой на паузе выбора записи не даёт.** Постановка DE-018 стартует на снимке, который бой разрешил; промежуточная
  запись дала бы повтор строк.
- **Скрытое — только непрозрачными ссылками.** Сейчас ни один эффект не кладёт в `targetIds` карту, но правило
  заложено: всё, что не боец и не игрок, уходит в `hidden.refs`. Заметки движка (`message`, по-русски, для Game Tester)
  тоже только владельцу: часть из них называет найденные карты.
- **Результаты без источника пропускаются.** Это бой, начатый до деплоя R-01 и прерванный выбором (в
  `combatResolutionProgress` старые `EffectResult`); владелец неизвестен, классифицировать нельзя.

## R-02 — клиент: строки эффектов боя из журнала сервера

эффекта», ревью C п. 4; 01 F-01 (+600 мс на строку, пропуск кликом); RESEARCH-2026-10-05 выводы 5–6; результат R-01.

**Что было (HEAD bb6ed26a).**
- `AS08FlowGameMode::StartCombatStage` подавал `In.EffectLines = 0`: механизм 600 мс на строку в `FS09CombatStage` был
  (тест `.Timeline`, гейт C4), но вживую не играл — `metadata.lastCombat` клиент не читал.
- Текста сработавших строк на экране не было: панели карт у краёв поля показывали только имя, значение, баннер и
  печатный текст карты.
- В трассе не было ничего, что связало бы `lines=` постановки с журналом сервера.

**Что сделано.**
- **Модель без мира — `S09/S09CombatEffectLog.{h,cpp}`:**
  - `FS09LastCombat::Read` декодирует `metadata.lastCombat` (запись боя и `appliedEffects`); поле `hidden` не
    декодируется вовсе — приватность по построению, как у `FS09HudFactory::HiddenCard`.
  - `Matches(baselineSeq, closingSeq, attacker, target)` — запись этого боя: `seq` в окне (последний снимок открытого
    боя; закрывший снимок], те же атакующий и цель.
  - `S09CombatEffectLog::Lines` — строки постановки: исходы `APPLIED`, `CHOICE`, `MANUAL`; опция с `parent`
    продолжает строку родителя («Choose one. -> DRAW_CARDS 1»); `NO_TARGETS` и `FAILED` строки не дают. Текст строки —
    печатное предложение, без него — `KIND value`.
  - `TraceLine` — `COMBAT-LOG seq=… log=… n=… entries=… lines=… src=log|none|other outcomes=APPLIED:a,…` (только

  строками); запросы панели `EffectLinesShown(now)` и `HighlightedEffectLine(now)`: строка k появляется в начале своего
  шага, подсвечена первые 400 × скорость, остаётся до конца; после пропуска все строки на панели, подсветки нет.
  Шкала и трасса `CUE combat` не менялись.
- **Игровой режим — `S08FlowGameMode.cpp`:**
  - `StartCombatStage` читает журнал закрывшего снимка, пишет `COMBAT-LOG` и подаёт `EffectLines` = число строк;
    `bHasEffectText` = текст на раскрытой карте **или** есть строка эффекта.
  - `BuildCombatStageHud` — под панелью карты блок `EFFECTS` со строками своей стороны (атакующая слева, защитная
    справа), текущая строка — жирная в цвете стороны. Slate, как остальной слой боя (финальный вид — GD-047/048).
  - `TickCombatStage` перестраивает HUD, когда появляется строка или кончается её подсветка (`CombatEffectHudKey`).
- **Контракт CUE:** фикстура `combat-staging-effect-lines` (две строки, пропуск кликом во второй: 280 мс, пауза 0,
  CUE-010 `ms=2680 hold=1880`, итог 4480; без пропуска 5100); гейт `cue_contract.py check-trace` — C8 (формат
  `COMBAT-LOG`; без своей записи строк 0; `lines` постановки = `lines` журнала того же seq; строки только при `text=1`;
  клиент R-02 пишет журнал перед каждой постановкой) и C9 (`--min-effect-lines N`); сводка `combat_logs`,
  `combat_logs_own`, `combat_effect_lines`. Документы: CUE-DISPATCHER.md §3.1, §5, §6, таблица фикстур;
  16-network-contract.md §5.1 (правило клиента).

**Решения.**
- **Строка = `APPLIED` / `CHOICE` / `MANUAL`; опция CHOOSE_ONE — продолжение строки родителя.** F-01 считает
  «сработавшую строку» печатного текста: выбор и выбранная опция — одна строка карты, а не две по 600 мс. `MANUAL` —
  печатный текст, который игроки применяют сами, его нужно прочитать. `NO_TARGETS` ничего не сделал (тост DE-016 /
  DE-020 его объясняет), `FAILED` — сбой движка; ни то, ни другое не удлиняет бой.
- **Окно seq вместо равенства.** R-01 ставит `seq` = снимок, который разрешил бой; клиент может получить его слитым с
  более поздним (WS-слияние, переподключение), поэтому запись принимается при `baseline < seq ≤ closing` и тех же
  бойцах. Запись прошлого боя (`seq ≤ baseline`) не даёт строк (`src=other`).
- **Строка эффекта включает чтение 1000.** Если эффект сработал, на карте был эффект; раскрытие может не назвать
  карту после переподключения — удержание чтения не теряется. Гейт C8 требует `text=1` при `lines>0`.
- **Строки — на панелях карт у краёв поля, не в ленте событий.** Лента `MS-LOG` — журнал перемещений (MS-T-17 /
  DE-022), слот карты-источника (DE-026) — для схем и бустов вне боя. Строка относится к раскрытой карте боя, и
  панель этой карты уже на экране всю постановку.
- **Пропуск не прячет текст.** Оставшиеся шаги обнуляются (F-01), а все строки встают на панель сразу и живут до
  конца постановки.
- **Проверка в трассе — отдельной строкой `COMBAT-LOG`, а не полем `stage=read`.** Чтение и строки — разные этапы
  (`read` 1000, `effect` 600 каждая, C4 уже проверяет их длительность и `lines`); формат `CUE combat` и побайтные
  фикстуры не менялись. Новая строка связывает `lines=` с журналом сервера (C8).
