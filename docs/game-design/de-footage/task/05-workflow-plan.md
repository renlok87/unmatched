# 05 — Нарезка на прогоны workflow

Пакет режется на четыре прогона. Между прогонами — проверка оркестратором (основная сессия) и коммит. Каждый
прогон запускается только по команде пользователя ([00-TASK.md §0](00-TASK.md#0-полномочия)).

| Прогон | Пункты | Когда | Агенты | Параллельность | Изоляция |
|---|---|---|---|---|---|
| A. Синхронизация спецификаций | W-01…W-05, W-20 | после R-серий и решений D-DE (принимает Claude, делегировано); без них — с пометками `waiting` | 6 редакторов + 1 ревьюер | редакторы параллельно: у них разные файлы | один worktree, ветка `de/spec-sync` |
| B. Подбор хода P1 | W-10…W-13 | после A; вместе с базовыми MS-T-08 / 12 / 16 / 17 | 4 исполнителя + 1 ревьюер | **последовательно**: общие `S09HudModel`, `S08ArtHud*`, `S08FlowGameMode`, одна сборка UE за раз | один worktree, ветка `de/ms-p1` |
| C. Бой, значки, смерть | W-15 → W-16 → W-14 | после A; W-14 — после ответа на D-DE-01 и D-DE-03 | 3 исполнителя + 1 ревьюер | последовательно | один worktree, ветка `de/combat-icons` |
| D. P2 | W-17, W-18, W-19 | после B и C | 3 исполнителя + 1 ревьюер | последовательно | один worktree, ветка `de/p2` |
| — Живое исследование DE | R-01…R-15 | в любой момент, лучше до A | без workflow | основная сессия с пользователем | — |

## Общие правила для всех прогонов

- **Модель и усилие:** opus, effort high — правило с 2026-09-29.
- **Ревью — один агент, один проход:** проверяет и смысл, и границы. Второго ревьюера и повторных раундов нет.
  Исправления — только на основе данных: ревьюер не дописывает код и не придумывает числа.
- **Интеграция:**
  - исполнители коммитят в worktree с `--no-verify`;
  - оркестратор проверяет `git diff --stat` против списка файлов пункта;
  - затем `tools/git/safe-integrate.sh <ветка>` — сначала dry run, потом `--apply`;
  - если прогон менял `unreal/`, после интеграции пересобрать UnmatchedEditor в основном checkout и, если
    упаковывали, перенести сборку `tools/s08/sync-staged-build.ps1 -From <worktree>`;
  - перед интеграцией влить свежий `fix/admin-panel` в ветку прогона, пересобрать и прогнать тесты.
- **Режимы (AGENTS.md «Iteration speed»):**
  - прогон A — лёгкий: без бенча, гейты только по затронутым файлам;
  - B–D — полный: все гейты, ревью, живой прогон;
  - одна упаковка на изменение.
- **Живые прогоны:** только Marmoreal или Sarpedon original, принятый арт включён по умолчанию; кадры смотреть до
  отчёта.
- **Скрипт workflow:**
  - править только через Write или Edit без CRLF: иначе отказ «control characters»;
  - `Date.now()` и `Math.random()` недоступны.

## Шаблон промпта агента

Подставить переменные `<…>`. Блок полномочий обязателен дословно: иначе субагент принимает последний вопрос
пользователя за границу разрешений.

```text
Ты — <роль> прогона <A|B|C|D> пакета DE (docs/game-design/de-footage/task/). Пункт: <W-xx>.

Полномочия (дословно из чата пользователя, 2026-10-04):
«…изучил этот ролик и выцепил для нас важную информацию для реализации последующих этапов.»
«Да, именно составь пакет документов на основе которых потом попилится задача для workflow.»
Запуск этого прогона пользователь подтвердил: «<дословная команда запуска>».
Постоянное делегирование «делай все без меня»: спрашивать только о блокерах.

Прочитай: task/00-TASK.md (правила, гейты), task/01-decisions.md (решения D-DE: <вставить принятые решения или
«не принято»>), task/02-spec-deltas.md (дельты <SD-..>), task/03-work-items.md (<W-xx>: файлы, приёмка).
Основание всех чисел — docs/game-design/de-footage/timings.csv и README.md. Нет данных — пиши «нет данных».

Границы: меняй только файлы пункта <W-xx>. Решения D-DE без записи в 01-decisions.md не применяй
(waiting). Ассеты, тексты карт и строки интерфейса DE не копируй. Работай в worktree <путь>, коммит —
git commit --no-verify. Режим: <лёгкий|полный> (AGENTS.md «Iteration speed»).

Верни: applied / stale / waiting / rejected по дельтам; изменённые файлы; запущенные гейты с результатом;
свидетельства (пути); открытые вопросы.
```

## Прогон A — подробно

1. **Шесть редакторов параллельно:** W-01, W-02, W-03, W-04, W-05, W-20. У каждого — свой набор файлов, они не
   пересекаются.
2. **Схема результата:**

   ```text
   {w, applied[{sd, file, anchor}], stale[{sd, current_text}], waiting[{sd, decision}],
    rejected[{sd, reason}], files[], gates[{cmd, ok, tail}]}
   ```

3. **Ревьюер — один проход:**
   - согласованность ссылок между документами: SD ↔ MS-T ↔ CUE ↔ Q-2xx;
   - CSV и `cue-table.json` идентичны по смыслу;
   - пометки «по умолчанию, D-DE-xx» стоят;
   - нет правок вне списка файлов;
   - гейты зелёные.

   Мелкие текстовые ошибки исправляет сам; спорное возвращает в журнал.
4. **Выход:**
   - коммит в `de/spec-sync`, интеграция;
   - журнал прогона — `docs/game-design/de-footage/task/runs/A-<дата>.md`, туда же список `waiting` для
     пользователя.

Оценка: ~7 агентов, 30–45 мин, без сборок UE.

## Прогоны B–D — подробно

Каждый пункт идёт по циклу:
1. сверить базовую задачу MS-T в `05-implementation-plan.md`: сделано / в работе / не начато;
2. реализовать;
3. сборка редактора и игровой цели (`Build.bat` выходит с кодом 0 и при ошибке компиляции — проверять лог);
4. тесты пункта;
5. живой прогон двух клиентов `tools/s08/run-phase2-demo.ps1` на Marmoreal original;
6. кадры до и после — в `docs/game-design/evidence/DE-FOOTAGE/<дата>/<W-xx>/`;
7. коммит.

Ревьюер в конце прогона (один проход):
- приёмка каждого пункта по [03-work-items.md](03-work-items.md);
- `git diff --stat` против списка файлов;
- кадры просмотрены;
- трассы `CUE …` / `MS-CUE …` прошли `cue_contract.py check-trace`.

Арт-приёмка значков (W-15) — за пользователем. Подскок (W-12) решён в D-DE-02; A/B-кадры прикладываются
для просмотра. Ревьюер только готовит кадры.

Оценка B: 5 агентов, несколько часов (сборки UE последовательны). C — 4 агента. D — 4 агента.

## Что оркестратор делает перед прогоном A

1. Провести живое исследование по [04](04-de-live-research.md) и по его данным принять решения D-DE-01, 02,
   03, 05, 12 (делегировано пользователем 2026-10-04). Записать их в 01 с обоснованием.
2. Обновить 02 там, где данные R изменили вывод.
3. Проверить, что `fix/admin-panel` не изменил места из колонки «Сейчас» ([02](02-spec-deltas.md)). Быстрая
   проверка — `git log --since=2026-10-04 -- <файлы>`.
