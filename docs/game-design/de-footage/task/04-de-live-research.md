# 04 — Живое исследование купленной DE (R-01…R-15)

Предложение пользователя (2026-10-04, дословно): «Если данных по каким-то пунктам непонятно, я могу запустить
купленную игру, и ты там сам заисследуешь, используя компьютеры Use, необходимые механики и».

Документ закрывает то, чего не дало видео (README §10.1): кнопки под вебкой, пропуск, звук, точный шаг при 60 fps
и так далее. Исследование **не workflow**: computer use последователен, а игру запускает пользователь. Делается
в основной сессии, сериями.

## 1. Рамки

- **Запуск — только пользователь.** Он открывает Steam и Unmatched: Digital Edition (app 1677980) и входит в
  аккаунт сам. Пароли и аккаунт не трогаем.
- **Доступ.** `request_access` выдаётся на окно игры, а при записи через OBS — и на OBS. Браузер и терминалы для
  этого не нужны.
- **Только наблюдение через экран.** Запрещено:
  - читать, копировать и распаковывать файлы игры (EULA);
  - читать память, в том числе Cheat Engine, который установлен на машине;
  - перехватывать сетевой трафик.
- **Только оффлайн:** обучение, соло против ИИ, испытания. Онлайн-партии — только с отдельного согласия
  пользователя: в них участвуют другие люди.
- **Настройки игры** (скорость анимаций, боевая камера, LOWER HAND) меняем только с согласия пользователя в
  начале сессии. Исходные значения записываем и в конце возвращаем.
- **Computer use отпускаем после каждой серии.** Оранжевая рамка пользователю мешает. Серия — это пакет действий
  через `computer_batch`, затем скриншот и выход. Между сериями работаем только с записью.
- **GPU.** На время записи не запускать клиенты UE и бенчи (AGENTS.md «Unreal GPU load»). Перед стартом проверить,
  что их нет.

## 2. Запись и измерение

1. **Окно игры.** Узнать заголовок:
   `powershell -NoProfile -Command "Get-Process | ? MainWindowTitle | select Name,MainWindowTitle"`.
2. **Видео и звук.** Рекордер `C:/tmp/de-footage/tools/de_record.py` пишет окно игры 60 fps через NVENC
   (`video.mkv`) и системный звук через WASAPI loopback (`audio.wav`, пакет `soundcard` в venv). Метки старта
   кладутся в `sync.json`. Проверен 2026-10-04: h264 60 fps, выход с кодом 0.

   ```bash
   C:/tmp/de-footage/tools/venv/Scripts/python C:/tmp/de-footage/tools/de_record.py "<заголовок окна DE>" C:/tmp/de-live/<дата>/session-01
   ```

   Запуск — в фоне. Стоп — создать файл `STOP` в папке сессии; процессы не убивать.
3. **Сведение звука.** В системе нет «Stereo Mix», поэтому ffmpeg звук игры не пишет — только рекордер.
   - Сдвиг звука к видео калибруется по клику в интерфейсе: звук клика против кадра, где курсор нажимает.
     Точность ±17 мс.
   - Заголовок окна передавать латиницей: кириллица в bash ломается (cp866).
4. **Измерение.**
   - Указать видео: `C:/tmp/de-footage/work/video.txt` → путь к записи.
   - Ленты: `python C:/tmp/de-footage/pipeline/burst.py strip T0 T1 60 6 400 OUT.jpg [w:h:x:y]`; 1 тайл = 16,7 мс.
   - Команды `segs` и `motion` работают только для ролика YouTube, на записи их не использовать.
5. **Результат:**
   - `docs/game-design/de-footage/live-<дата>/README.md` — по пункту R на раздел: что сделано, что увидели, числа,
     время в записи, вывод для D-DE / SD;
   - `timings-live.csv` — колонки как в `../timings.csv` плюс `source=live60`;
   - кадры и записи — только локально в `C:/tmp/de-live/`, в репозиторий не кладём.

## 4. План сессии

Около 60–90 минут времени пользователя. Он нужен на старте (запуск, вход) и на финальной арт-сверке.

1. **Подготовка, ~5 мин:**
   - пользователь запускает игру;
   - проверка отсутствия клиентов UE;
   - заголовок окна, устройства звука;
   - старт записи;
   - запись исходных значений настроек.
2. **Серия 1, ~20 мин — решения пользователя:** R-14, R-02, R-04, R-13. После серии computer use отпустить и
   прогнать замеры по записи.
3. **Серия 2, ~20 мин — HUD и подача:** R-01, R-05, R-07, R-09, R-08.
4. **Серия 3, ~15 мин — частные случаи:** R-06, R-10, R-11, R-15, R-03.
5. **R-12 (звук)** идёт сквозной записью во всех сериях, если звук пишется. Иначе — отдельная серия с OBS.
6. **Закрытие:**
   - вернуть настройки;
   - остановить запись и ffmpeg (по командной строке, не по имени);
   - отпустить computer use;
   - оформить `live-<дата>/README.md` и `timings-live.csv`;
   - обновить [01-decisions.md](01-decisions.md) и [02-spec-deltas.md](02-spec-deltas.md) там, где данные изменили
     вывод: пометка «R-xx», старое значение не стирать.
