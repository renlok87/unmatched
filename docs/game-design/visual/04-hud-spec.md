## 1. Экраны

Общее для всех экранов:
- Слои снизу вверх: сцена → HUD партии → экран (вуаль) → модаль → тосты → оверлей связи → курсор. Экраны маршрута
  (BOOT → LOGIN → LOBBY → ROOM → загрузка → GAME) сменяют друг друга, стек не растёт.
- Фон BOOT…ROOM и загрузки — живая сцена Marmoreal K1 без фигур под `panel.veil` 0,6, без размытия (ВР-75). PAUSE и
  GAMEOVER — над текущей партией под той же вуалью.
- Переход между экранами — проявление 250 мс (reduced motion — 100 мс). Звук экрана — по реестру звука; здесь только
  ссылка на id ([03-sound-registry.csv](../audio/03-sound-registry.csv)).
- Безопасные поля: контент не ближе 24 su к краю (в классе S — 16 su), кнопки — не ближе 32 su.
- Единицы: su. Колонка «1080p» — холст 1920×1080 su (1 su = 1 px). Колонка «720p» — холст 1707×960 su, 1 su = 0,75 px
  (ВР-62). Класс S — правила сжатия в §1.6.
- Esc: закрыть верхнюю модаль → снять выбор → открыть PAUSE. Разрушительное действие всегда через подтверждение.
- Каждый экран пишет `SHOT widget id=<UI-ID> …` при съёмке (§7.1).

## 3. Общие состояния

### 3.1 Кнопки: 6 состояний

Обычная и главная кнопка — 02 §4.3 (normal, hover, pressed, disabled, focus, selected). Высоты: 48 su (главные и в
модалях), 40 su (в панелях), 32 su (чипы). Ширина — по тексту + 2 × 16, минимум 120 (кнопки-диски — 80).
- В окне одна главная кнопка.
- Недоступная кнопка всегда объясняет себя: подсказка `why.*` через 300 мс наведения и CUE-004 при нажатии
  (UI-INP-011). Молча отключённых кнопок нет.
- Нажатие — на отпускании над тем же элементом; удержание 0 и 50 мс засчитываются (n ≥ 20 → 0 потерь, DE-014).
- Отправленная команда: кнопка «Отправлено…» с курсором «занято» до ответа (V-10).

### 3.2 Курсоры (ВР-46, 02 §4.4)

- Обычный — везде; указатель — кнопки, карты, свои фигуры, подсвеченные клетки; недоступно — недоступный элемент
  вместе с `why.*`; занято — команда в полёте (песок 1500 мс, reduced — статичен). Текстуры `T_Cursor_*` 32 px, ×1 и ×2.
- Системный курсор скрыт; курсоры — software cursors `UGameViewportClient::SetSoftwareCursorWidget` с `UUmCursor`.

### 3.3 Загрузка и скелеты

- Ожидание > 300 мс показывает индикатор: спиннер 32 / 48 (8 ступеней по 125 мс, reduced — 250), прогресс 480×8,
  скелет строк (`panel.bg.inset`, пульс прозрачности 0,6 ↔ 1,0 за 900 мс, reduced — статично).
- Скан карты грузится: рамка и текст сразу, спиннер 32 на месте скана.
- Аватар грузится: монограмма до появления PNG.

### 3.4 Фокус и клавиатура

- Порядок фокуса в GAME: ACTIONS → HAND → PENDING → COMBAT (кнопки защиты) → DECKS → TOP. Tab циклит свои фигуры
  только при фокусе на поле (UX UI-INP-009).
- Фокус видим только при навигации клавиатурой (кольцо `card.glyph` 2 su). Мышь фокус не рисует.
- Виджеты HUD не забирают игровые клавиши: `GameAndUI`, без захвата клавиатуры (HUD-RULES П7); S09 key-probe даёт те же
  строки `S09PROBE`.

### 3.5 Reduced motion (UI-ACC-006, 02 §11.2)

- Движение UI — только прозрачность ≤ 100 мс. Масштабы, подъёмы, полёты карт — мгновенно.
- Кольцо хода — статичный обод; трекер — без `fill`, сразу итог; сердце — смена значка без пульса и ореола.
- Баннер 100 мс; тосты без подъёма; «−N» без подъёма, 450 мс.
- Пропуск удержаний боя работает; удержания чтения остаются.

### 3.6 Масштаб UI 75–150 %

- `ApplicationScale` = UI-ACC-001 поверх DPI-кривой ВР-62. При 720p ползунок от 100 %.
- Класс раскладки (ВР-H01) пересчитывается при смене окна и масштаба; переключение без перезапуска.
- Поле и мировые значки масштаб UI не меняет; тег и «−N» — меняет (это экранные виджеты).
- Обязательная проверка: 1920×1080 при 75 / 100 / 150 % и 1280×720 при 100 / 150 % (§7.2).

### 3.7 Контраст

- Текст ≤ 16 su — ≥ 4,5 : 1 к своему фону; текст ≥ 24 su Bold и значки — ≥ 3 : 1 (02 §3.5).
- Текст на бирюзе — только `card.glyph`. `state.error` текстом — только ≥ 24 su (заголовок «ПОРАЖЕНИЕ»).
- Текст на сцене без капсулы или панели запрещён (субтитры, «−N», тег — в капсулах).
- Замер G-READ на кадрах обеих досок (§7).

### 3.8 «Не только цвет» (02 §11.4)

| Сообщение | Второй канал в HUD |

| чей ход | статус «ВАШ ХОД» / «ЖДЁТ» и баннер, не только кольцо |

## 4. Дерево WBP и C++-базы

### 4.1 Правила

- Панель = класс (П1): C++-база `UUm<Имя> : UUserWidget` в `Source/Unmatched/S08/UI/` с `BindWidget`, WBP-потомок в
  `/Game/S08/UI/<группа>/` (ВР-H14). Логика видимости и текста — в C++ и моделях S09, не в графе WBP.
- Один вход данных на блок: `ApplyModel(const F<Модель>&)` (П1). Обновление только по событию применённого снапшота
  или тика постановки (П2); биндингов свойств и тика ради данных нет. Пересоздания дерева нет: пулы виджетов.
- У базы есть `BuildDefaultTree` (как у `US08ArtPlateWidget`): без WBP блок собирается кодом с теми же именами
  (тесты без ассетов, свежий worktree).
- Цвета, кегли, отступы, радиусы, длительности — только из `UUmHudTheme` (П3). Литералов нет (G-TOKENS).
- Каждая база реализует `CollectShotLines(TArray<FString>&)` для гейта (П4).
- WBP, тема и StringTable — `git add -f` или генерация скриптом (П9).

### 7.3 Что считается приёмкой

- **Технически:** G-TOKENS, G-WIDGET, G-ICON, G-CUE зелёные; UE-тесты `Unmatched.S08.Hud.*`, `Unmatched.S09.*` и

  «Лично» — только с цитатой пользователя.
- **G-LOOK:** доска настоящая, задник верный для карты, шесть фигур v2 на каждом кадре.

### 7.4 Открытые риски

- **ENV-U16.** Marmoreal по умолчанию ещё P5c (3D). Замеры `FIELD` и контраста HUD к заднику взяты с `-ConceptPaste`;
  после ENV-U16 переснять наборы A и C на Marmoreal.
- **Доска в ROOM.** Мутации смены доски нет; ВР-38 в части «выбор доски в ROOM» выполняется только видом до серверной
  добавки (ВР-H11).
- **RU-названия карт King Arthur** в скрапе пустые: бюджет длины RU для его колоды не проверен.
- **Сканы и аватары** — WebP; конвертация в PNG и импорт в пак (ВР-47, ВР-51) — до шага H7.
- **Параллельные сессии** правят `S08FlowGameMode*.cpp`: каждый шаг §5.2 — короткая ветка и `safe-integrate.sh`; при
  конфликте точки подключения переносятся в новый файл `S08FlowGameModeUmHud.cpp`.
- **Класс S при 1138×640 su** плотный: если карта руки 120 su не держит веер из 10 карт без перекрытия названия, шаг
  веера падает до 72 su и название видно только по наведению.
