## 1. Контракт стиля «мрачноватая атмосферная диорама» (D-02)

`РЕШЕНИЕ D-02`: стилизованная объёмная диорама, контрастный направленный свет, холодные тени + тёплые акценты фонарей, фактуры камня/старого дерева. Ниже контракт в воспроизводимых признаках — каждый признак проверяем по превью/в сцене, «красиво» не является признаком.

### 1.1. Таблица признаков контракта

| # | Признак | Значение (ПРЕДЛОЖЕНИЕ) | Как проверить |
|---|---|---|---|
| С-1 | Пропорции персонажей | Стилизация ~5–6 голов в высоте фигурки; укрупнённые голова/руки/оружие (оружие ×1.2–1.4 от «реалистичной» длины) для читаемости силуэта с фиксированного угла | Чёрный силуэт фигурки на белом с обзорной камеры различим без цвета (контрольный кадр К-1, §3); превью в карточке модели (`04`) |
| С-2 | Степень стилизации | Условная «окрашенная статуэтка»: формы упрощены до больших плоскостей, мелкая детализация — только там, где работает на силуэт; без фотореалистичных пор/тканевых микродеталей | Силуэт-тест + wireframe-превью в сдаче ассета (`04` §5) |
| С-3 | Материалы | Матовый «окрашенный» look: камень (булыжник, кладка), старое дерево (настил, ящики), металл только как акцент (фонарь, оружие); roughness ≥ 0.6 на ≥ 90 % площади; metallic = 0 почти везде, металл — редкий акцент | Отчёт материала (скрипт `mesh_report.py`, `04` §4.3); визуально — отсутствие «зеркальных» бликов на превью |
| С-4 | Текстурная подача | Hand-painted BaseColor, светотень запечена в albedo умеренно; запрещены фотореалистичные PBR-текстуры высокого разрешения и скан-материалы | Ревью текстур в карточке ассета |
| С-5 | Палитра теней | Холодные сине-серые: камень #2A3038–#3A424C, булыжник #4A525C–#5A6470, старое дерево #4A3A2C–#5C4838 | Пипетка по контрольному кадру К-1 |
| С-6 | Тёплые акценты | Фонари/окна фасадов: #FFB45C–#FFCE8A; ≤ 6 тёплых источников на сцену | Счётчик источников света в сцене |
| С-7 | Цвета зон поля | Насыщенные, но различимые НЕ только цветом: blue #3D7BDB, green #3FA65C, yellow #E0B23C, purple #8A56C6, red #D9483F — код из `boardState`/`zones` (`ФАКТ`, `docs/backend-api/05` ч. B, маппер `ZONE_ALIASES`); различение — цвет + форма обводки + пиктограмма (§6, семейство UI-ICON-ZONE) | Кадр К-1 при симуляции дальтонизма (deuteranopia) — зоны остаются различимы формой/пиктограммой |
| С-8 | Свет | Один key directional «лунный» холодный (#B8C8E0, интенсивность умеренная), динамические тени только от него; тёплые point-акценты фонарей — без теней, малый радиус | Настройки сцены; счётчик shadow-casting источников = 1 |
| С-9 | Контраст слоёв | Игровой слой (клетки, подсветки, маркеры, фигурки) на +0.3..+0.7 EV ярче и насыщеннее декоративного (фасады, декор); декор в холодных приглушённых тонах | Замер яркости по маскам слоёв на кадре К-1 |
| С-10 | Фон за доской | Тьма + экспоненциальный туман + виньетка по краям кадра; «поднос» диорамы обрывается рваным краем (камень/скала), дальше — ничего | Кадр К-1: за границей подноса нет читаемых объектов |
| С-11 | Цвета команд (2 игрока) | Тёплый золотой #E8C06A (игрок 1) и холодный серебристо-голубой #9FC2D8 (игрок 2) — только на подставках/кольцах/маркерах; тонально отличаются от зонных цветов (зоны насыщеннее и живут на плоскости доски) + дублируются формой: разный профиль подставки (круг vs шестигранник) | Кадр К-1: кольца команд различимы в градациях серого |

`ПРЕДЛОЖЕНИЕ` (зафиксировать): палитра С-5..С-7, С-11 — стартовая; финальные значения фиксирует контрольная сцена (этап 4 «Эталон качества», бриф §14) и `02-ux-ui-spec.md` (дизайн-токены HUD обязаны использовать те же значения).

### 1.2. Почему это достижимо на среднем ПК (D-07)

`РЕШЕНИЕ D-07`: GTX 1060/1660, RX 580, 1080p @ 60 FPS. Следствия контракта:

- **Без Lumen и Nanite по умолчанию** — `ПРЕДЛОЖЕНИЕ`, зафиксировать: сцена маленькая (одна доска ≤ 30 клеток, ≤ 6 фигурок), статическое освещение решается одним directional + несколькими point без теней; Nanite не нужен при бюджетах полигонов из `04` §1.
- Тени: только key directional (С-8); point-акценты фонарей — unshadowed.
- Туман — Exponential Height Fog (дешёвый), виньетка — постэффект в постпроцесс-материале.
- Деградация на минималках: первым отключается смягчение теней directional и часть декора (ASSET-DECOR-KIT-001 — ящики/фасады, кроме фонаря), затем плотность тумана; игровые подсветки и маркеры не отключаются никогда (бриф §13: «игровые подсветки и читаемость не должны исчезать на минимальных настройках»).
- Кадровый бюджет: целевые значения (frame time, VRAM) фиксируются контрольной сценой на целевом железе — все числа этого файла предварительные.

## 2. Камера (D-10)

`РЕШЕНИЕ D-10`: фиксированный угол, перспективная камера, зум колесом, без вращения и кино-вставок в MVP. `РЕШЕНИЕ D-13`: осознанное отклонение от прежнего плана `docs/unreal/06` (ортографическая камера сверху, OrthoWidth = max(W,H)·100·1.15, зум ±20 %) — прежние планы были «плоские мини-арты + ортокамера»; в диораме (D-02) нужна перспектива. Значения ниже — `ПРЕДЛОЖЕНИЕ`, финализируются контрольными кадрами §3.

| Параметр | Значение (ПРЕДЛОЖЕНИЕ) | Комментарий |
|---|---|---|
| Проекция | Перспективная | `РЕШЕНИЕ` D-10/D-13 |
| Модель задания объектива | **FOV (горизонтальный), фиксированный = 35°** | Выбрана одна модель — FOV; фокусные расстояния нигде не используются как параметр (бриф §8.2: не смешивать). UE-камера: горизонтальный FOV по умолчанию |
| Стартовый наклон Pitch | −55° (рабочий диапазон проверки −50…−60) | Компромисс: объём диорамы (−50) vs читаемость дальней строки клеток (−60) |
| Стартовый поворот Yaw | −90° (камера с «южной» стороны, взгляд вдоль −Y вглубь доски; строка y=0 — дальняя) | Игрок сидит «снизу кадра», как в веб-клиенте (`_sources/facts-web-ux.md`: players[0] — локальный игрок снизу) |

## 4. Доска Cobble City как диорама

### 4.1. Слои (разделение по брифу §8.3)

| Слой | Что это | Источник истины | Кликабельность |
|---|---|---|---|
| L0. Логическая сетка | Клетки `{x,y}`, типы (normal/wall/obstacle/door/zone-line), `zones[]`, `doors`, `fog` | `ФАКТ`: `boardState` живой партии (`docs/backend-api/05` §A.2, `docs/backend-api/10` §5) | — |

| L4. Фон | Тьма, туман, виньетка, рваный край подноса ASSET-TABLE-BASE-001 | Чисто визуальное | Нет |

### 4.2. Правило: геометрия и позиции — только из boardState

- Стартовые позиции фигурок — из начального `GameState.fighters[].position` (`ФАКТ`: размещение серверное, «seat + офсеты, зажим в границы», `docs/backend-api/10` §5.5). Арт доски НЕ источник стартовых позиций.
- Зоны и их границы — из `cells[y][x].zones` (мультизонные клетки возможны: в коде 6×4 это (1,1) blue+green, (3,1) green+yellow, (1,2) purple+red — `ФАКТ` кода; в БД может быть иначе).
- **Геометрия НЕ подтверждена** (`ФАКТ`-противоречие: код 6×4=24 клетки vs проверка брифа через API 5×6=30 клеток; `00` §10 п.8, `_sources/facts-content.md`). Истина — `boardState` живой партии. Следствия:
  - модель ASSET-BOARD-COBBLE-001 `blocked` до проверки живой партией (запись в `06-asset-manifest.csv`);
  - серый вариант строится **параметрически из boardState** в UE (instanced-плитки по width/height/cells — идея из прежнего плана `docs/unreal/06`, статус ПЛАН, не реализация);
  - декоративный кит и поднос от геометрии не зависят и не блокируются.

### 4.3. Физическая коллизия декораций не создаёт правил

`ФАКТ`-правило (бриф §8.3 + `docs/backend-api/10` §5.1): проходимость определяют типы клеток L0. Декор L3 может визуально «стоять» на непроходимой клетке (wall/obstacle), но никогда не делает проходимую клетку непроходимой и наоборот; правила перемещения не меняются ради удобства 3D-модели. Клики по декору — игнор или tooltip, не игровое действие.

### 4.4. Правило перекрытий

- Фасады — только на дальней (северной, y-max) стороне подноса; высота ≤ 120 uu; не выше полутора клеток.
- Контрольный кадр К-1 обязан показывать **все** клетки доски, включая дальнюю строку; если фасад перекрывает клетку — он укорачивается или скрывается.
- При зуме ≥ 1.2× фасады дальней стороны плавно скрываются (fade до 30–40 % непрозрачности за ~200 мс) — чтобы К-2 показывал фигурку и клетку без «стены за спиной».
- Боковые фасады (восток/запад) допустимы только ниже уровня игровой плоскости (бортик подноса), ближняя (южная) сторона — без вертикального декора вообще (загородит обзор при Pitch −55).
- Фонарь — вертикальный акцент, размещается у угла подноса или на границе зоны, его свет не меняет читаемость клеток (тёплый, без теней, С-8).

### 4.5. Условности, принятые для Cobble City (ПРЕДЛОЖЕНИЕ)

- Двери/туман не моделируются: в Cobble City их нет по коду (`ФАКТ`, `docs/backend-api/10` §5.4: «стен/препятствий/дверей/тумана нет»); в `boardState` поля `doors`/`fog` присутствуют, но пусты. Прежний план `docs/unreal/06` тоже не рисовал двери/туман (ПЛАН, не реализация). Если живая партия даст непустые `doors` — серый вариант рисует простую плитку-заглушку с иконкой двери (семейство UI-ICON-ACTION), решение в `08-integration-decisions.md`.
- `isHighGround` — в механиках движка не используется (`ФАКТ`, `docs/backend-api/10` §5.1), визуально не моделируется в MVP.
- Мультизонная клетка: тонировка — доминирующая зона + составная обводка из двух цветов по двум дугам/сторонам + (при наведении) обе пиктограммы. Не только цвет (§6).

## 6. Контраст и читаемость обратной связи

Три обязательных состояния выбора различаются **формой + иконкой + цветом** (цвет никогда не единственный канал — бриф §7.3, доступность; D-08 не влияет, но принцип единый):

| Состояние | Форма (геометрия подсветки) | Иконка (семейство UI-ICON-ACTION) | Цвет (ПРЕДЛОЖЕНИЕ) |
|---|---|---|---|
| Можно ходить (достижимая клетка) | Сплошная мягкая заливка клетки 20–30 % + тонкое кольцо-обводка по периметру клетки | След/шаг (мелкая, по центру, при наведении) | Тёплый белый #F2E9D8 |
| Можно атаковать (допустимая цель) | Рамка-«прицел» из четырёх уголков вокруг клетки/фигурки, пульс ~1 Гц | Скрещённые мечи над целью | Красно-оранжевый #E05A3A |
| Ожидается выбор эффекта (pending MOVE/PLACE/CHOOSE_ONE — `ФАКТ`, `docs/backend-api/05` §A.6) | Пунктирная обводка зоны выбора + вертикальный маркер над фигуркой, которой нужен выбор | Жезл/вопрос | Фиолетовый #8A56C6 (совпадает с зоной purple по тону — обязательно дублируется формой пунктира и иконкой) |

- Недоступный выбор: короткая встряска курсора/фигурки + иконка «стоп» + текст причины (P2: «не ваш ход», «нет действия», «недостижимо») — см. `07-animation-vfx-audio.csv` (CUE-004) и `02-ux-ui-spec.md`.
- Выделенная своя фигурка: кольцо команды (С-11) + подсветка подставки; выбранная карта — рамка (UI-CARD-FRAME, состояние selected).
- Правила пакета эффектов (детализация — `07-animation-vfx-audio.csv`): feedbackDelay ≤ 200 мс (P3); блокировка ввода только для событий короче 1 с; всё пропускаемо; при reconnect старая очередь эффектов не проигрывается (только финальное состояние + короткий резюмирующий тик); сетевой результат не зависит от завершения анимации (P3/P4).
