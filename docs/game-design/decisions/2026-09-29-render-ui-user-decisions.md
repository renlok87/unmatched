## U-1. DX12 + Lumen сейчас

**Что решено.** Проект переходит с DX11/SM5 на DX12 с шейдерной моделью SM6 и включает динамическое глобальное освещение Lumen сейчас, до финальных K1–K3, а не после MVP.

**Что это значит технически (для исполнителя, меморандум R0.2).** `DefaultGraphicsRHI_DX12`; `+D3D12TargetedShaderFormats=PCD3D_SM6` при сохранённом `PCD3D_SM5` (фолбэк); `r.DynamicGlobalIlluminationMethod=1`; `r.GenerateMeshDistanceFields=1` (программный Lumen трассирует distance fields статики; пересборка всех static mesh); полная перекомпиляция шейдеров. Метод отражений (`r.ReflectionMethod`: Lumen или SSR) решением не задан — выбирается bench-замером.

**Чего решение не включает.** Nanite, Virtual Shadow Maps, MegaLights, Substrate пользователь не выбирал: остаются выключенными (`nanite == false` в отчётах импорта, `r.Substrate=0`, тени — CSM). Их включение — отдельные решения с замером. D-07 (целевой ПК: GTX 1060/1660, RX 580, 1080p @ 60 FPS) не меняется.

**Следствия.**
- Запекания нет и не будет: свет динамический (Movable), непрямой — Lumen. Поэтому AD-OPEN-12, AD-CNF-23 и Q-313 закрываются по умолчанию формулировкой «без запекания; key directional с тенью + point без теней + Movable SkyLight, непрямой свет — Lumen GI; UV1 в ассетах не требуется» (предложенный diff: [w4d-render-dx12-lumen.diff.md](../../art-pipeline/proposals/w4d-render-dx12-lumen.diff.md)). Формулировку 03 §1.2 «без Lumen и Nanite по умолчанию» и 08 §6.1 «без Lumen/Nanite» решение пользователя заменяет.
- Все packaged-кадры K1–K3, снятые на DX11 (волны 1–3), остаются диагностикой; финальный набор для GD-058 снимается на DX12 + Lumen с эталоном U-2 (меморандум: смена RHI обнуляет K1–K3). Отпечаток `RENDER fingerprint` каждого кадра записывает RHI, feature level и метод GI.
- Риск ACC-022 высокий (оценка меморандума, не замер): Lumen ≈ 8–10 мс из 16,7 мс на GTX 1060; пара клиентов по 30 FPS делит один GPU. На картах без SM 6.6 и 64-битных атомиков (часть драйверов RX 580 / GTX 1060) движок молча остаётся на SM5 — там Lumen нет, картинка отличается от принятой. Perf-gate ACC-022 требует замера на железе класса D-07 (AD-OPEN-20 открыт).
- DX12: доступен PSO precaching (в D3D11 его не было); первые показы эффектов всё равно прогреваются (контракт CUE-слоя). На DX12 `gpuMs` вычитает простой (bubbles removal), но GPU-критерии прототипов по-прежнему берутся из ProfileGPU без лимита FPS.
- Стиль B (С-4: светотень умеренно в albedo) и Lumen могут посчитать свет дважды — вопрос к автору (предложенный diff 03).
- AGENTS.md (раздел «Unreal GPU load») описывает DX11 и `DefaultGraphicsRHI_DX11`; его правка — решение пользователя или оркестратора, этим журналом файл не меняется.

## U-2. Эталон приёмки — High

**Что решено.** K1–K3 (GD-058, QA-010) и замер ACC-022 принимаются на уровне scalability **High**: все группы `sg.* = 2`, 1920×1080, `r.ScreenPercentage=100` (меморандум §1 п.1; при `sg.ResolutionQuality=0` авто-кривая дала бы ≈73 %).

**Следствия.** Packaged по умолчанию стартует на Epic (`sg.* = 3`), поэтому High задаётся явно (DefaultScalability.ini / GameUserSettings / командная строка) и проверяется по `RENDER fingerprint`; кадр без отпечатка `sg.*=2` не засчитывается. Качество Lumen на High ниже, чем на Epic, — эталон фиксирует именно его. Нижние уровни (@0/@1) не должны убирать тень key и игровую информацию (C-8, бриф §13) — DefaultScalability.ini (оркестратор, §1 п.1). Нужен ли игроку пресет в UI-SCR-PAUSE — открыто.

## U-3. TeamColor на базе, кольце и одежде

**Что решено.** Вариант (b) AD-CNF-58: цвет команды несут подставка и кольцо (С-11) **и** одежда фигуры (маска TeamMask на плаще, накидке и т. п.). Полный multiply всей фигуры (как у текущей Medusa) — нет.

**Следствия.** Каждому герою нужна текстура TeamMask (выход стадии atlas; у Arthur маска по HSV уже есть, у остальных — нет; ≈ 0,5–1 дня арта на ассет по оценке меморандума). Мастер `M_UM_Figure` читает TeamColor из Custom Primitive Data 0–3 и применяет его по маске; база — `M_UM_BaseMarker` с теми же CPD. Цвета — hex С-11 (Q-304 открыт), в материал только через `FLinearColor::FromSRGBColor` (AD-OPEN-39, предложенный diff). Формулировка С-11 «только на подставках/кольцах/маркерах» и строки 17 меняются предложенным diff [w4d-teamcolor-colorspace.diff.md](../../art-pipeline/proposals/w4d-teamcolor-colorspace.diff.md). Проверка K1 в градациях серого и deuteranopia остаётся обязательной: одежда не заменяет различение профилем подставки.

## U-4. HUD — гибрид UMG сейчас

**Что решено.** Пользовательские блоки HUD и экраны переводятся на UMG уже сейчас (C++-база с `BindWidget` + WBP), Slate остаётся для операторской панели F10, трасс и проб. Меморандум предлагал «правила сейчас, порт в S12 (GD-047)». CommonUI в MVP не вводится.

**Следствия.** Правила «панель = класс», токены стиля, гейты по трассам `SHOT widget`, StringTable/`why.*` — [HUD-RULES.md](../../unreal/contracts/hud/HUD-RULES.md) (для W4-C). Пиксельные гейты S09/S10 переводятся на трассы до переноса блоков (≈ 2–4 дня перепроверки по R3.0). Порт 11 блоков и 9 экранов ≈ 6–10 DEV-дней. Строка 17 §5 «UMG-HUD партии в UE нет» и план 13 (S12) — предложенный diff [w4d-hud-umg-rig-plan.diff.md](../../art-pipeline/proposals/w4d-hud-umg-rig-plan.diff.md).
