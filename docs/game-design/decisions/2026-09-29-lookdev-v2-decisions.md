# Журнал решений look-dev v2: герои на библиотеке материалов UM v1 (2026-09-29)

Журнал волны LD. Пользователь делегировал решения исполнителям («делай все без меня»). Здесь каждая задача волны
фиксирует свои решения отдельным разделом. Решения пользователя, на которые опирается волна:

- DX12 + Lumen;
- эталон качества High;
- TeamColor и на одежде, но красятся только классы ткани, не золотая кайма (найдено в 5c-A);
- гибрид UMG.

Их журнал — [2026-09-29-render-ui-user-decisions.md](2026-09-29-render-ui-user-decisions.md). Эталон сравнения героя —
концепт `art/imagegen/hero-quality-v1/<hero>/`, а не прошлая итерация. Библиотека материалов —
[docs/art-pipeline/material-library/README.md](../../art-pipeline/material-library/README.md).

## LD-merlin-blender — Merlin: MatID, LUT, UV1 (headless Blender)

Отчёт: [docs/art-pipeline/merlin-lookdev-v2.md](../../art-pipeline/merlin-lookdev-v2.md). Прогон:
`art/pipeline-candidates/ASSET-MERLIN-001/20260929-h2-lookdev/`. Статус: технически собрано и измерено в Blender, в UE не
импортировано.

| # | Решение | Почему |
|---|---|---|
| LDM-1 | Золотая вышивка, звёзды и кайма = класс `silk` (ткань, Cloth 0.6), **не металл**. В LUT Merlin у него `teamDyeAllowed = 0`, roughness 0.42 [0.32, 0.58], sheen в цвет нити (tint 1.0) | Правило пользователя: TeamColor только на ткани, не на золотой кайме. Нить с металлической обвивкой глаже шерсти, блик золотой через Fuzz Color. TeamMask на вышивке и так = 0 — двойная защита |
| LDM-2 | Мантия, капюшон, рукава = `wool_coarse` + TeamColor. Пояс, сапоги и кожаная обмотка бороды = `leather_worn` с `teamDyeAllowed = 0`. Пряжка = `bronze`. Посох и когти навершия = `wood`. Лицо и кисти = `skin`. Подставка = `stone_base` | Зоны из масок H2.1 (`materials_h21`) и частей Tripo. Обмотку бороды отделяет от кожи правило «насыщенный коричневый ниже z 0.70 м» (замер) |
| LDM-3 | Кристалл и борода — MatID 0 (`legacy_bake`). Кристалл: запечённый глянцевый диэлектрик (roughness 0.12–0.18), BC подогнан к концепту. Борода: ORM.G переназначена в матовый диапазон (p50 0.62 → 0.75) | В v1 нет классов «самоцвет» и «волосы», свободных индексов нет. Specular сапфира (≈ 0.96) без класса не задать — вопрос v1.1 |
| LDM-4 | MatID Merlin — 2K (размер рантайм-атласа), а не 1K из README §3 | При 1K 7.5 % текселей вышивки уходят в шерсть, границы идут ступенями 2 × 2. Цена — +3 МБ G8 |
| LDM-5 | MatID = argmax весов классов без порога «вес < 0.5 → 0» (README §3 п.2) | Порог вставил бы legacy-пиксели (roughness шерсти 0.96) на стыках трёх классов |
| LDM-6 | BC подгоняется к концепту по зонам: `gain = chroma × luma`. Chroma — тон и насыщенность концепта, [0.6, 1.6]. Luma — отношение яркостей / экспозиция k, зажим [0.75, 1.35]. Модель мерится в Blender тем же светом и кадром, что концепт, зоны — по ID-проходу | Концепт — освещённый рендер: яркость в нём несёт свет (одна кожа: лицо 0.84–1.18, кисти 1.71–1.78), тон — надёжнее. После подгонки тон всех зон в пределах 2.4° от концепта |
| LDM-7 | Строка 0 LUT у диэлектриков Merlin = медиана BC класса после подгонки (справочно: режим bake-clamped читает BC-текстуру). **`Ymed_class_hero` металла — строка 7.R** его столбца | README §4 требует Ymed в LUT, но ячейки не даёт. У металла зажим яркости не используется. Предложение мастеру `M_UM_Figure` v2 |
| LDM-8 | UV1 = UV0 острова × масштаб до метров, центр острова в (0, 0), **без поворота**. Исключение — острова дерева: они повёрнуты главной осью вдоль U (волокно тайла) | Подобие без поворота сохраняет касательный базис UV0: нормаль детали смешивается без доработки шейдера. У дерева базис повёрнут — в UE нужна касательная UV1 по производным или принять повёрнутый рельеф. Центровка даёт \|UV1\| ≤ 0.2 м: шаг 16-битных UV 0.12 мм, Full Precision не нужен |
| LDM-9 | EdgeMask (выпуклость по запечённой нормали) — в TeamMaskRGBA.A (в H2.1 было 255) | Свободный канал: лишнего сэмплера нет (README §3/§8). Рёбра low-poly формы в нормали не записаны — ограничение |
| LDM-10 | Геометрия, риг и веса берутся из `work/h2-rig.blend` H2.1 (append) и сверяются с FBX H2.1 read-back. Модуль получил режим lookdev (стадии `ld_*`, свой `run_dir`), стадии H2 не тронуты | Задача запрещает менять риг и геометрию. Совпадение проверено: полигоны, вершины (Δ 0), кости, веса (Δ 0) |

## LD-medusa-blender — Medusa: MatID, LUT, UV1, тона по концепту (headless Blender)

Отчёт: [docs/art-pipeline/medusa-lookdev-v2.md](../../art-pipeline/medusa-lookdev-v2.md). Прогон:
`art/pipeline-candidates/ASSET-MEDUSA-001/20260929-h2-lookdev/`. Статус: технически собрано и измерено в Blender, в UE не
импортировано.

| # | Решение | Почему |
|---|---|---|
| LDD-1 | Платье и накидка = `linen` + TeamColor (Cloth 0.7, specular 0.4). TeamMask.R обнулён вне класса ткани: кайма, пояс и пряжки = `gold_antique`, не красятся | Правило пользователя (5c-A). В концепте складки матовые, с мягким цветным отблеском — это sheen льна, а не глянец шёлка. «Серое» платье H2.1 — белый specular 0.04 на тёмном альбедо, его убирает Cloth |
| LDD-2 | Ремни сандалий (металл частей 4/5 ниже z 0.104 м, части 14–16) = `leather_worn`, BC/roughness из запечённого Tripo до прохода металла H2.1, metallic 0 | В концепте ремни — коричневая матовая кожа, H2.1 сделал их золотом. Золотые заклёпки потеряны — остаток |
| LDD-3 | Змеи, волосы, глаза, губы = `legacy_bake` (MatID 0). Змеи затемнены по концепту множителем, который действует только на оттенок 38–110° | Классов «чешуя»/«волосы» в v1 нет. `skin` с порами на чешуе неверен. Гейт по оттенку не даёт затемнить губы и брови |
| LDD-4 | Тона классов подгоняются к концепту по зонам ID-прохода: множитель = (концепт / k) / кадр Blender, 2–3 итерации, числа в профиле (`grade.gains`). Экспозиция k — **по платью** (самая большая зона, TeamColor), не взвешенное среднее всех классов | Взвешенное среднее (0.72–0.74) тянут камень, кожа и дерево, которые в концепте вдвое темнее. Оно осветлило бы кожу персонажа на 40 %. Якорь на платье сохраняет отношения тонов «к платью» как в концепте |
| LDD-5 | Пол альбедо не нарушается: у тёмных классов медиана ≥ 1.2 × пол пресета (0.024). Полости сжимаются «носком» `lo + Y²/(4·lo)`, а не срезаются на пол | Камень, дерево и ремни концепта темнее физического пола 0.02: остаток — свет концепта (подставка в тени), не альбедо. Жёсткий зажим сделал бы 76 % камня плоским |
| LDD-6 | LUT героя — **в формате мастера v2** (`build_ue_inputs.py`: DDS 16 × 16 RGBA16F, `ymedClassHero` в строке 8) плюс файл переопределений `--overrides`. Не EXR 16 × 8 | Мастер `M_UM_Figure` v2 (UM_V2_Core) читает строки 0–9 этой раскладки. Один генератор LUT на всех героев. Merlin (LDM-7) положил Ymed в строку 7.R EXR 16 × 8 — форматы нужно свести к v2 |
| LDD-7 | F0 золота Medusa в LUT = медиана подогнанного BC класса (0.863, 0.451, 0.198), Y 0.52; max канала ≤ 0.92 | «Античное» золото концепта темнее и краснее табличного (1.0, 0.766, 0.336). Правило металлов (Y ≥ 0.45) соблюдено |
| LDD-8 | UV1 = (UV0 − центр острова) × метры/UV, без поворота и зеркала | Базис касательных UV1 = UV0. Центровка: \|UV1\| ≤ 0.152 м, шаг half-float ≤ 0.12 мм — Full Precision UVs не нужен. У подставки в UE выключить Generate Lightmap UVs (иначе перезапишет UV1) |
| LDD-9 | EdgeMask — отдельная текстура `T_Medusa_H2LD_2K_Edge.png` (R8), а не канал TeamMask | Мастер v2 читает отдельный параметр `EdgeMaskTexture` (линейный grayscale). TeamMask остаётся как в H2.1 |
| LDD-10 | MatID 4K мастер + 2K рантайм (не 1K из README §3). Metallic в ORM — бинарный по классу | При 1K гаттер 8 px 4K становится 2 px, а тонкая кайма уходит в ткань. Бинарный metallic — правило библиотеки; в H2.1 у дерева лука под размытой маской было до 176/255 |
| LDD-11 | Режим `--mode lookdev` в `h2_bake` читает готовый прогон H2.1 по sha256 и пишет новый каталог. Геометрия и риг берутся append из `sk_authored.blend` и сверяются с FBX H2.1 read-back | Стадии H2 не тронуты. Совпадение: позиции и UV0 каждого loop (Δ 0), кости, треугольники, лицо +X. Повтор сборки даёт те же байты |

## LD-master — мастер `M_UM_Figure_v2` в UE

Отчёт: [docs/art-pipeline/material-library/m-um-figure-v2.md](../../art-pipeline/material-library/m-um-figure-v2.md).
Ассеты: `/Game/UM/Materials/v2/`. Статус: технически импортировано и измерено в живом редакторе (DX12/SM6 + Lumen,
High). SM5 и SM6 cook прошли без ошибок. v1 не тронут (sha256).

| # | Решение | Почему |
|---|---|---|
| LDV-1 | LUT = **16 × 16 RGBA16F** в DDS, а не 16 × 8 EXR. Строки 0–7 — как в README §4. Строка 8.R = `ymedClassHero` (0 = нет данных, модуляции нет). Строка 9 = тон полостей кожи (rgb) и сила. Строки 10–15 — резерв. Один генератор на все LUT: `build_ue_inputs.py [--hero --overrides]` | README требует Ymed в LUT, но ячейки для него не даёт. Строка 7.R — это luminance min: класть туда Ymed (как в LDM-7) нельзя. Merlin пересобирает свою LUT этим генератором, Medusa (LDD-6) уже в этом формате |
| LDV-2 | Массивы деталей импортируются из DDS 2D array прямо в Texture2DArray (DetailN — BC5, DetailRMH — BC7, мипы из источника). Ассетов-срезов нет. Сами DDS не коммитятся: скрипт пересобирает их байт-в-байт | Вдвое меньше данных в репозитории (~52 МБ вместо ~100) и нет 32 лишних ассетов |
| LDV-3 | Правки тайлов делаются при сборке срезов, PNG v1 не меняются. Золото и камень: нормаль из собственной высоты, RMS 0.045 и 0.035. У всех срезов убран наклон нормали. R процедурных тайлов центрирован на 0.5. Латунь остаётся плоской | Известные мелочи v1. Числа рельефа — арт-решение, калибруются в look-dev |
| LDV-4 | Деталь по умолчанию — трипланар по `PreSkinnedLocalPosition` (VertexInterpolator), UDN-смешивание. UV1 в метрах включается static switch `UseUV1Metres`. Касательная UV1 строится по производным | У героев пока нет UV1. Трипланар до скиннинга не плывёт в анимации. Касательная по производным снимает ограничение «UV1 без поворота» (LDM-8, дерево вдоль U) |
| LDV-5 | Нормаль детали переводится в касательное пространство героя по базису UV0 из экранных производных: X = ∇u0, Y = +∇v0 | Совпадает с `Transform(Local → Tangent)` движка: ошибка 0.3 уровня против 185.6 у противоположного знака. Не зависит от скиннинга |
| LDV-6 | Cloth задаётся по пикселям: From Material Expression + `If(IsCloth)` → узлы ShadingModel. Выходы идут через MakeMaterialAttributes (ClearCoat = Cloth, SubsurfaceColor = Fuzz). Fuzz считается от итогового альбедо после красителя. Substrate выключен | Python-перечисление 5.8 не даёт подключить `MP_CustomData0` и `MP_ShadingModel` напрямую. Блик ткани в цвет команды |
| LDV-7 | TeamColor = TeamMask.R × `teamDyeAllowed` класса из LUT: кожа ×2, шерсть, лён, шёлк, перья. Класс 0 (legacy) ведёт себя как v1 — только TeamMask. Металлы, камень, дерево и кожа персонажа не красятся ни при какой маске | Правило пользователя (5c-A). Проверено: 16/16 классов. Кайма-«золото» на ткани в LUT героя получает свой флаг (LDM-1) |
| LDV-8 | EdgeMask — отдельный параметр `EdgeMaskTexture` (R, linear grayscale). По умолчанию `T_UM_Mask_Black`: износа нет. Износ гасится в полостях (× smoothstep AO) | `TeamMaskTexture` в v1/v2 — сэмплер LinearGrayscale: RGBA-маска с EdgeMask в A (LDM-9) сломала бы умолчания v1. Merlin перед импортом выносит A в отдельную текстуру; у Medusa так уже сделано (LDD-9) |
| LDV-9 | Имена параметров, умолчания и раскладка CPD v1 сохранены. Класс 0 повторяет граф v1 | Перевод героя = смена родителя MI + MatID/LUT/EdgeMask. Регрессия: G-buffer v1 и v2 на Merlin H2 совпадает |
| LDV-10 | `MetresPerLocalUnit` = 0.01 (1 uu = 1 см; фигуры импортированы ×100, высота ~62 uu) | Пересчёт tilesPerMeter из пресетов без правки чисел |
| LDV-11 | В свете Cobble яркие металлы упираются в потолок, воронёная сталь получает luma 134. F0 классов не трогаем; тёмная сталь Arthur — через LUT героя или контраст окружения (свет доски, 5b-R). Материал проверяем кадрами −1.5 EV, приёмку снимаем в Cobble | Купол SkyLight × 11.2 — равномерно яркое окружение для отражений. Физика материала верна: это видно на кадре −1.5 EV |

## LD-merlin-ue — Merlin в UE на `M_UM_Figure_v2`, look-dev против концепта

Отчёт: [docs/art-pipeline/merlin-lookdev-v2.md](../../art-pipeline/merlin-lookdev-v2.md), раздел «UE». Прогон CLI:
`art/pipeline-candidates/ASSET-MERLIN-001/20260929-h2ld-ue-import/`. Ассеты: `/Game/PipelineCandidates/Merlin/H2LD`.
Статус: технически импортировано и измерено в живом редакторе (DX12/SM6 + Lumen, High, свет Cobble).

| # | Решение | Почему |
|---|---|---|
| LDMU-1 | LUT Merlin пересобирается одним генератором (`build_ue_inputs`) в формат мастера v2: 16 × 16 DDS, `ymedClassHero` в строке 8. Работает конвертер `lookdev_ue_inputs.py`, слои в порядке «пресеты → переопределения Blender-стадии (`ld-lut.json`) → слой UE look-dev». EdgeMask = TeamMaskRGBA.A — отдельная L8-текстура. EXR 16 × 8 в UE не импортируется | LDV-1 / LDV-8 / LDD-6: один формат LUT на всех героев. Строка 7.R EXR (Ymed в LDM-7) в v2 — это luminance min |
| LDMU-2 | Меш H2LD стоит на каноническом скелете `/Game/PipelineCandidates/Merlin/Rig/SK_Merlin_Skeleton` волны H2Anim (ключ `ue.target_skeleton` унаследован из `merlin-h2-ue-import.json`) | Риг H2LD равен H2.1 (LDM-10), клипы H2Anim подходят без ретаргета, лишнего скелета нет. Цена — зависимость от коммита волны H2Anim |
| LDMU-3 | Фигура — на `M_UM_Figure_v2` с `UseUV1Metres = true`. Подставка остаётся на `M_UM_BaseMarker` v1 | UV1 в метрах есть (LDM-8): 2 выборки деталей вместо 6, волокно посоха вдоль U. У подставки командная лента нужна для читаемости доски (W4-B, 5b-R), камень концепта на боковине не сравнивается |
| LDMU-4 | Зоны замера в UE — отладочный MI героя: ZoneID в слоте MatID, отладочная ZoneLUT (12 плоских цветов, металлическая ветка), DebugView 7 + DebugBakeFromLUT. Эталон цвета зоны — калибровочный кадр `DebugMatIDOverride`; фон отсекается кадром-«плитой». Ассеты живут в папке прогона (CLI `ue.extra_instances`) | Мастер v2 не меняем. Пастельные цвета DebugView 1 различались на 10–20 уровней sRGB (r1), а палитра ZoneLUT — не меньше чем на 40. Маски одинаковы для H2 и H2LD: геометрия и UV0 совпадают |
| LDMU-5 | Look-dev правит только слой `lut.ue_lookdev` конфига `merlin-h2-lookdev-ue-lut.json`. Текстуры запекания и MI-ручки не трогаются. Каждая принятая итерация — полный `adopt` + `ue-import`. Кандидаты между итерациями проверяются пробами: LUT перезаливается поверх ассета прогона (`h2ld_lookdev_ue.py reimport`), затем идёт полный CLI-импорт | Воспроизводимость: итоговое состояние UE целиком выводится из CLI. Итерации UE-0…UE-4 — в отчёте §U5 |
| LDMU-6 | **Пересмотрено 2026-09-30 после ревью.** На r3 яркость вышивки «совпадала» только на плече тоновой кривой EV100 1.3: при −1.5 EV она была 1.62, при −1.5 EV проходила одна зона из пяти. Вывод r3 «остаток — только свет доски» отменён. Теперь: (1) материальная часть исправлена — блеск Cloth шёлка 0.5 → 0.09, specular шёлка 0.35 → 0.2, красный тон полостей кожи 0.55 (UE-3); (2) look-dev сверяется на двух экспозициях (LDMU-10); (3) остаток вышивки (EV100 1.3: 0.83 / +6.8° / −0.14), лица (0.76 / −0.11), кистей (0.71 / −0.20 при EV100 1.3 и 1.29 при −1.5 EV) и шерсти при −1.5 EV (0.76 / +0.13) `Saturation` и альбедо не компенсируются. Он передан 5b-R как несовпадение контраста тоновой кривой UE и концепта, а не как чисто световой | Пробы p3–p5: яркость вышивки растёт на ~0.46 на единицу sheen при EV100 1.3 и на ~1.5 при −1.5 EV. Значения, которое держит обе экспозиции в ±15 %, нет. У кожи в LUT v2 нет множителя альбедо: подъём при EV100 1.3 ещё сильнее выводит кисти при −1.5 EV. `Saturation` 1.2 допуска не даёт (p2) и перенасыщает шерсть, дерево и кристалл |
