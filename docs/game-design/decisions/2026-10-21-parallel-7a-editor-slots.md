Решение ДС-3 (2026-10-14) «7a — строго один герой за раз» было правилом проекта, а не пределом машины (64 ГБ ОЗУ,
32 потока, RTX 4090; кадр бенча 2,2 мс GPU): у редактора был один порт MCP :8123 и один файл блокировки, и второй агент
7a потерял бы чужой редактор. ДС-3a снимает это правило.

## Tripo API вместо кликов Studio — что нужно от пользователя (не сделано, гейт ДС-2)

Сейчас этап 2 — клики в Tripo Studio, одна вкладка, ≈ 12–13 мин на героя строго по очереди. API асинхронный
(`references/tripo3d-stages.md` §10): задачи ставятся пачкой и опрашиваются, три героя — ≈ 10–15 мин вместо 36 и
0 минут рабочего стола. Это деньги и новый кошелёк, поэтому решает пользователь:
1. Аккаунт на developers.tripo3d.ai и API-ключ. Ключ пользователь кладёт сам в переменную окружения `TRIPO_API_KEY`
   (агент ключи и пароли не вводит; в репозиторий ключ не попадает).
2. API-кредиты — отдельный кошелёк от Studio (1 кредит = $0,01): H2 на героя ≈ 70–90 кредитов (≈ $0,7–0,9),
   черновик 1b — 20–30.
3. Решение «API вместо Studio для этапа 2» и лимит кредитов в `credits-ledger.json`.
После этого: инструмент `tools/art/pipeline_batch/tripo_api.py` (multiview-to-model с частями → `models/texture` 8K PBR,
опрос, загрузка, source-spec как у `post_h2.py`, строка журнала `tripo-api`) и один калибровочный герой API против
Studio (число частей, ≈ 1,9 млн треугольников, 8K PBR) до переключения. Без денег — Claude in Chrome на этом ПК (DOM,
без курсора пользователя), но по-прежнему по очереди.

## Сборка C++ и Live Coding (ответ на «Там же есть лайф режим»)

- C++ в пайплайне героя — только регистрация на шаге 7b, один раз на окно пачки: строка `Specs()`
  (`S08HeroesV2.cpp:97-118`), тесты `S08HeroesV2Tests.cpp`, `CharacterKey`/`HitType` (`S08AudioBank.cpp`).
  Инкрементальная сборка редактора — 16–24 с в пилоте; 2026-10-21 правка `S08FlowGameMode.cpp` (самый большой файл
  проекта) собралась за 30,5 с. Игровой target после touch `Unmatched.Build.cs` — 264,5 с, один раз на упаковку.
- Live Coding — тоже компиляция (те же 20–30 с на файл); он экономит перезапуск, а не сборку. Он уже основной путь для
  правок кода игры (`devexec.py lc`, AGENTS.md «Live Coding dev loop»). Для регистрации героя не годится: таблица
  `Specs()` — статическая переменная функции, Live++ сохраняет уже созданные статики, новая строка без перезапуска не
  появится; упакованный `-Bench` (приёмочные кадры) собирается из игрового target, патча в памяти там нет; живая сессия
  `-LiveCoding` блокирует сборку `UnmatchedEditor` во всех checkout (F9), то есть ломает параллельную сессию.
- Дальше (после волны A, отдельная правка): таблица героев в `Config/Heroes/S08HeroesV2.json` (чтение при старте,
  встроенная таблица — откат), тогда регистрация героя вообще без C++ и сборки, упаковка с `-SkipBuild`.
