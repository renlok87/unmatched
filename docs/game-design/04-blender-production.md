## 1. Общий стандарт ассетов (бриф §9.1 — полная таблица)

| Параметр | Стандарт |
|---|---|
| **Версии** | Blender **5.2.2 LTS** (`ФАКТ` брифа §2.1), UE **5.8.2** (`ФАКТ` брифа §2.1). Обмен — FBX; документация Epic указывает FBX **2020.2** для своего FBX pipeline (`ФАКТ` ссылки брифа §9.1), но экспортёр Blender версию Autodesk не выбирает — совместимость Blender 5.2.2 → UE 5.8.2 **проверить на проверочном наборе §2**. Дополнения Blender не требуются (сценарий обходится штатным FBX-экспортёром; glTF-импортёр UE 5.8 — резервный путь для static mesh, тоже **проверить**). |
| **Единицы** | В Blender: 1 unit = 1 метр (Scene Units: Metric, Unit Scale 1.0). Клетка доски = **1.0 м** в Blender = **100 uu** в UE (соответствие ×100 см/м применяется FBX при корректном Unit Scale; не выставлять ручной Scale при импорте — если потребовался, это дефект, а не настройка). Зафиксировать после проверки кубом §2. Масштаб клетки — из прежнего плана `docs/unreal/06` (статус ПЛАН, не реализация) — принят как `ПРЕДЛОЖЕНИЕ`. |
| **Оси** | Blender: Z-up, «лицом вперёд» = **−Y**. UE: Z-up, X-forward. Конвертация выполняется FBX-экспортом (Forward = −Y, Up = Z): персонаж, смоделированный лицом вдоль −Y в Blender, в UE смотрит вдоль +X. Проверяется асимметричной стрелкой §2. |
| **Pivot** | Фигурки: центр опоры (низ подставки, центр клетки); X/Y — центр клетки, Z=0 — поверхность игровой плоскости. Декор: по месту крепления (фонарь — центр основания; фасад — нижний край наружной грани, по центру; ящик — центр основания). Плоскость карты: центр, Z=0. |
| **Трансформации** | Перед экспортом Apply: Rotation + Scale (все объекты); запрет отрицательного масштаба и зеркальных объектов (Mirror-модификаторы применить, нормали проверить — у зеркальных часто инвертированы). |
| **Геометрия** | Бюджеты LOD0 (`ПРЕДЛОЖЕНИЕ`, предварительно, до контрольной сцены): **герой 15–25k tris; помощник 8–15k; доска-основа 30–50k; декор-кит (сумма) 30–60k; подставки/маркеры (каждый) 0.5–2k; плоскости карт < 0.1k**. Силуэт важнее деталей: детали, не читаемые с обзорной камеры (К-1, `03` §3), не моделируются. Нормали наружу (проверка: визуализация backface/режим Normals), без пересечений «внахлёст», закрывающих силуэт. |
| **Материалы** | ≤ **3 слота** на модель. Один общий master material **M_DioramaMaster** (см. §6 манифеста-строк в `06`): параметры BaseColor/Normal/ORM-текстуры, **TeamColor** (Vector), EmissiveIntensity, RoughnessRange. Цвет команды/выделения — параметр материала, не отдельная текстура. |
| **UV** | Один канал UV0 (без перекрытий в атласе; плотность текселей согласована внутри класса ассета). Канал UV1 (lightmap, развёртка без перекрытий, второй набор) — только если контрольная сцена покажет необходимость запечённого освещения; в MVP с одним directional светом не требуется (`ПРЕДЛОЖЕНИЕ`). |
| **Текстуры** | **2K герой / 1K помощник и мелочь** (доска-основа: 2K на секцию/атлас — см. карточку). Набор: **BaseColor + Normal + ORM** (упаковка AO→R, Roughness→G, Metallic→B). sRGB — только BaseColor; Normal/ORM — Linear. Нормали в формате DirectX (UE): при выпечке в Blender (OpenGL, зелёный +) — конвертация зелёного канала; **проверить на контрольном материале**. |
| **Коллизии** | Только **selection-collision** (выбор мышью), не физика: отдельный простейший меш в том же FBX с префиксом **UCX_** (выпуклая оболочка) или **UBX_** (бокс); фигурки — капсула/цилиндр по габариту (префикс UCP_/USP_ допустимы по конвенции UE). Физической симуляции в MVP нет — сложные коллизии не делаем. |
| **LOD** | MVP: **без LOD** или LOD1 = ×0.5 tris (упрощение без потери силуэта) — `ПРЕДЛОЖЕНИЕ`; критерий: контрольная сцена на D-07-железе. Переключение — по экранной ширине, задать в UE, не в Blender. |
| **Rig** | Лёгкий (D-11): `root + hips + spine + head + 2×(arm: upper/lower/hand) + 2×(leg: upper/lower/foot) + weapon` — ~15 костей; ≤ **4 влияний** на вершину; масштаб костей единичный. Совместимость анимаций — один шаблон скелета на всех персонажей (имена костей из шаблона `blender/_shared/rig_template.blend`). |
| **Экспорт** | FBX, сохранённый preset «UM_FBX_v1» (настройки — таблица §1.1); повторяемая процедура — скриптом `batch_export.py` (§4.2). Все значения — **проверить на выбранных версиях** (Blender 5.2.2 LTS → UE 5.8.2) на наборе §2. |
| **Файлы** | `blender/<ASSET-ID>/`: `<slug>.blend` (редактируемый исходник), `export/*.fbx`, `textures/T_*`, `preview/*` (вид с игровой камеры, силуэт, wireframe), `REPORT.md` (отчёт сдачи §5). Каталог `blender/` — `ПРЕДЛОЖЕНИЕ`, создаётся при первом задании. |
| **Приёмка** | Чек-лист 7 пунктов §5; проверка масштаба/ориентации/pivot/материалов/коллизии выбора/анимаций в UE 5.8.2 на серой сцене с клеткой 100 uu. |

### 1.1. FBX-пreset «UM_FBX_v1» (значения — до проверки на выбранных версиях)

| Настройка Blender FBX-экспорта | Значение |
|---|---|
| Limit to Selected Objects | Выкл (скрипт передаёт список объектов) |
| Object Types | Armature + Mesh (остальные выкл) |
| Transform / Apply Scalings | **FBX Units Scale** |
| Forward / Up | **−Y / Z** |
| Apply Unit | Вкл |
| Apply Transform | Выкл (трансформации уже применены в .blend — стандарт §1) |
| Triangulate Faces | Вкл |
| Loose Edges / Only Selected / Custom Properties | Выкл |
| Primary / Secondary Bone Axis | Y / X (**проверить**: поза в UE не должна быть развёрнута) |
| Bake Animation (для SK) | Вкл; Key All Bones = Вкл; NLA/Strips — выкл; SACD — выкл |
| Shape Keys / Smoothing (Face) | Выкл / Face |
| Path Mode | Auto (текстуры кладутся рядом вручную, не встраиваются) |

Сkeletal-анимации экспортируются **отдельным FBX-клипом на действие** (Idle/LungeAttack/HitReact/DeathSettle) с тем же скелетом — импорт в UE как Animation Sequences на общий Skeleton. Альтернатива «один FBX со всеми действиями» — **проверить**, что UE 5.8 корректно режет на секции; выбран раздельный вариант как заведомо предсказуемый (`ПРЕДЛОЖЕНИЕ`).

### 1.2. Именование

- Меши в UE: `SM_<Имя>` (static), `SK_<Имя>` (skeletal); текстуры `T_<Имя>_<BC|N|ORM>`; материалы `M_<Имя>`. Коллизии: префикс `UCX_/UBX_/UCP_/USP_` + имя объекта.
- Внутри .blend: объекты без префиксов UE, но с осмысленными суффиксами (`_LOD0`, `_col` для коллизии); коллекции = будущие экспортные единицы.
- Контент-ключи (medusa, king-arthur, harpy, merlin, cobble-city) — только в путях/именах ассетов нижним регистром; ID из БД (cuid) в имена не зашиваются (бриф §11.3).

## 2. Проверочный набор (до любого производства моделей)

Набор = один .blend `blender/_shared/check_set.blend`, экспорт через preset §1.1, импорт в пустой проект UE 5.8.2.

1. **Куб** 1.0×1.0×1.0 м (в UE ожидается бокс **100×100×100 uu**, pivot в нижнем центре).
2. **Асимметричная стрелка направления**: стрела длиной 1 м, «наконечник» смещён к −Y в Blender (в UE ожидается наконечник по **+X**), верхняя грань помечена (в UE — вверх по **+Z**).
3. **Тестовая фигурка** (упрощённый манекен ~0.5 м) с pivot **на опоре**, материалом с TeamColor-параметром и коллизией-капсулой UCX_/UCP_.
4. **Skeletal-тест**: та же фигурка на шаблонном скелете §1 + короткий клип 30 кадров с **root-движением** на 1 м и подъёмом руки (в UE ожидается: клип играет, смещение = 100 uu по ожидаемой оси, без разворота на 90°).

Таблица «ожидаемое/полученное» — заполняется при проверке, результат — в `REPORT.md` набора:

| Проверка | Ожидаемое | Получено | Вывод |

| Размер куба | 100×100×100 uu | 100×100×100 uu | PASS |

| Направление стрелки | наконечник +X, метка +Z | X = 0…100 uu; Z = 0…10 uu | PASS |

## 4. Автоматизация через Blender (бриф §9.4)

Все скрипты живут в `blender/_tools/`, запускаются `blender --background <file>.blend --python <script> -- <аргументы>`; логи — консоль + `blender/_tools/logs/<script>-YYYYMMDD.log`; повторный запуск идемпотентен (кроме превью — перезаписываются). **Честно: художественное качество скриптом автоматически не получается** — автоматизация покрывает только техническую дисциплину (имена, экспорт, отчёты, превью); скульпт/текстуры/анимация — ручная работа по карточкам §3.

### 4.1. normalize_names.py — нормализация имён

- Вход: `.blend` (один или список).
- Выход: переименованные объекты/коллекции в .blend.
- Параметры: `--prefix-map` (SM_/SK_/T_/M_ по типу: mesh→SM_ или SK_ при наличии арматуры, image→T_, material→M_), `--suffix-lod`, `--dry-run`.
- Повторный запуск: без изменений (идемпотентен; уже корректные имена не трогает).
- Логи: список «было → стало».
- Проверка: после прогона `mesh_report.py` не находит объектов без префикса.

### 4.2. batch_export.py — батчный экспорт по preset

- Вход: список карточек (по `ASSET-ID` из имён коллекций) или `--all`.
- Выход: `export/*.fbx` (+ отдельные клипы для SK по списку действий из карточки).
- Параметры: `--preset UM_FBX_v1` (значения §1.1 читаются из JSON-конфига, не из кода), `--dry-run`, `--only SK_Medusa`.
- Повторный запуск: перезаписывает FBX с новой версией; старые версии не хранит (версия — в `REPORT.md` и манифесте).
- Логи: на каждый экспорт — настройки, размер файла, предупреждения экспортёра.
- Проверка: файл ≠ 0 байт; в логе нет ERROR; контрольная сумма попадает в манифест (4.5).

### 4.3. mesh_report.py — отчёт по полигонам/материалам/UV

- Вход: `.blend` или список.
- Выход: CSV `REPORT-mesh.csv`: объект, tris (по карточке — итог), material slots, имена материалов, UV-каналы, перекрытия UV (эвристика), влияния костей > 4 (для SK), отрицательный масштаб, неприменённые трансформации, нормали внутрь (эвристика).
- Параметры: `--budgets budgets.json` (из §1; отклонения помечаются FAIL).
- Повторный запуск: перегенерирует отчёт.
- Логи/проверка: строки FAIL = 0 перед сдачей; отчёт вкладывается в `REPORT.md` ассета (§5).

### 4.4. preview_render.py — превью с игровой камеры

- Вход: `.blend` ассета + файл стенда `blender/_shared/preview_stage.blend` (клетка 100 uu, серый поднос, свет по 03 С-8).
- Выход: `preview/<имя>_game-view.png` (камера: вертикальный FOV ≈ 20° при 16:9 = горизонтальные 35° UE, Pitch −55 — эквивалент стартового угла 03 §2), `_silhouette.png` (материал-flat чёрный/белый — тест С-1), `_wireframe.png`.
- Параметры: `--camera preset|closeup` (К-1/К-2 ракурсы), `--engine EEVEE`.
- Повторный запуск: перезаписывает превью (превью — производный артефакт).
- Логи: список отрендеренных файлов.
- Проверка: силуэт-превью различим без цвета (ручная проверка художником по карточке).

### 4.5. manifest_build.py — сборка строк манифеста

- Вход: `blender/*/` + `REPORT-mesh.csv`.
- Выход: `manifest_rows.generated.csv` с колонками `06-asset-manifest.csv` (assetKey, blendPath, exportPath, unrealAssetPath, version, sourceHash = sha256(.blend)).
- Параметры: `--status planned|wip|imported|verified|blocked` (статус ставится вручную — см. ниже).
- Повторный запуск: пересчитывает hash/version, не трогает статусы, проставленные вручную.
- Логи: изменения hash по ассетам.
- Проверка: строка ассета в `06-asset-manifest.csv` обновлена вручную по этому файлу (манифест — ревьюемый документ, автозапись напрямую запрещена, чтобы статус не «утекал» без проверки).

Чего скрипты НЕ делают (осознанно): генерацию персонажа/декора «по описанию», авторемонт топологии, авто-развёртку для финального качества.

## 5. Сдача ассета (чек-лист брифа §9.5 — 7 пунктов)

Для каждого ассета из §3, перед перемещением статуса в `06-asset-manifest.csv` дальше `planned`:

1. Редактируемый `.blend` в `blender/<ASSET-ID>/`: понятные коллекции, без потерянных текстур/библиотек (File → External Data → Pack не используется; пути — относительные от `blender/`).
2. Экспортный файл `export/*.fbx` + точные настройки экспорта (ссылка на preset UM_FBX_v1 и его версию в `REPORT.md`).
3. Текстуры `textures/T_*` + перечень материалов (сколько слотов, какой master, параметры).
4. Превью `preview/`: вид с игровой камеры (К-1/К-2), силуэт, wireframe.
5. Отчёт `REPORT.md`: размеры (uu), tris, материалы, скелет (кости, влияния), анимации (список клипов, длительности), коллизии, LOD; результат `mesh_report.py`.
6. Результат импорта и проверки в UE 5.8.2 (по §2-таблице, применённой к ассету) — либо честный статус «ещё не проверено».
7. Запись в `06-asset-manifest.csv` обновлена (version, sourceHash, verificationStatus) + происхождение исходников (для референсов .glb — путь и пометка «только референс формы, D-06»).

Отклонение любого пункта = ассет не считается сданным (даже если «выглядит хорошо»): без REPORT/превью невозможно ревью и повторное производство.
