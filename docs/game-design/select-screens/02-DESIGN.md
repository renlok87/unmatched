# Выбор героя и поля в духе файтингов — дизайн (SEL)

Дата: 2026-10-16. Статус: v2 — после валидации Opus xhigh (`04-REVIEW-OPUS.md`, PASS-WITH-FIXES); правки — §11.
Вход: `01-research-fighting-games.md` (ресерч MK1 / MK11 / Injustice 2 / SF6 / Tekken 8 / Smash / Unmatched DE),
код комнаты `unreal/Unmatched/Source/Unmatched/S08/UI/UmScreenRoom.*`, лобби `UmScreenLobby.*`, загрузки
`UmScreenLoading.*`, фигуры `S08/S08HeroesV2.h`, сервер `backend/src/games/game.service.ts`.

Запрос пользователя (2026-10-16): «поресерчил в интернете… референсы, как выглядит во всяких файтингах меню выбора
персонажей и выбора карты, ориентир Mortal Kombat и Injustice… Нужно реализовать подобное в игре».

## 0. Что есть сейчас и почему плохо

Кадр: `docs/game-design/hud-redesign/frames/live-s3-room.jpg`.
- Комната (`UUmScreenRoom`) — пять плоских тёмных панелей: слоты игроков слева, две карточки героев 300×420 по центру,
  блок доски, ряд колоды, нижняя полоса. Это форма настроек, а не момент выбора бойца.
- Герой — круглый портрет 120 su. Готовые 3D-фигуры v2 (Idle/Lunge/Hit/Death) на экране выбора не видны вообще.
- Соперник — строка текста в слоте. Нет «лицом к лицу», нет VS.
- Доску выбирают при создании комнаты в лобби; в комнате блок доски только для чтения. В правилах Unmatched сначала
  выбирают героев, потом поле.
- Загрузка — маленькая панель 624×494 «Король Артур против Медузы» с дисками 160 su; нет момента VS.

## 1. Принципы (из ресерча, адаптированные к Unmatched)

| П7 | Выбор арены — отдельный шаг после бойцов, крупное превью + лента миниатюр + «Случайная» (MK11, Injustice 2, SF6) | Шаг «Поле» после выбора обоих героев: большое превью карты, имя, подпись; лента миниатюр Marmoreal / Sarpedon + «Случайное»; выбирает хост, гость видит выбор вживую |
| П8 | VS-экран — пауза-кульминация: обе фигуры, имена, «VS», арена (MK, Injustice, Tekken) | Экран загрузки становится VS: две фигуры в полный рост на всю высоту, медальон «VS» по центру, имена и ники, имя поля; стадии загрузки — мелкой строкой снизу |
| П9 | Кричащий неон MK — не наш язык; у нас «Стол»: мрамор, бронза, золото (HUD принят 16.10) | Плашки M3 мрамор+бронза (`hud.table.*`), золото C-11, Philosopher для заголовков; цвета команд: P1 золото `#E8C06A`, P2 серебристо-синий `#5A7F9F` (`S08Team.h`) вместо синего/красного MK |

## 2. Поток

```
LOBBY ──create/join──▶ ROOM: шаг «ГЕРОЙ» ──оба героя выбраны──▶ шаг «ПОЛЕ» ──готовность──▶ отсчёт 3-2-1 ──▶ VS (загрузка) ──▶ матч
                          ▲                         │ хост меняет поле
                          └── смена героя снимает готовность (как сейчас)
```

- Шаги — это фазы одного экрана `UUmScreenRoom`, не новые стадии `ES08Stage` (сервер о шагах не знает; шаг выводится
  из состояния комнаты: оба героя есть → «ПОЛЕ»). Кнопка «‹ Герой» возвращает к шагу героя, пока свой игрок не готов.
- VS_AI: героя бота сервер назначает при старте (`Герой ИИ — при старте`) → витрина P2 показывает «ИИ выберет героя»
  со знаком «?»; шаг «ПОЛЕ» открывается после своего выбора.
- Доска: выбор в лобби при создании остаётся как начальное значение (код не ломаем). В шаге «ПОЛЕ» хост меняет её
  новой мутацией `selectBoard(gameId, boardId)` (LOBBY, только хост, только реальные карты — Marmoreal / Sarpedon,
  AGENTS.md «Board scenes»). Смена поля снимает готовность гостя (как смена героя).

## 3. Шаг «ГЕРОЙ» — раскладка 1920×1080 su (класс L)

```
┌──────────────────────────────────────────────────────────────────────────────────────────────┐
│ [‹ Выйти]           ВЫБОР ГЕРОЯ   ·  шаг 1 из 2        Комната ABC123 [копировать]       [≡] │ 0–96
│ ┌───────────────┐                                                       ┌───────────────┐    │
│ │               │            ┌──────── карточка героя ────────┐         │               │    │
│ │  ВИТРИНА P1   │            │ КОРОЛЬ АРТУР                    │         │  ВИТРИНА P2   │    │
│ │  3D-фигура    │            │ HP 18 · ход 2 · ближний бой      │   VS    │  3D-фигура /  │    │
│ │  Idle / Lunge │            │ + Мерлин · HP 7 · дальний бой   │ медаль- │  «?» пьедестал│    │
│ │  на пьедестале│            │ способность — 2 строки           │   он    │               │    │
│ │  560×800      │            │ [Колода · 30]                    │         │  560×800      │    │
│ │               │            └──────────────────────────────────┘         │               │    │
│ ├───────────────┤                                                       ├───────────────┤    │
│ │ ИМЯ ГЕРОЯ     │        ┌────┐ ┌────┐ ┌────┐                            │ ИМЯ / «?»     │    │
│ │ ник · ВЫБРАН  │        │ P1 │ │ P2 │ │ ?  │   лента ростера             │ ник · выбирает│    │
│ └───────────────┘        └────┘ └────┘ └────┘                            └───────────────┘    │
│                                                                    [ГОТОВ]  [НАЧАТЬ ПАРТИЮ]  │ H-112
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

Размеры (su, 1080p): витрины x=48 и x=W-48-560, y=120, 560×800 (видимая часть фигуры 560×700 + плашка имени 100);
карточка героя по центру 640×300 с y=200; медальон VS 140 su в центре между карточкой и витриной P2 не ставим —
медальон стоит по оси экрана на уровне груди фигур (y≈420), карточка героя под ним (y=520…800); лента ростера
центрирована, y=H-280, плитка 128×168 с шагом 16; нижняя полоса как сейчас (y=H-112, h=88).
Класс S (≤1280 по ширине): витрины 400×600, карточка 520×260, плитки 104×136.
Сверхширокие 2560/3840×1080: витрины прижаты к краям безопасной зоны 16:9 по центру (как HUD), фон — сцена.

Витрина:
- Рамка M3 мрамор+бронза (тонкий бронзовый кант 4 su), внутри — рендер-текстура SceneCapture своей фигуры на тёмном
  фоне с мягким световым конусом цвета команды сверху; пьедестал фигуры (тот же `PedestalPath`) виден.
- Камера: фигура в три четверти к центру экрана (P1 смотрит вправо, P2 влево — ВР-06: никогда спиной), рост фигуры
  ≈ 80 % высоты окна.
- Плашка имени под окном: имя героя (Philosopher 40), ник игрока (Roboto 20), статус-чип «ВЫБИРАЕТ…» / «ВЫБРАН» /
  «ГОТОВ» цветом команды; под ней строка помощника с круглым портретом и HP («+ Мерлин · HP 7», «+ Гарпии ×3 · HP 1») —
  как в Unmatched DE: помощник идёт с героем, отдельного шага нет (ресерч §9, рек. 5).
- Фиксация (MK11, ресерч §2): камера витрины делает короткий наезд (FOV 24° → 20° за 250 мс и обратно за 400 мс)
  одновременно с LungeAttack.
- Состояния: `empty` (пьедестал без фигуры, крупный «?», текст «Выберите героя» / «Соперник выбирает…» / «ИИ выберет
  героя»), `hover` (своя витрина: фигура наведённого героя, Idle, полупрозрачная плашка «наведение»), `locked` (фигура
  выбранного, после Lunge — Idle; рамка вспыхивает золотом 300 мс), `ready` (лента «ГОТОВ» поперёк низа витрины).

Плитка ростера 128×168:
- Портрет (`T_Portrait_<hero>`), снизу полоса с именем; рамка бронза.
- `normal`, `hover` (рамка своей команды 3 su + подъём 6 su, 120 мс), `picked-own` (угол-бейдж P1 цветом своей команды),
  `picked-opp` (бейдж соперника; плитка затемнена 50 %, не кликается — GD-016 «без дубликатов»),
  `unsupported` (герой соперника вне ростера клиента — уже есть GD-053), `random` (знак «?» на мраморе).
- Клик по плитке = выбор (как сейчас кнопка «Выбрать»). Наведение мышью — превью в своей витрине.

Карточка героя: показывает наведённого героя, иначе выбранного. Источник — `adminHero` (HP, ход, тип атаки,
помощники, способность), текст способности RU, если есть (`FetchHeroDetails`).

## 4. Шаг «ПОЛЕ»

```
│  ВИТРИНА P1 (фигура выбранного, Idle)   ┌──────────── ПРЕВЬЮ ПОЛЯ 960×540 ────────────┐  ВИТРИНА P2 │
│                                          │  кадр K1 карты (реальный бенч-кадр)          │             │
│                                          └──────────────────────────────────────────────┘             │
│                                           MARMOREAL · оригинальная карта                               │
│                                           подпись: зоны, особенность поля (из boardList/админки)      │
│                                     [Marmoreal] [Sarpedon] [Случайное]     ← лента миниатюр 200×120   │
│  [‹ Герой]                         «Поле выбирает хост» (гость)                  [ГОТОВ] [НАЧАТЬ]     │
```

- Витрины уменьшаются до 400×600 и уезжают к краям (анимация 250 мс), центр занимает превью поля.
- Превью — реальный кадр K1 каждой карты (бенч-кадры `docs/game-design/evidence/VISUAL/AN-23/sheet-0{1,3}-*-K1-plain.png`
  → текстуры `T_BoardPreview_<key>`), не ImageGen.
- Наведение на миниатюру — превью меняется (у хоста). Клик — `selectBoard`. Гость видит выбор хоста (поле комнаты
  `boardId` из опроса) и плашку «Поле выбирает хост»; его наведение меняет только его превью.
- «Случайное» — клиент хоста выбирает случайную карту из реальных и отправляет её id.

## 6. Техника 3D-витрин

- Новый актёр `AUmHeroShowcase`: в мире далеко под полем (Z = −20000), на каждую сторону — `USkeletalMeshComponent`
  (меш, MI команды и клипы из `S08HeroesV2`), пьедестал, 2 точечных света с ограниченным радиусом (ключевой тёплый +
  контровой цветом команды), `USceneCaptureComponent2D` с `ShowOnlyList` (только эта фигура и пьедестал), источник
  `SCS_FinalColorLDR`, RT 512×768 (1080p; 384×576 на классе S), захват каждый кадр только пока экран открыт.
- Lumen в захвате выключен (show flags / post-process: GI и отражения None) — дёшево и предсказуемо; фон чёрный,
  световой конус и виньетка — в UMG поверх/под картинкой (рамка витрины).
- Клипы: Idle (петля, фаза по id), LungeAttack при фиксации выбора, затем Idle (`S08HeroesV2::NextClip`).
- Помощники (Мерлин, гарпии) в витрине не стоят — только герой (как в правилах: герой — главный; помощник в карточке).
- Бюджет: две захватки без Lumen < 1 мс GPU (замер один раз по правилу «без оптимизаций в бюджете»).
- Откат: `-S08SelectLegacy` возвращает текущую комнату и загрузку байт-в-байт.

## 8. Гейт и трасса

- SHOT-строка экрана расширяется: `step=hero|board`, `p1=<empty|hover|locked|ready>`, `p2=…`, `tiles=<n>`,

- Ни имён, ни кода комнаты в гейте (как сейчас).

## 9. Открытые вопросы (решаю сам по делегированию, если Opus не возразит)

- В1. Карточка героя по центру или под витриной? → по центру (MK11: инфо-панель в середине, обе витрины свободны).
- В2. Показывать ли «скоро» силуэты остальных героев БД (84) как MK1 / Injustice DLC (ресерч рек. 16)? → нет в этой
  итерации: 82 «?» при двух играбельных — это «чёрные ямы», которые критиковали в MK11 (рек. 18); лента строится из
  играбельных + «Случайный» и растёт с ростером (П10).
- В4. Таймер выбора (ресерч рек. 10)? → нет: сервер не знает таймера, авто-выбор без сервера рассинхронит комнату.
- В3. Кто выбирает поле онлайн? → хост (в настольной игре — договорённость/случай; «Случайное» есть).

## 11. v2 — правки по ревью Opus (2026-10-16)

| Ревью | Решение (реализовано) |
|---|---|
| C: цель — вариант A на всех экранах | Ниша — мраморная плита `hud.table.card` с тонкой линией цвета команды внутри, фигура на тёмном студийном фоне с ореолом контрового света команды; вуаль вида выбора 0,82 (сцена меню едва видна) |
| F1: противоречия состояний | Хост видит «Выберите поле партии», гость — «Поле выбирает хост»; «‹ Герой» неактивна, пока игрок «Готов»; карточка в центре — наведённый или свой герой; **такт фиксации 1,2 с**: оба выбрали → пара стоит лицом друг к другу с VS, затем шаг «ПОЛЕ» |
