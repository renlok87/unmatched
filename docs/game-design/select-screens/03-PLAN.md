## 1. Архитектура (решения)

| Решение | Почему |
|---|---|
| Новый вид — режим существующих `UUmScreenRoom` / `UUmScreenLoading`, а не новые экраны | Владелец (`S08FlowGameModeUmRoom.cpp`), гейты, SimulatePress, диалоги колоды и выхода остаются; меньше риска |
| Вид выбора — по умолчанию; откат `-S08SelectLegacy` (старая комната SC-14…SC-18 и загрузка SC-19 байт-в-байт) | AGENTS.md «Accepted art is the default; flags only roll it back» |
| 3D-витрины — `AUmHeroShowcase`: v2-фигуры (`S08HeroesV2`: меш, MI команды, пьедестал, Idle/LungeAttack) в студии далеко от поля (X = +400 000), SceneCapture2D только своих компонентов, свет канала 2, без Lumen | Живые готовые модели вместо картинок (П1, ВР «готовый арт по умолчанию»); фон и свет поля не мешают |
| Качество витрины: RT 1024×1536 с мипами + TAA захвата, LOD0 принудительно, `bForceMipStreaming` | Первые кадры были мутными: стриминг текстур видит только основной вид и держал низкие мипы; без AA — лесенки |
| Аренда активности (`RequestActive` каждый кадр) | Комната и загрузка не дерутся за SetActive; без экрана захват спит (GPU) |
| Шаг «Поле» — фаза комнаты; смену поля делает новая мутация `selectBoard` (хост, LOBBY, доска существует; снимает готовность гостя) | Правила Unmatched: сначала герои, потом поле; сервер не знает шагов UI |
| Тексты нового вида — ключи `screens.sel.*` через ST_Screens, пока ключей нет — встроенные RU/EN | Импорт string table — отдельный шаг (раздел 5) |
