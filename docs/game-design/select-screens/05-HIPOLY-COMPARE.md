# SEL — витрины: игровые H2LD против исходников Tripo H2

Дата: 2026-10-16. Запрос пользователя: «Попробуй поставить в витрины высокополигональные исходники Tripo (статичные),
сравни кадры с текущими».

## Что сделано

- Импорт: `tools/art/showcase/import_hipoly.py`. Запуск через headless UnrealEditor-Cmd + Interchange. Исходник берётся
  как glTF `*-tex8k-pbr.glb`: свои материалы и текстуры 4K BC / 1K RM / 1K N на каждую часть. Части склеены в один
  Nanite static mesh, результат лежит в `/Game/PipelineCandidates/{KingArthur,Medusa}/HP/`. Объём: Артур 109 МБ, Медуза
  91 МБ, 85 и 69 ассетов. Content в git не входит.
- Исходники — те же задачи Tripo, из которых децимированы игровые фигуры: Артур `c24eeff0` (1 990 362 треугольника),
  Медуза `40c4d1cd` (1 856 473 треугольника). Импортированный меш хранит 15 379 и 13 603 треугольника. Это fallback-меш
  Nanite, а на экран рисуются полные кластеры Nanite.
- Флаг клиента `-S08ShowcaseHiPoly`: в нише вместо скелетной фигуры и её пьедестала стоит статичный исходник. Высота
  подгоняется по верху игровой фигуры, разворот подобран по живым кадрам (45° / 135°). По умолчанию ничего не меняется.
- Кадры одной сессии, один свет, одна камера: `frames/hipoly-01-sheet.jpg` (вверху H2LD, внизу Tripo HP: ниши героев и
  VS) и `frames/hipoly-02-detail-2x.jpg` (фрагменты ×2).

## Сравнение по кадрам

| | Игровая H2LD (38–43 тыс., анимация) | Исходник Tripo H2 (~2 млн, статика) |
|---|---|---|
| Детали доспеха и лица | орнамент «запечён» в текстуру и местами кашеобразен (наплечники, кольчуга); черты лица мягкие | **заметно чётче**: гравировка наплечника, рельеф перчатки, львиная пряжка, черты лица; змеи Медузы объёмнее |
| Цвет | после look-dev: тёмная сталь, золото, у Медузы синие ленты P2 / золотые P1 (цвет команды на одежде) | **сырые цвета Tripo**: у Артура светлая хромированная сталь, у Медузы нет акцентов цвета команды на одежде |
| Пьедестал | игровая база с кольцом цвета команды (золото / синий) | своя тёмная подставка Tripo, **цвета команды нет** |
| Геометрия | дефекты исходника исправлены в look-dev | **дефекты на месте**: у Артура второй «фантомный» меч за спиной (виден на всех кадрах HP), у Медузы открытые торцы |
| Движение | Idle-дыхание, выпад при фиксации, наезд камеры | статика: только наезд камеры, выпада нет |
| Совпадение с полем | тот же меш, что на доске в матче | на поле другая фигура (другой цвет доспеха, без кольца) |
| Цена | ~0 | +200 МБ ассетов на двух героев (около +100 МБ на каждого следующего). Время загрузки и стоимость GPU не замерялись. В упакованный клиент HP-ассеты сейчас не попадают: их грузит только флаг, cook их не видит |

## Вывод и рекомендация

Исходники выигрывают в резкости рельефа: на крупных фрагментах это видно сразу. Проигрывают во всём остальном: нет
анимации (выпад был главным моментом фиксации), сырые цвета не совпадают с принятым look-dev и с фигурой на поле, нет
цвета команды на пьедестале, видны дефекты (фантомный меч Артура).

**Рекомендация: по умолчанию оставить H2LD**, флаг `-S08ShowcaseHiPoly` оставить для сравнения. Если важна резкость
витрины, дешевле поднять детализацию игровой фигуры, а не ставить исходник:
1. Перезапечь нормали и BC игровых H2LD в 4K с этих же исходников (сейчас 2K, `docs/art-pipeline/*-lookdev-v2.md`).
   Получим ту же гравировку на анимированной фигуре с правильными цветами.
2. Либо сделать «витринный» LOD: H2LD, децимированный до 150–300 тыс. треугольников, на том же скелете и с тем же
   look-dev материалом. Это работа этапа 4–6 скилла `3d-model-pipeline`.

Хайполи в витрине по умолчанию — только по слову пользователя. Тогда нужно: перекрасить материалы под look-dev, убрать
фантомный меч, поставить игровой пьедестал с кольцом команды.
