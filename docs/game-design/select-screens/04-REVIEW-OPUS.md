## B. Референсы по одному

Общие для всех восьми:
- Текст у угловых меандров: инсет текста ≈27 px, меандр занимает ≈22 px — символы прилипают к уголкам. «?» в плашке P2
  R1 (1318–1356, 828–862) читается как «[?»; так же `Veteran` (55–146, 886–912), `ProGamer`, `Медуза` в плашке P2,
  `P1`/`P2` в R4 (78–115 и 1215–1255, 905–932).
- Контраст P2: текст `#5A7F9F` на `#141B24`…`#1D2526` = **3,7–4,1:1** (чип «Выбирает…/Готов», метка «P2») — ниже AA
  4,5:1 для 16–20 px; у P1 золото `#E8C06A` = 9,1:1. В R2 строка HP Медузы уже взята светлым тоном `#A4BECE` (8,2:1) —
  это и есть нужное правило.
- Фигуры — ImageGen-живопись по фронтам hero-quality-v1, не v2-модели: тёмные пьедесталы вместо командного кольца
  базы v2 (золотая/серебристо-синяя полоса, см. look-dev b1/i3v). Как композиция годится, как цель сходства — нет.
- Шрифт заголовков Georgia — заглушка; в игре Philosopher (П9).
- Хост обозначен только короной 18 px (182–206, 727–745) — сигнал одним значком; в текущей комнате есть чип «Хост».
- Убраны «Комната · код» и «Копировать», нет «Режим» — регресс к `live-s3-room.jpg` (код `SNYMNZ` без подписи).

## D. Замечания к 02-DESIGN.md

### D1. Противоречия
1. §3 «карточка 640×300 с y=200» и в той же фразе «карточка под медальоном (y=520…800)» — две позиции; 520…800 = 280,
   не 300. Карточка кончается на 800, лента начинается на 800 (README это заметил и оставил зазор 12), а конец ленты
   800+168 = 968 = верх нижней полосы `y=H-112` — второй нулевой зазор, о нём README молчит; в рефах полоса уехала на
   980–1060 (h=80 против спековых 88). Нужна одна таблица координат.
2. Плашка 100 su вмещает имя 40 + ник 20 + чип, но не обещанную «строку помощника с круглым портретом» — поэтому рефы
   её выбросили. Либо плашка 140 su, либо помощник в отдельной полосе витрины.
3. §2: шаг выводится как «оба героя есть → ПОЛЕ», значит состояние R2 (оба зафиксированы, шаг 1) длится 0 мс.
   Нужен такт фиксации: медальон и Lunge обоих, затем переход (предлагаю 1200 мс) — и он же должен быть в §7.
4. «Готов» есть на обоих шагах, а смена поля снимает готовность гостя. Готовность на шаге героя почти всегда
   сгорит. Проще: «Готов» только на шаге «ПОЛЕ».
5. §2 поток содержит «отсчёт 3-2-1», нигде больше не описанный (кто запускает, отменяется ли, сервер не знает), и
   рядом «таймер не берём». Описать (клиентский, после `startGame`, 3×400 мс) или убрать.
6. §3 «Карточка: наведённый, иначе выбранный» против рефа R2 (карточка соперника). Решить: своя карточка; карточка
   соперника — только по наведению на его плитку и с бейджем P2 в углу.
7. §5 «Своя сторона всегда слева» + «P1 золото слева» в рефах: у гостя слева будет его серебристо-синий P2. Цвета и
   бейджи идут от места (`S08Team.h`), не от стороны экрана — записать и нарисовать хотя бы один кадр с точки зрения гостя.

### D2. Недостающие состояния
- Гость ещё не зашёл (WIP уже пишет «Ждём соперника…» и ставит «—» вместо ника) против «соперник выбирает»;
  гость вошёл/вышел посреди выбора (витрина сбрасывается, готовность хоста?); хост вышел (гость в лобби с тостом).
- Гонка GD-016: оба жмут Медузу — сервер отклоняет второго. Нужны тост «Герой уже выбран соперником», откат наведения,
  плитка → picked-opp. Так же «Случайный», когда свободных героев 0.
- Ожидание ответа `selectHero` / `selectBoard` / `toggleReady` (спиннер на плитке/кнопке, блок повторного клика),
  ошибка сети, переподключение.
- VS_AI: витрина P2 «ИИ выберет героя», готовность ИИ всегда «Готов», шаг «ПОЛЕ» без ожидания; на VS герой ИИ
  известен только после `startGame` (`setupAiOpponent`) — VS должен показать «?» и раскрыть фигуру по приходу состояния.
- Гость наводит миниатюру другой карты — его превью меняется, а выбранная хостом карта должна оставаться помеченной.
- Фокус клавиатуры/геймпада (ресерч рек. 20): фокус = наведение, Enter = фиксация, Esc = назад; иначе превью
  доступно только мыши.

### D3. Разрешения (класс S / 720p / ультраширокие)
«Класс S (≤1280 по ширине)» противоречит правилу проекта (`UmHudScale.h`: DPI по короткой стороне, класс S = холст
< 1500 su). Реальные холсты:

| Окно | Холст su | Класс | Что ломается в §3 |
|---|---|---|---|
| 1920×1080 | 1920×1080 | L | — (после исправления D1.1) |
| 1280×720 | 1706×960 | **L** | макет L занимает по высоте до 1056 su → перелёт ≈96 su |
| 1440×1080 | 1440×1080 | S | 48+400+16+520+16+400+48 = 1448 > 1440 |
| 1920×1080 при UI 150 % | 1280×720 | S | шапка 96 + витрина 600 + полоса 112 > 720 |
| 2560/3840×1080 | 2560/3840×1080 | L | боковые поля — чем заливать (см. §C) |

Нужны раскладки по высоте холста (1080 / 960 / 720 su), не только по ширине. RT витрины 512×768 (2:3) не совпадает
с видимой частью 560×700 (4:5) — растяжение или обрез; размер RT должен идти от `PxPerSu` (на 2160p ниша ≈1120×1400 px,
512×768 будет мылом).

### D4. Доступность
P2 `#5A7F9F` годится для рамок и плашек-подложек, но не для мелкого текста (3,7–4,1:1): текст P2 — светлым тоном
(`#A4BECE`, 8,2:1). Хост — словом «Хост» (строка уже есть в комнате), корона — дополнительно. Статусы уже с текстом —
хорошо; picked-opp держится на затемнении + бейдже, добавить подпись «у соперника» на плитку или в тултип.

### D5. Сервер
- WIP `selectBoard` проверяет только существование доски; «только реальные карты» (AGENTS.md, решение 2026-10-04) не
  проверяется — API примет Cobble 5×6 или ART FIXTURE. Нужна проверка по списку `c121b47f8d6eb28daccb76d05`,
  `c7fa64a26c29a0835f2383e63` (или флаг реальной карты) и спек-тест на отказ. «Случайное» — только из этих id.
- Имя поля: в БД «Marmoreal · original map» (`default-board.ts` `DEFAULT_BOARD_NAME`, проверяется при старте), старая
  комната так и показывала. Рефы показывают «Marmoreal · оригинальная карта» — спека должна назвать источник русского
  имени (таблица по id на клиенте), иначе живой экран покажет английское.
- «Подпись: зоны, особенность поля (из boardList/админки)» — поле данных не названо; без источника — убрать.
- `selectHero` / `toggleReady` / `selectBoard` не публикуют лобби-события (публикуются только PLAYER_JOINED/LEFT,
  GAME_ENDED): «соперник выбрал» и «хост сменил поле» доходят только опросом. Задать предельную задержку (≤1 с) или
  добавить события HERO_SELECTED / READY_CHANGED / BOARD_CHANGED.
- Отсутствие таймера и героя ИИ до старта спека учитывает правильно (В4, §2).

### D6. Ресерч
