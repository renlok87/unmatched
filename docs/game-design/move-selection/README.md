## 1. Зачем этот пакет

Пользователь попросил (чат 2026-10-03) провести исследование подбора хода для пошаговой настольной игры и собрать по
нему документы с планом реализации. Опираться нужно на правила проекта, на референсы из документации и на известные
проекты. Отдельно — библиотеки Fab и Unreal и концепты для ImageGen.

Пакет отвечает на три вопроса:

1. Как игрок выбирает и выполняет перемещение в нашем клиенте UE 5.8 на сетке и на графовых картах.
2. Что для этого меняется в существующем коде клиента (S08/S09) и сервера (`backend/src/game-engine`).
3. Как проверить результат: автотесты, паритет клиента и сервера, кадры, производительность.

## 2. Что понимаем под «подбором хода»

Подбор хода — весь путь от намерения «двинуть бойца» до момента, когда обе стороны увидели итог:

| Шаг | Что происходит | Где сейчас в коде |
|---|---|---|
| 1. Начало манёвра | игрок решает потратить действие; сервер списывает действие и добирает карту | `beginManeuver` — `backend/src/game-engine/services/game-action-executor.service.ts:1644-1668` |
| 2. Выбор бойца | свой живой боец, не обездвиженный | `FS09CommandUi::SelectFighter` — `unreal/Unmatched/Source/Unmatched/S09/S09ManeuverUi.cpp:509-519` |
| 3. Достижимые пространства | BFS по правилам GD-015 с допуском «движение + буст» | `FS08BoardModel::ComputeReachableCells` — `unreal/Unmatched/Source/Unmatched/S08/S08BoardModel.h:207-209` |
| 4. Путь и его превью | маршрут до цели, линия, призрак фигурки | нет (путь строится молча при подтверждении — `BuildManeuverPath`, `S08BoardModel.h:217-221`) |
| 5. Буст | сброс одной карты (другая карта заменяет выбранную), её BOOST прибавляется каждому бойцу | `ToggleBoostCard` — `S09ManeuverUi.cpp:562-580` |
| 6. Несколько бойцов | по одному ходу на бойца, ходы применяются по очереди | сервер `game-action-executor.service.ts:1737-1779` |
| 7. Подтверждение и отмена | один атомарный коммит `maneuver(moves[], boostCardId?)`; отмена только локальная | `ConfirmManeuver` — `S09ManeuverUi.cpp:597-651` |
| 8. Анимация | фигурка скользит по пути (D-11, CUE-007) | нет (телепорт — `S08FighterActor.cpp:226`) |
| 9. Взгляд соперника | соперник видит, кто и как прошёл | нет (только итоговые позиции) |
| 10. Эффекты MOVE/PLACE | те же подсветки для выборов карт и способностей | `ComputePendingCells` — `S09ManeuverUi.h:328-330` |
| 11. Подсказки и бот | опционально: подсказка хода игроку, выбор хода ботом | `backend/src/game-engine/services/ai-decision.service.ts:422-459` |

## 3. Рамки

**В рамках:**
- клиент UE 5.8 (`unreal/Unmatched`, модули S08/S09) на сетке Cobble City и на графовых картах Marmoreal/Sarpedon
  (пространства, связи, зоны);
- изменения сервера, без которых подбор хода не работает правильно: публичный след перемещения, коды ошибок,
  каноническая функция пути, исправления правил, найденные исследованием;
- визуальный язык подсветки («подложки» под пространствами), путь, призрак, анимация, взгляд соперника;
- доступность, локализация RU/EN (инфраструктура — MS-T-28), производительность, тесты и кадры приёмки;
- опционально: подсказки ходов, слой угроз, улучшение бота;
- концепты для ImageGen и выбор библиотек Fab.

**Вне рамок:**
- веб-клиент `src/` (он поддерживает только сетку и отклоняет графовые карты — `src/lib/gameStateAdapter.ts:316`);
  план его не ломает и не развивает;
- изменение правил настольной игры (D-01): правила меняются только там, где движок расходится с официальным текстом;
- новые карты и спецсвязи (тайные ходы, односторонние пути — `R1-D11`);
- полный переход ввода на Enhanced Input и CommonUI;
- геймпад как цель MVP (`docs/game-design/02-ux-ui-spec.md:18`); раскладка дана как задел;
- покупки на Fab: их делает только пользователь.

## 4. Глоссарий

| Термин | Значение в пакете |
|---|---|
| Боец (fighter) | герой или сайдкик на поле; запись `GameState.fighters[]`, у каждого своё `movement` |
| Пространство (space) | клетка, куда может встать боец. На графовой карте — круг с `spaceId` (`M13`, `S07`); на сетке — клетка `(x,y)` |
| Связь (link) | линия между двумя пространствами графовой карты; шаг по связи стоит 1 независимо от длины линии |
| Зона (zone) | множество пространств одного цвета; пространство может входить в несколько зон; на движение не влияет |
| Решётка (lattice) | координатная сетка `cells[y][x]`, которой сервер описывает и графовую карту; соседство на ней ≠ связь |
| Манёвр (maneuver) | действие хода: добор 1 карты, затем перемещение своих бойцов (0..N) с необязательным бустом |
| Буст (boost) | сброс одной карты руки; её BOOST прибавляется к движению каждого бойца этого манёвра; выбор другой карты заменяет прежнюю |
| Допуск (allowance) | `movement бойца + BOOST выбранной карты` — максимум шагов пути |
| Черновик (draft) | локальный план манёвра после добора: назначения, пути, буст, порядок. Сервер его не видит |
| Предвыбор (pre-draft) | цель, выбранная до начала манёвра; переносится в черновик после добора (MS-D-03) |
| Коммит (commit) | отправка `maneuver(maneuverId, moves[], boostCardId?)`; атомарна: принят весь план или ничего |
| Превью (preview) | локальный показ пути до клетки под курсором; не меняет модель |
| Призрак (ghost) | полупрозрачная копия фигурки на цели черновика |
| Подложка (plate) | слой подсветки под пространством: заливка, кольцо, контур, глиф (четыре канала с приоритетами — 03 §4.2a); цвет задаётся на доску (03 §4.2b); состояние — данными экземпляра ISM |
| Канонический путь | детерминированный кратчайший путь с одним правилом выбора среди равных (MS-D-05) |
| След (trail) | публичная запись пройденного пути: `metadata.lastMovement` (MS-D-11) |
| Подсказка (hint) | предложение клетки от сервера; никогда не ставит цель и не подтверждает ход сама (MS-D-21) |
| Слой угроз (threat layer) | показ, кто из врагов сможет атаковать пространство в следующий ход, по публичным данным |
| Нужен буст (NeedBoost) | ход черновика, путь которого есть, но длиннее движения бойца плюс BOOST выбранной карты; `RequiredBoost = длина − движение`; рисуется V-04b, подтверждение заблокировано |
| Конфликт (conflict) | ход черновика, для которого пути нет (занятая цель, блок, порядок, новый снапшот); рисуется V-09 |

## 7. Статус и решения

- Все MS-D — решения оркестратора по постоянному делегированию пользователя («делай все без меня»). Они обратимы.
- **Финальная арт-приёмка** (цвет подложек, высота «подскока», вид следа соперника) — за пользователем
  (`MEMORY: feedback-no-pinging-2026-10-01` — спрашивать только блокеры и финальную арт-приёмку).
- Изменения правил на сервере (MS-T-19, MS-T-20) идут только после сверки с официальными источниками (MS-T-01).
- Покупки Fab (07 §9) делает только пользователь.
- Решения, принятые при исправлении ревью (цвет подложки по доскам, статус NeedBoost, путь на ISM, луч к плоскости
  поля, перевод автодрайвера на черновик, отдельная задача локализации MS-T-28), перечислены в 09 §3 и тоже обратимы.

Открытые вопросы — в 01 §6.
