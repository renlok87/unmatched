## 3. Условия утверждения

1. **Порядок.** Изменения правил на сервере (MS-T-19, MS-T-20) начинаются только после MS-T-01, то есть после сверки
   с официальными источниками Restoration Games. Фан-источники правилами не считаются.
2. **Процесс.** Реализация идёт в отдельном worktree на ветке фичи. Интеграция в `fix/admin-panel` — после каждой
   вехи, только через `tools/git/safe-integrate.sh` (сначала dry run). Коммиты — `git commit --no-verify` (AGENTS.md).
3. **Режимы.** Задачи с новым кэшем, контрактом ошибок, правилами сервера, новыми кнопками или новыми ассетами идут
   в режиме full. Режим light — только MS-T-13 (подбор параметров через live tune, ≤ 3 итерации).
4. **Эталонные кадры.** До арт-приёмки пользователя новая подсветка работает только с флагом `-S08MovePlates`.
   Кадры ENV-MAPS снимаются без этого флага.
5. **Общий парсер.** Правка `S08BoardArt.cpp` (`ParseMoveSelection`) — отдельной функцией. Перед интеграцией нужны
   сверка с актуальным `fix/admin-panel` и прогон `S08BoardArtTests`. Файл ведёт сессия ENV-MAPS (05 §4).
6. **Цвета.** Цвет подложек на картах (`#FFC857` или `#4CD2DC`), высота подскока и вид следа соперника — предложения.
   Их утверждает пользователь на арт-приёмке (MS-Q-04) по концептам MS-T-00 и кадрам MS-AT-30.
7. **Опциональная веха.** Веха M4 (подсказки, слой угроз, точки маршрута, спайки Fab) опциональна и не блокирует M5.
   Для подсказок в PvP (MS-Q-08) нужно решение пользователя до MS-T-22.
8. **Экран паузы.** Экрана паузы UI-SCR-PAUSE в клиенте нет (09 §4 п. 7). Для него заводится отдельная задача GD. До
   её выполнения настройки reduced motion и скорости анимации работают через флаги и ini.
