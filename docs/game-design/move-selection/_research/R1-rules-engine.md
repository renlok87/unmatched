## 1. Короткие выводы

1. Сервер реализует манёвр как **две мутации**: `beginManeuver` (списывает действие и добирает карту,
   создаёт `metadata.pendingManeuver`) и `maneuver` (буст + пути всех бойцов). Отменить начатый манёвр
   нельзя: «Отмена» в клиенте может сбросить только локальный путь; минимальное завершение —
   `moves: []` (`backend/src/game-engine/services/game-action-executor.service.ts:1645-1668`,
   `:1693-1844`; `backend/src/games/resolvers/game-actions.resolver.ts:277-306`).
2. Правила пути (GD-015) едины для валидатора, бота и эффектов: союзник проходим, живой враг
   блокирует, конечное пространство свободно от любого живого бойца, побеждённые не блокируют
   (`backend/src/game-engine/movement/traversal.ts:19-69`). Это совпадает с официальным rulebook.
3. Смежность — одна функция `board-topology.isAdjacent`. На графовой доске соседи — ровно `links`
   (симметризованные), на сетке — 4 ортогональных соседа (`backend/src/game-engine/engine/board-topology.ts:111-201`).
4. **Сервер не отдаёт ни достижимые клетки, ни путь.** Запроса «reachable/legal moves» нет;
   `MovementService`/`AStarService`/`PathCacheService` в продакшен-потоке не вызываются. Клиент обязан
   считать достижимость сам по тем же правилам (раздел 9).
5. **Соперник не видит маршрут.** Журнал `eventsSince` отдаёт `input` мутации только её автору
   (`backend/src/games/game-state.service.ts:1125-1131`), в состоянии остаются только конечные позиции.
   Для MOVE-эффектов сервер принимает только конечную клетку, путь не существует вовсе.
6. Главные расхождения с правилами: буст картой без напечатанного BOOST разрешён (+0); `immobilized` не
   блокирует MOVE/PLACE-эффекты; «move N spaces» без «up to» трактуется как «до N»; PLACE «in any other
   space» не запрещает своё же пространство; двери рассинхронизированы; спецсвязи карт (тайные ходы,
   односторонние пути) не моделируются (раздел 6).
7. Бот двигает **только героя**, **никогда не бустит**, идёт строго ближе к ближайшему вражескому
   герою по графовой дистанции и атакует при досягаемости (раздел 8).
8. Часть проектной документации описывает старый поток (добор после движения, recycle колоды,
   `moveFighter` как действие, сетку без топологии) — раздел 7.

## 4. Поток манёвра на сервере (как есть)

1. **`beginManeuver(input: { gameId, expectedSequenceNumber })`** — guards `GqlAuthGuard, GameInProgressGuard,
   GamePlayerGuard, ActionPhaseGuard`, лимит 30/мин (`game-actions.resolver.ts:277-287`). Проверки:
   свой ход, фаза `ACTION_MANEUVER|ACTION_ATTACK`, нет боя, нет `pendingManeuver/pendingHandDiscard`,
   пустая очередь `pendingEffects`, `actionsRemaining > 0`, совпадение `expectedSequenceNumber`
   (`game-action-executor.service.ts:1649-1658`). Эффект: `actionsRemaining - 1`,
   `maneuveredThisTurn = true`, добор 1 (с истощением), `seq + 1`, `pendingManeuver = { id, playerId }`
   (`:1660-1666`).
2. **Состояние между стадиями** сохраняется (`metadata.pendingManeuver` — `game-state.model.ts:160`),
   переживает перезагрузку JSON и отклоняет повтор (`s03-turn.spec.ts:53-64`). Пока он открыт, атаки,
   схемы, `endTurn`, MOVE-выборы запрещены (`game-action-executor.service.ts:520, 740, 1866`;
   `game-rules.validator.ts:528`).
3. **`maneuver(input: ManeuverDto)`** (`backend/src/games/dto/gameplay.dto.ts:111-159`): `maneuverId`
   обязателен; `moves: [{ fighterId, path: [{x,y}] }]`; `boostCardId?`; legacy `fighterId/path/cardId`.
   `PositionInput.x/y ∈ [0, 19]` (`gameplay.dto.ts:64-77`). Проверки по каждому ходу — `validateManeuver`
   (`game-rules.validator.ts:277-396`): свой боец, жив, не `immobilized`, фаза, буст в руке, путь непуст,
   клетки в границах и проходимы, длина ≤ движение + буст, шаги смежны, нет живых врагов на пути,
   конец свободен. Затем: применение позиций, `seq + 1` один раз, сброс буст-карты, реакции
   `applyMoveReactions`, `pendingManeuver = undefined`, при `actionsRemaining == 0` — передача хода в
   том же ответе (`game-action-executor.service.ts:1781-1818`).
4. **Атомарность**: при ошибке любого хода из `moves[]` весь манёвр отклоняется, добор и списанное
   действие остаются (`s03-turn.spec.ts:64`), `pendingManeuver` остаётся открытым — можно прислать
   исправленные пути.
5. **Передача хода в том же ответе**: если манёвр был последним действием, ответ уже содержит
   turn-end/turn-start хуки (Medusa, Leonardo и т. п.) и, возможно, выбор сброса до 7.

Коды ошибок манёвра, которые клиент должен уметь показать: `FIGHTER_NOT_FOUND`, `NOT_YOUR_FIGHTER`,
`FIGHTER_DEFEATED`, `FIGHTER_IMMOBILIZED`, `INVALID_PHASE`, `HAND_NOT_FOUND`, `CARD_NOT_IN_HAND`,
`EMPTY_PATH`, `INVALID_POSITION`, `NOT_ENOUGH_MOVEMENT`, `INVALID_STEP`, `PATH_BLOCKED_BY_ENEMY`,
`POSITION_OCCUPIED` (`game-rules.validator.ts:286-393`), плюс текстовые ошибки исполнителя
(«Каждый боец двигается в манёвре не более одного раза», «Begin maneuver first…», «Boost must be a card
instance in your hand» — `game-action-executor.service.ts:1712, 1720, 1734`). В GraphQL они приходят
как `BadRequestException` с текстом, не с кодом (`game-actions.resolver.ts:134-138`) — коды
валидатора в текст ошибки не попадают (не проверено, попадает ли `code` в extensions).

### 5.2. Буст

- **R1-B04. BOOST в контенте** (экземпляры карт, все 70 колод): 0 — 9 (Loki «Trick»-карты), 1 — 577,

- **R1-B05. Буст без значения.** `boostValue ?? 0` — карта с `null` или 0 принимается и даёт +0

- **R1-B06. Буст при пустой руке.** После `beginManeuver` в руке ≥ 1 карта, если колода не пуста;
  при истощении рука может остаться пустой → буст невозможен.
- **R1-B07. Буст без движения.** `moves: []` + `boostCardId` — карта сбрасывается без эффекта
  (`game-action-executor.service.ts:1787-1789`). Правилами не запрещено явно; **не проверено**.
- **R1-B08. Один буст на манёвр**, одно поле `boostCardId`; одинаковый для всех бойцов.

### 5.3. Длина пути и радиус

- **R1-B09. Допуск = движение + буст.** Минимум 1 (движение 1, без буста). Обычный максимум
  контента 3 + 4 = 7; с подозрительной картой 3 + 6 = 9. MVP: Medusa/Harpies 3..7, Arthur/Merlin 2..5.
- **R1-B10. Формат пути.** Без стартовой клетки; `path.length` = число шагов; пустой путь для бойца
  в `moves` → `EMPTY_PATH` (чтобы «не двигать», бойца не включают); петли разрешены
  (A→B→A стоит 2 шага, конечная = старт — проверка конца пропускается, `game-rules.validator.ts:384-393`);
  повтор клетки внутри пути не запрещён; путь со стартом в начале → `INVALID_STEP`.
- **R1-B11. Верхней границы массива в DTO нет** (`ManeuverMoveInput.path` без `ArrayMaxSize` —
  `gameplay.dto.ts:83-95`); фактически ограничено допуском.

### 5.5. Занятость, союзники, враги

- **R1-B16. Конечная клетка.** Ни одного другого живого бойца (свой или чужой); на своей клетке
  остаться можно (путь-петля).
- **R1-B17. Промежуточная клетка с союзником** — проходима; с живым врагом — нет; с побеждённым —
  свободна. Враг на конечной клетке даёт код `PATH_BLOCKED_BY_ENEMY`, а не `POSITION_OCCUPIED`
  (порядок проверок `game-rules.validator.ts:372-393`).
- **R1-B18. Исключение «сквозь врагов».** Winged Frenzy: `canPassThroughEnemies` — враги не блокируют,
  конец всё равно свободен (`game-action-executor.service.ts:645-654`;
  парсер — `effect-text-parser.ts:218-229`).

### 5.6. Несколько бойцов в одном манёвре

- **R1-B19. Порядок и взаимная блокировка.** Ходы применяются в порядке массива; каждый следующий
  валидируется на позициях после предыдущих (`game-action-executor.service.ts:1737-1779`). Следствия:
  (а) A может закончить на клетке, которую B освободил раньше в списке; (б) если B ходит позже, клетка B
  для A занята; (в) прямой обмен местами двух бойцов невозможен в любом порядке (так же и по O-3);
  (г) два бойца не могут закончить в одной клетке; (д) путь позднего бойца может проходить сквозь уже
  переместившегося союзника.
- **R1-B20. Максимум бойцов.** Сайдкиков из одной записи не больше 4 (`game-initialization.service.ts:732`),
  записей может быть много: у Squirrel Girl в скрейпе 8 записей → 9 бойцов на стороне
  (**не проверено** против карты персонажа). MVP: 4 бойца у Medusa, 2 у Arthur.
- **R1-B21. Мёртвые сайдкики.** Не могут быть в `moves` (`FIGHTER_DEFEATED`); возврат — только PLACE с
  `restoreFullHealth` (Winged Frenzy), identity сохраняется (`game-action-executor.service.ts:593-597, 686-690`).

### 5.7. Добор и действия

- **R1-B22. Пустая колода при манёвре.** Истощение применяется в `beginManeuver` до выбора путей;
  1-HP сайдкики (Harpies) гибнут и выпадают из манёвра; гибель героя — `GAME_OVER` без
  `pendingManeuver` (R1-M11).
- **R1-B23. Действия.** 2 за ход; оба могут быть манёврами (`s03-turn.spec.ts:28`); атака тратит
  действие при объявлении; `GAIN_ACTION`/`END_TURN` эффектов меняют остаток (`s03-turn.spec.ts:118-153`).
  `beginManeuver` при `actionsRemaining == 1` ставит 0, но ход не передаётся до `maneuver`.
- **R1-B24. Повтор/гонка.** Повтор `beginManeuver` с устаревшим `expectedSequenceNumber` отклоняется;
  повтор `maneuver` с уже закрытым `maneuverId` отклоняется (`s03-turn.spec.ts:53`). Лимит 30 мутаций
  в минуту на `beginManeuver`/`maneuver` (`game-actions.resolver.ts:279, 292`).

### 5.8. Эффекты MOVE / PLACE

- **R1-B25. Значение MOVE.** `pending.value ?? 1`; парсер даёт `value || undefined`, то есть 0 → 1
  (`backend/src/game-engine/effects/card-effect-executor.service.ts:697, 735, 758`;
  `game-action-executor.service.ts:647`). Значения MVP: Hounds of Mighty Zeus «each Harpy up to 3»,
  Dash «up to 3», Winged Frenzy «each of your fighters up to 3», Swift Strike «up to 4», Command the
  Storms «each fighter up to 3 (включая чужих)», Divine Intervention «King Arthur up to 5», Skirmish «один
  из участников боя up to 2», Bewilderment «place your fighter in any space» (S01-снимки).
- **R1-B26. EACH.** «Each …» — отдельный pending на каждого живого бойца, строго по очереди;
  `EACH_FIGHTER` (Command the Storms) — всегда `optional`, двигаются и чужие (`card-effect-executor.service.ts:684-716`).
- **R1-B27. COMBAT_FIGHTER** (Skirmish): один pending, выбор любого живого участника боя, `anyOwner`
  (`card-effect-executor.service.ts:720-751`).
- **R1-B28. Нет целей.** MOVE без живых целей не создаёт pending (`card-effect-executor.service.ts:673-675`);
  PLACE без свободной клетки — серверный авто-резолв возвращает `null` (`game-action-executor.service.ts:883-888`),
  mandatory-выбор зависает (R1-D07).
- **R1-B29. Зонное ограничение PLACE.** Только `zoneFighterName` (возврат Harpy в зону Medusa) —
  `game-action-executor.service.ts:672-679`.
- **R1-B30. Движение в чужой ход.** After-combat эффекты защитника (Dash/Skirmish на защите)
  создают выбор, принадлежащий защитнику, в ход атакующего; turn-start способности (Leonardo,
  `ability-config.ts:681-695`) — в начале хода нового игрока; реактивный урон Tomoe — в любой ход.
  Владелец выбора резолвит его без проверки «чей ход» (guard без `ActionPhaseGuard` —
  `game-actions.resolver.ts:434`).
- **R1-B31. Способности с MOVE.** `pending-move` (Robin Hood после атаки, до 2 — `ability-config.ts:662-673`;
  Leonardo в начале хода, до 1, только свои — `:681-695`; Bruce Lee, до 1, свой герой — `:755-764`)
  создают **mandatory** MOVE (поле `optional` не ставится — `generic-hero-ability.handler.ts:870-878`);
  «остаться на месте» закрывает такой выбор.

### 5.9. Прочее

- **R1-B32. Двери.** Клетка `door` с `isOpen=false` непроходима (`traversal.ts:28-31`); `toggleDoor`
  меняет только словарь `boardState.doors`, не `cell.isOpen` (`game-action-executor.service.ts:2846-2858`) —
  R1-D10. На текущих досках дверей нет.
- **R1-B33. Позиции побеждённых.** Живой боец может закончить на координатах побеждённого
  (`isFreeEndpoint` их игнорирует) — две записи `fighters[]` с одинаковой позицией возможны.

**P2** — затрагивает героев вне MVP или редкие случаи; **P3** — технический долг.

## 8. Как бот выбирает ход

Источник: `backend/src/game-engine/services/ai-decision.service.ts`, исполнение —
`backend/src/games/services/ai-turn.service.ts:29-140` (те же продакшен-методы, что у человека).

Порядок решения `decide` (`ai-decision.service.ts:40-114`):

1. Свой выбор сброса до 7 → первые `count` карт руки (`:43-48`).
2. Открытый свой `pendingManeuver` → путь **только для героя** (`aiHero` — первый живой HERO, иначе
   первый живой боец — `:365-368`), если он не обездвижен; допуск = `getFighterMovement(hero)` **без буста**;
   `boostCardId` не передаётся никогда; если пути нет — `moves: []` (`:49-58`).
3. Голова очереди выборов: чужая → ждать (`null`); своя → `decidePending`, иначе optional отклонить
   (`:63-71`).
4. Бой: защита лучшей картой по `defenseValue`, затем резолв (`:74-92`).
5. Свой ход: при `actionsRemaining == 0` — `endTurn`; иначе ближайший враг (приоритет вражеским
   героям, дистанция `distanceField` — граф BFS на топологии, манхэттен на сетке — `:370-378`);
   если враг смежен или (ranged и общая зона) — атака лучшей картой по `attackValue` (ATTACK предпочтительнее
   VERSATILE при равенстве, с проверкой баннера — `:286-300`); иначе `beginManeuver` (`:95-113`).

Выбор пути `pathToward` (`:422-459`): BFS от героя по `getAdjacentCells` (топология учитывается),
живые враги — стены, союзники проходимы, конец — только на свободной клетке; выбирается первая
найденная клетка с **строго меньшей** статической графовой дистанцией до цели (при равенстве — более
короткий путь и порядок соседей: N, E, S, W на сетке, порядок `links` на графе). Если ближе подойти
нельзя — путь пустой. Тесты: `ai-decision.service.spec.ts:74-116`, `board-topology.spec.ts:596-688`,
`env-maps-board-contract.spec.ts:509`.

MOVE-выборы (`:246-272`): для чужого бойца — «остаться на месте»; для своего — шаг к ближайшему врагу
не дальше `value` (или движения бойца), иначе отказ (optional) или нулевой шаг (mandatory). Revive-PLACE —
свободная клетка зоны якоря, ближайшая по графу (`:231-244, 380-397`).

Ограничения бота, важные для «подсказок» игроку:

- сайдкики (Harpies, Merlin) в манёвре не двигаются никогда;
- буст манёвра не используется, буст-карты в руке не оцениваются по BOOST;
- ranged-герой (Medusa) подходит вплотную вместо позиции «в зоне цели, вне смежности»;
- статическая дистанция не учитывает блокировки бойцами — бот может «упереться» в союзника/врага;
- нет оценки угрозы (дистанция до вражеских атак), нет учёта зон для собственной ranged-атаки после
  движения, нет планирования двух действий (манёвр + атака той же картой после добора).

Это не нарушает правил, но означает, что любой будущий «советчик хода» для игрока нельзя строить на
текущей эвристике бота без расширения (оценка позиций, буст, сайдкики).

## 9. Следствия для клиента (сводка требований из матрицы)

1. **Данные для подсветки**: `boardState.cells[y][x]` (`type`, `zones`, `links`, `spaceId`, `start`),
   `fighters[]` (`ownerId`, `position`, `movement`, `health`, `isDefeated`, `effects`),
   `metadata.pendingManeuver`, `metadata.pendingEffects[0]`, `handZones[me].cards[].boostValue`.
2. **Алгоритм достижимости** = копия правил сервера: граф (`links` симметризованные, иначе 4 соседа в
   границах), клетка проходима, если `type` не `wall/obstacle/door(closed)` и существует; живой враг (для
   владельца двигаемого бойца) — стена (кроме `canPassThroughEnemies`); союзник — проходим, но не
   цель; конец — без живых бойцов; BFS до `movement + boost` (или `pending.value`). Источник истины —
   `traversal.ts:19-69`, `board-topology.ts:174-201`, `game-rules.validator.ts:337-393`.
3. **Отправка**: путь без стартовой клетки, координаты решётки `{x,y}` (не `spaceId`), `moves` в
   выбранном игроком порядке, бойцы с нулевым ходом не включаются, `boostCardId` — instance id.
4. **Превью нескольких бойцов**: последовательная симуляция позиций (R1-B19).
5. **Отмена**: до `beginManeuver` — полная; после — только локальные пути и буст; серверный минимум
   завершения — `moves: []`.
6. **Соперник**: маршрута в данных нет (R1-D03/D04) — анимировать достроенный кратчайший путь на
   состоянии до хода либо добавить серверный публичный след.
7. **Ошибки**: показывать текст сервера и откатывать локальный путь к последнему снапшоту; атомарность —
   весь `moves[]` или ничего.
8. **Пустая колода**: предупреждение до `beginManeuver` (истощение).
9. **Зоны**: в превью конечной клетки показывать, кого можно будет атаковать (melee — смежные, ranged —
   смежные или общая зона).
