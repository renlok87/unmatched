# 02. Правила перемещения для клиента и граничные значения

Дата: 2026-10-03. Статус: ПРЕДЛОЖЕНИЕ, v2 (после адверсариального ревью — [09](09-review-log.md)). Основа —
[R1](_research/R1-rules-engine.md) (правила и движок), [R2](_research/R2-client-current.md) (клиент),
[R4](_research/R4-tech-patterns.md) §7 (граничные значения). Факты кода перепроверены на HEAD `29080626`.

Иерархия истины: **официальные правила → сервер → клиент**. Клиент повторяет сервер, даже если сервер расходится с
правилами; расхождение исправляется на сервере отдельной задачей, после чего клиент следует новому серверу (MS-D-01,
MS-D-19). Клиент никогда не строже сервера: подсветка «нельзя» там, где сервер разрешил бы, — тоже дефект (AP-16).

## 2. Алгоритм достижимости для клиента (нормативная сводка)

Полная спецификация и паритет — 04 §3. Здесь — правила одного шага (R4 §3.2, проверено по `traversal.ts:19-69`):

| Пространство | Войти как промежуточное | Закончить ход |
|---|---|---|
| пустое проходимое | да | да |
| стена, препятствие, закрытая дверь, отсутствующая клетка, не-пространство решётки на графовой карте (`obstacle`) | нет | нет |
| живой союзник (`isLivingFighter`) | да | нет |
| живой враг (для владельца двигаемого бойца) | нет (кроме `canPassThroughEnemies`) | нет |
| побеждённый боец (`health <= 0` или `isDefeated`) | как пустое | как пустое |
| собственная стартовая клетка | — | да, это «остаться»: записи в `moves[]` нет |
| соседняя по решётке без связи (графовая карта) | не сосед | не сосед |

Предикаты «живой» разделены по ролям, как на сервере: **блокирующий и занимающий** боец — `isLivingFighter`
(`health > 0 && !isDefeated`, `traversal.ts:19-21`); **двигаемый** боец отклоняется только при `health <= 0`
(`game-rules.validator.ts:294-296`, MS-E-77).

Допуск: `getFighterMovement(fighter) + boostValue(выбранной карты)` для манёвра; `pending.value ?? 1` для MOVE-эффекта
(отсутствие → 1, `0` → 0; MS-E-57, MS-E-76).
