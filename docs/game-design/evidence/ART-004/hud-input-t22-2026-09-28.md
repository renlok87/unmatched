## Сборка editor target при живом Live Coding главного редактора

Проверено. Главный редактор (PID 19540) держит мьютекс `Global\LiveCoding_C++Program Files+Epic Games+UE_5.8+Engine+Binaries+Win64+UnrealEditor.exe`. Имя строится от общего `UnrealEditor.exe` установленного движка, поэтому UBT отказал бы в сборке любого editor target (`HotReload.cs`, `CheckForLiveCodingSessionActive`). Флаг `-NoHotReloadFromIDE` (`bAllowHotReloadFromIDE=false`) снимает только эту проверку и **сохраняет `WITH_LIVE_CODING 1`**, в отличие от `-NoLiveCoding` (риск R3). DLL арт-worktree лежит в её собственном `Binaries`, поэтому то, что загрузил живой редактор, не перезаписывается. Сборки [E3–E6](hud-input-t22/build/) прошли успешно, во всех SharedDefinitions `WITH_LIVE_CODING 1`, мьютекс существовал до и после. Прежний UnmatchedEditor арт-worktree был собран с `WITH_LIVE_CODING 0`; это устранено (followup T1.1).

Попутно найдено: editor target не линковался с кодом T1.1 `-S08Perf` (`RHIGetGPUFrameCycles`, `GDynamicRHI`, `GGameThreadTime`, `GRenderThreadTime`, [E2](hud-input-t22/build/E2-editor-build.json)). Монолитный game target скрывал это. В `Unmatched.Build.cs` добавлены приватные зависимости `RHI` и `RenderCore`. Сборка E1 упала на моём C4458 (затенение `StatusLine`), исправлено.

Game target собран без `-NoLiveCoding` ([G1–G4](hud-input-t22/build/), `WITH_LIVE_CODING 1`). `package-client.ps1 -SkipBuild` прошёл 4 из 4 раз, из них P1–P4 — cook с новой editor DLL (`WITH_LIVE_CODING 1`). Гейт «cook 3/3» выполнен; риск R3 на этой DLL отсутствует. Текстуры `T_UI_Action_Attack_{24,32,48}` приготовлены (ReferencedSet cook). Stderr всех 14 процессов E1–E6, G1–G4 и P1–P4 был пуст (0 байт), поэтому пустые файлы `*.log.err` в доказательства не включены.

## Ограничения и открытое

1. **Реальный ввод не проверен.** Путь `src=os` (колесо, Space, клики, hover) в коде есть, но в offscreen-прогонах не срабатывал. Это T4.3. Hover учитывается, только если курсор ОС действительно сдвинулся, чтобы offscreen-кадры оставались детерминированными.
2. **Зум — предложение (Q-302).** Ближний предел 300 uu соответствует 6,44× и повторяет измеренную пробу 5×. 03 §2 предлагает 1,6×. Параметры можно поменять в ini или CLI без правки кода.
3. `SHOT reachable` содержит **назначения** выбора: 13 клеток без своей. Своя клетка (нулевой ход, `legal=14`) не считается целью клика, потому что клик туда попадает в саму фигуру. Строка `SHOT selection` фиксирует это как `ownCellExcluded=1`.
4. Текст плашки ASCII/английский, без кириллицы: шрифт по умолчанию. Статусы из `effects[]` не проверены живьём: в проекции Cobble `effects` пуст.
5. При промежуточных зумах плана (1,02–1,28×) плашка иногда уходит на 94–174 px, потому что ближе чистого места нет. На K2-кадрах 1,6× и 5× зазор 6 px.
6. Иконки 24/32/48 — концепт ART-003 в точных размерах, художественно не приняты. Проверка 24 px пройдена только по контрасту: 10,8:1 на фоне доски.
7. `manifest.json` прогона K3 после отменённого дополнения пересохранён Python-JSON-ом. Список файлов и sha256 прежние, validation переписана.
8. Проверка `snapshot_baseline.py check`, запущенная из арт-worktree, разрешает корень «repo» относительно своей копии и даёт ложные различия. Из главного checkout: 62 файла, 0 различий. Production не тронут.
