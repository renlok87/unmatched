# Medusa в Tripo Studio: проверенные инструменты и порядок доводки

Срез на 2026-09-27 для [задания Medusa `d562f057-1455-4663-8cd8-bb738175111d`](https://studio.tripo3d.ai/ru/workspace/generate/d562f057-1455-4663-8cd8-bb738175111d). Это рабочая карта интерфейса **Studio**, а не описание API. Факты о конкретной модели получены в Studio и проверены на экспортированном GLB в Blender 5.2.2; возможности без выполненной операции помечены как непроверенные на Medusa. Предыдущий [пилот H3.1](../tripo-pilot-20260927/README.md) остаётся исходным художественным эталоном, а ART-004 ещё не принят.

## Проверенная карта функций Studio

| Функция | Что показал интерфейс на Medusa | Практическое применение и ограничение |
| --- | --- | --- |
| **Model / Smart Mesh** | Исходник сделан HD H3.1; отдельный режим Smart Mesh доступен при генерации. | Для нового варианта P2.0 может сразу строить квады и семантические части, но это **новая генерация**, не улучшение уже принятого лица. Сохранять H3.1 как референс. [Анонс P2.0](https://www.tripo3d.ai/blog/tripo-august-update) описывает нативные квады и разбиение по частям; результат именно этой Medusa с P2.0 не проверялся. |
| **Segment** | Уровни Simple 3–6, Balanced 6–15, Detailed 15+ частей. На форме один пробный запуск; кнопка отображает `40` и `0` для пробной функции. Встроенный 7-шаговый туториал показывает объединение Ctrl+click, добавление/уточнение части кистью, сохранение, переименование и завершение частей. | Это наиболее прямой способ отделить **лук, тело и подставку**. Семантические границы надо проверить вручную у пальцев, тетивы, змей и плаща. Пробная сегментация Medusa **не запускалась**, поэтому качество разделения и фактическое списание не подтверждены. [Описание Segmentation v2](https://www.tripo3d.ai/blog/tripo-segmentation-v2). |
| **Fill Parts** | Раздел доступен, но для неразделённой Medusa предлагает сначала сегментацию. | После разрезания открытые срезы можно закрыть Quick Cap или AI Completion. Официальная документация называет Quick Cap бесплатным и AI Completion доступным на платном плане без кредитов; после экспорта проверять реальные отверстия и внутренние поверхности. [Официальное описание](https://www.tripo3d.ai/blog/tripo-segmentation-v2). |
| **Retopology** | Quad/Triangle, Smart Mesh P1.0, ручная цель 500–10 000; заказанный вариант дал 10 485 квадов в UI и 19 486 tris в GLB. | Для бюджета ART-004 этот результат годится как низкополигональная **основа**. Он не создаёт деформационный риг и не разделяет лук/базу. Визуальную сохранность локтя, кистей и тетивы проверять отдельно; [руководство Tripo](https://www.tripo3d.ai/blog/ai-workflow-to-reduce-manual-retopology) тоже оставляет ручную правку для деформируемых hero-моделей. |
| **Smart UV** | Для ретопологии кнопка активна, 2 пробных запуска, затем в UI 20 кредитов. Текущее заполнение 31,6%. Интерфейс прямо предупреждает: **новая развёртка удалит текущую текстуру; после сохранения модель надо текстурировать заново**. | Не нажимать ради одной цифры заполнения: текущие UV и перенос PBR уже работают. Переразвёртка оправдана только при видимых швах/искажениях и с отдельным планом ретекстурирования. Лимит 80k tris/40k quads указан в [официальной статье](https://www.tripo3d.ai/blog/smart-uv); исходный 1,88M-меш превышал лимит. |
| **Texture Gen** | Есть входы по изображениям, модели и тексту; у Medusa подставлены её исходные виды. Видны Remove Lighting, 2K/4K/8K, кнопка `30` с пробной отметкой `0`. | Полная новая текстура на существующей топологии, если Smart UV её заменит или если палитра не проходит художественный gate. Наблюдаемая цена — форма Studio на этом аккаунте, не публичный API-тариф. [Руководство по ретекстурированию](https://www.tripo3d.ai/blog/upscale-retexture-existing-model). |
| **Magic Brush / Правка** | Режимы генерации и рисования, маска на поверхности, текстовый запрос, сила креатива, платный preview (`5` в UI) и сохранение. | Подходит для отдельных цветовых/текстурных дефектов, не чинит сетку и не отделяет оружие. [Описание кисти](https://www.tripo3d.ai/blog/repaint-specific-texture-area). |
| **Texture Upscale / PBR** | Upscale предлагает 4K/8K (8K помечен Max trial; форма `20`/`0`), PBR Generator — `5` кредитов. | У экспортированного ремеша уже есть BC/N/RM и для игры нужны 2K-карты; увеличение до 8K не решает задачу. PBR перегенерировать только если карты дают неверный отклик в свете UE. [Официальное сравнение инструментов](https://www.tripo3d.ai/blog/upscale-retexture-existing-model). |
| **Rig** | Human/Other. Для Human — пресеты **ActorCore, Mixamo, UE5 Mannequin, VRM 1.0, Unity Humanoid**, кнопка Auto-rig `20`; подсказка требует чистую **T- или A-позу**. | Пресет UE5 полезен для движка, но текущая Medusa держит лук, а подставка слита с ногами. [Help Center](https://www.tripo3d.ai/help/features/is-it-possible-to-upload-my-existing-model-for-animation) прямо ограничивает авто-риг T-позой гуманоида и стоящим четвероногим. Сначала отделить аксессуары/базу или привести тело к нейтральной позе; не считать UI-пресет гарантией исправных весов. На Medusa Auto-rig ещё не запускался. |
| **Animate** | Библиотека пресетов содержит, среди прочего, `стоя_отдых`, `выстрел`, `удар_спереди`, `падение`; на каждой карточке сейчас `Сначала риг`. Text-to-motion показывает `20` и длительность 5 с по умолчанию, видео-в-движение в UI недоступно; есть многоэтапное движение. | Можно испытать после хорошего рига, но эти общие пресеты не равны требуемым Idle/LungeAttack/HitReact/DeathSettle с длительностями, неподвижным root, сокетами и корректным оружием. [Официальный обзор](https://www.tripo3d.ai/blog/apply-preset-animations-to-3d-character). |
| **Export / DCC Bridge** | В экспортном диалоге доступны FBX/GLB и другие форматы, выбор texture tier и `Send To`. GLB ремеша скачан и проверен. Панель Bridge в последней проверке показывала Blender v1.0.3, Unreal v1.0.4, оба **switch off**; ранее в пилоте Blender был connected — состояние соединения динамическое. | Bridge передаёт модель прямо в открытую сцену/проект, но не доказывает масштаб, материалы, скелет или UE-приёмку. Для Blender нужен активный аддон и `Connected`; UE-плагин работает в Editor mode и подключается к первому запущенному UE. Настройки UE по умолчанию: bottom-center pivot, max texture, auto material, auto placement. Не отправлять в пользовательскую Blender-сцену без проверки назначения. [Blender Bridge](https://www.tripo3d.ai/integrations/blender), [UE Bridge](https://www.tripo3d.ai/blog/tripo-dcc-bridge-for-ue), [форматы и ручной экспорт](https://www.tripo3d.ai/help/features/how-to-export-and-import-to-dcc-tools). |

Официальные страницы иногда называют другой тариф или шире описывают возможности, чем текущий интерфейс; для расхода кредитов и доступности функции авторитетна **форма Studio в момент запуска**, для качества — только экспорт и проверка в Blender/UE.

## Порядок дальнейшей работы с этой моделью

1. Сохранить H3.1 и уже оплаченный ремеш как неизменяемые исходники. Проверить, может ли **Balanced Segment** выделить целый лук, подставку и тело, не разрезав кисть или змеиную корону. При успешном split сохранить отдельную версию, экспортировать и сравнить силуэт/UV/текстуры и полигональный бюджет. При плохих границах исправить кистью в Studio или локально в Blender, не принимать результат автоматически.
2. Не применять Smart UV к уже текстурированному ремешу до диагностированного дефекта UV. Если развёртка всё-таки понадобится, сначала выбрать путь переноса/повторной генерации текстуры и сохранить исходный GLB.
3. Проверять Tripo Auto-rig **только на отделённом теле в нейтральной позе**. Если это невозможно без повреждения внешнего вида, использовать Blender для контролируемого рига и весов. Не тратить кредиты на анимации до проверки сгибов рук, ног, шеи и независимости подставки/лука.
4. Bridge использовать для ускорения передачи проверенного кандидата, затем независимо пройти контракт [ART-004](../README.md): 50–55 uu, pivot/ориентация, 2K BC/N/ORM, TeamColor, сокеты Weapon/Head, четыре клипа без root motion, выбор через коллизию, K1/K2/K3 с HUD и packaged-проверку. Изолированный Blender-рендер этого не закрывает.

До этого аудита был создан черновой [Blender build script](../../../../../blender/ASSET-MEDUSA-001/build_tripo_medusa.py) и FBX в `blender/ASSET-MEDUSA-001/export/`; это **не проверенный игровой ассет**. Черновик не подменяет рассмотренные функции Tripo и не должен импортироваться как окончательная Medusa, пока не проверены деформации, части, материалы и UE-гейты.
