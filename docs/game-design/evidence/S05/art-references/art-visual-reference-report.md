## Root motion record (unit-contract pass)

```
S05_RM_CLIP root_track t0=X=0.000 Y=0.000 Z=0.000 mid=X=0.000 Y=52.579 Z=0.000 end=X=0.000 Y=100.000 Z=0.000 enable_rm=1 len=1.208s
S05_ROOTMOTION_RESULT delta=(x=0.00 y=100.00 z=0.00) rm_frames=1055
```

The morning recipe (`import_uniform_scale=100`) was WRONG on both ends: UE multiplies every FBX number by the file UnitScaleFactor AND puts that x100 factor on skeleton bone 0, which root-motion consumption applies a SECOND time (measured: `delta=(0,10000,0)`). The export recipe is now: Blender bakes x100 into bones/curves/mesh data/locations (`scale_rig_units` + `scale_objects_units` in `blender/S05/build_medusa.py`, undone after export), every FBX is patched to UnitScaleFactor=1.0 (`patch_fbx_unit_scale`), and UE imports with `import_uniform_scale=1.0` — every number lands 1:1 as uu, bone-0 scale is exactly 1, and the same contract fixed the K3 missing-bodies defect (ref/clip factor mismatch collapsed played clips to 1/100).
