панель показывала чёрным, и первый же сдвиг ползунка красил остров в чёрное.

## 2. Новые строки только правкой реестра (без C++)

- **«Огни вклейки (режим вклейки)»** — `conceptPaste.lights` (5 огней Sarpedon × сила / радиус / цвет / мерцание), та же
  область, что у огней lit3d: применяется сразу (0,05 мс, без пересборки).
- **«Тон вклейки (пересборка)»** — `conceptPaste.grade`: `gainLinear`, `devignette`, `emissiveScale`.
- Режим вклейки: `-EnvLayoutVariant=concept` (`concept-paste mode=on … reason=variant`). Тон ×1,45 + огонь форта 220 кд
  `#FF5020`: [03](03-paste-tone-and-light-before-after-K1.jpg) — картинка ярче, огонь ярче и краснее, доска не тронута.
  Сохранение: [S08ArtTuner.overrides.paste-mode.json](S08ArtTuner.overrides.paste-mode.json).
- В режиме lit3d тон вклейки **не действует**: ×2 даёт среднюю разницу 0,44 / 0,49 (K1 / K2x1.6) — уровень шума,
  [04](04-paste-tone-x2-in-lit3d-no-effect-K1.jpg). Это записано в подсказке строки.
- **Эффекты раскладок** (`fx[].user` в `EnvLayouts/*.layout.json`) правкой реестра не добавить: панель работает с одним
  документом — профилем; раскладки — отдельные файлы. Нужен код (второй документ в модели, внесение в раскладку).
- Новая строка реестра в собранном клиенте видна после упаковки без компиляции (`package-client.ps1 -SkipBuild`): реестр
  лежит в pak.

## 4. Новый эталон K1 Sarpedon

Паспорт: [k1-reference-sarpedon.json](k1-reference-sarpedon.json). Кадры — вне git, по прежнему пути
`C:/tmp/envmaps-research/lightcheck/sarpedon/`; старый эталон P9b сохранён как `…/lightcheck/sarpedon-p9b-2026-10-02/`.
Миниатюра: [08](08-new-k1-reference-sarpedon.jpg).

- Три свежих упакованных `-Bench` на `fe12eb7c` с командной строкой старого эталона (60 FPS, High, K1 + K2x1.6 + K2x2.5).
  Эталон — прогон-медоид (run2). Рядом в `noise/` лежит второй прогон (run3) для маски шума.
- `render_fingerprint.py check`: `reference=true` на всех трёх видах, `profilesSource=pak`, `profilesSha256=23e4ebed…`.

| Средняя абсолютная разница / пиксели > 24, % | K1 | K2x1.6 | K2x2.5 |
|---|---|---|---|
| шум: run2 ↔ run1 | 0,339 / 0,054 | 0,387 / 0,119 | 0,372 / 0,003 |
| шум: run3 ↔ run2 | 0,305 / 0,052 | 0,370 / 0,111 | 0,348 / 0,005 |
| контроль run1 ↔ новый эталон | 0,339 / 0,054 | 0,387 / 0,119 | 0,372 / 0,003 |
| то же вне маски шума (`--noise …/sarpedon/noise`) | **0,304 / 0,0001** | **0,340 / 0** | **0,362 / 0,0007** |
| сегодняшние прогоны ↔ старый эталон P9b | 0,34–0,44 | 0,40–0,51 | 0,36–0,48 |

- Средняя разница ≤ 0,5 к новому эталону выполняется с запасом. Порог «пиксели > 24 ≤ 0,05 %» на K1 и K2x1.6 не держат
  даже два свежих прогона подряд (огонь, вода, водопад). Поэтому сравнивать нужно с маской шума: проходит на всех видах
  (`passOutsideNoise=true`).
- Сегодня и старый эталон даёт K1 0,34–0,44, а в M6 было 0,59. Расхождение M6 — состояние машины в тот момент, а не сам
  кадр. Новый эталон снят с той же сборкой, что сейчас в `StagedBuilds`, и у него есть парный шумовой прогон.

Команда для следующих сравнений:

```
python tools/art/render/live_tune.py bench --packaged --map sarpedon --views K1+K2x1.6+K2x2.5 --out <папка>
```
