## Проверенный объём

1. **Полный порядок выдачи — (sequenceNumber, GAME_ENDED-last, timestamp, id)**
   (`GameStateService.getEventsSince`): терминальная пара делит один seq; при
   равных timestamp порядок раньше решал случайный UUID и GAME_ENDED мог
   встать ПЕРЕД своим действием. Теперь терминал строго последним в группе
   seq — и на boundary-разрезе, и вне границы; порядок стабилен между
   выборками. Курсор клиента — seq (`gt: lastSequence`), поэтому
   внутристраничный порядок не влияет на границы страниц.
2. **Cursor-контракт + complete-boundary.** Страница (take 100) дополняется
   до полной группы boundary-seq: терминальная пара доставляется целиком,
   следующий `gt: lastSequence` пропускает её без потерь и дублей; страница
   может превысить 100 на хвост группы.
3. **151-строчная синтетическая регрессия** (149 филлеров + пара на seq 150)
   — доказательство multi-page catch-up: полный журнал ровно один раз,
   терминал последним.

## Residual (явные, не закрытые в этом пасе)

1. **Поздние асинхронные journal-записи.** `GameAction` пишется после
   коммита состояния (`GameActionProcessor`/`AiTurnService.recordJournal`) и
   может закоммититься позже, чем клиентский курсор `eventsSince` уже прошёл
   её sequenceNumber. Complete-boundary покрывает группы в пределах самой
   выборки, но не гонку «запись прилетела ПОСЛЕ выдачи страницы» — против
   перекрёстных поздних записей гарантий нет. Простой nonbreaking
   серверной митигации нет: синхронная запись журнала в транзакции мутации —
   широкое изменение production-путей (не в этом bounded-пасе). Следствия
   закрывает контракт (`16-network-contract.md` §3–4): журнал — НЕ replay,
   свежесть состояния гарантирует snapshot (`gameState` + connection
   barrier); клиент обязан НЕ проигрывать CUE записей с seq <= применённого
   им sequenceNumber.
2. **Live catch-up ≠ multi-page proof.** Число записей живого матча не
   гарантировано >100: full-match чек доказывает end-to-end доставку (весь
   журнал ровно один раз, терминал последним, приватность на страницах),
   а разрез по границе страницы доказывает только синтетическая 151-строчная
   регрессия.
3. **BullMQ combat-timeout в live-прогон не поднимается** (упрощение
   харнесса full-match): дедлайны боя проверяются юнит-прогонами
   (`ai-turn`/`s07` specs), живой матч отвечает защитой немедленно.
