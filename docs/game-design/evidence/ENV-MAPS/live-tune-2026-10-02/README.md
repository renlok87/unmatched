# Live tune: подгонка без перезапуска игры (2026-10-02)

Статус: **сделано и измерено.** Это инструмент, визуал не менялся.

Запрос пользователя (дословно): «Конечно, делай и закрепи это в основном пайплайне.» Это ответ на предложение
«Подгонка без перезапуска игры. Перечитывать профиль света и сцены «на лету» и снимать кадры консольной командой в уже
запущенной игре. Итерация подгонки сократится с ~15 минут до 2–3.» Закреплено в AGENTS.md («Iteration speed»).
Как пользоваться: `tools/art/render/LIVE-TUNE.md`.

Профили света, раскладки, `docs/art-pipeline/render-reference.json` и визуальный результат не менялись. Без флага
`-ArtLiveTune` код не работает. Свежий `-Bench` на новом бинарнике против кадров P9b старого бинарника (тот же профиль, sha
`23e4ebed…`): средняя |разница| 0,26–0,52, вне шума бенча 0–0,008 %. Это уровень разницы между двумя свежими бенчами.

## Что сделано

Клиент, файлы `unreal/Unmatched/Source/Unmatched/S08/`:
- `S08LiveTune.h/.cpp` — протокол `cmd-<seq>.json` → `done-<seq>.json`, разбор команд, модель времени `-Bench`.
- `S08FlowGameModeLiveTune.cpp` — сессия в game mode:
  - после инициализации фикстуры `-Bench`: прогрев, затем `ready.json`;
  - команды `reload` / `shot` / `state` / `quit`;
  - `bench.trace.log` кадра собирается из строк журнала трассы.
- `S08BoardActor` — `ReloadArtData`:
  - проверяет профиль и все раскладки с оверлеями до любых изменений;
  - сносит арт-рантайм до состояния после BeginPlay;
  - следующий `Rebuild` — полный, обычным путём.

  Также `RequestFullRebuild`, override режима fx для `live:true`, `GetBuildCount`.
- `S08FlowGameMode` — `BenchSetupView` / `BenchCameraSettled` вынесены из `RunRenderBench` и общие с live-кадром; имя кадра
  `S08LiveTune::ShotFileName`.
- `S08FighterActor` — позиция зацикленного клипа (`GetHeroClipTime` / `ShiftHeroClipClock`).
- `S08TraceLog` — журнал и копия строк в файл кадра; работают только с флагом.

Драйвер `tools/art/render/live_tune.py`: `start` / `reload` / `shot` / `cycle` / `state` / `stop`, плюс `bench` (свежий
`-Bench` для сверки), `compare` (числа точности, `--noise`), `--check`. Замок `C:/tmp/unmatched-gpu.lock` держится на всю
сессию: `owner=LIVE-TUNE pid=<клиент> map=…`.

## Точность: свежий `-Bench` против live-сессии

Порядок на карту:
1. `bench` ×2 (a1, a2 — второй даёт шум бенча);
2. `start`, `shot` → b0;
3. правка через reload копии профиля, `shot` → b1:
   - Sarpedon — `sarpedon-night heroLight.key.lux` 7 → 14;
   - Cobble — `cobble-probe points[warm].intensity` 85 → 170;
4. `reload` исходного файла (вернуть как было), `shot` → b2;
5. `shot --clock free` → b3;
6. ещё раз reload + `shot` → b4.

Числа — `fidelity.json`, картинки — `montage-<карта>.jpg`:
- столбцы: свежий бенч, live после возврата, live с правкой, |правка − возврат| ×4;
- строки: K1 и K2x2,5;
- правка видна только на фигурах, то есть там, где ожидалось.

Гейт задачи — средняя |разница| ≤ 0,5 и пикселей с разницей > 24 ≤ 0,05 %. В ячейках: средняя |разница| / доля пикселей
> 24 / та же доля вне маски шума бенча. Маска шума — пиксели, где a1 и a2 различаются > 8, расширенные на 3 px; это 0,7–1,1 %
кадра: огонь Niagara и вода, которая движется со временем мира.

RENDER-отпечаток всех кадров b0 / b2 / b3 / b4 — `reference=1`, `profilesSource=pak`, sha `23e4ebed…` как у бенча.
Кадр b1 читался из копии профиля, поэтому у него `profilesSource=override`, `reference=0`; так и должно быть.

**Итог.**
- **Вне шума бенча гейт пройден на всех видах обеих карт после reload и возврата:** пикселей > 24 не больше 0,0005 %.
- Без маски Sarpedon K2x1,6 даёт 0,11 %. Ровно столько же между двумя свежими бенчами: это огонь и вода, а не live tune.
- **Не пройдено по средней:** Cobble K2x2,5 даёт 0,67–0,72 при гейте 0,5 (бенч против бенча 0,48); K2x1,6 — 0,51–0,57.
  - Это равномерный шум в 1–3 уровня по камню и швам; заметен только при усилении ×20.
  - Видимых отличий нет: > 24 — 0,004–0,008 %.
  - Live против live на этом виде: 0,70 / 0,006 %.
  - Не убирается ни settle 14 с (0,62), ни точным повтором таймингов бенча (0,66), ни отключением `fresh` (0,61–0,68), см.
    `calibration.json`.
- Вывод для гейтов:
  - метрики по видимым отличиям и маскам фигур / зон на live-кадрах совпадают с бенчем;
  - для «до / после» снимать оба кадра в одной сессии;
  - приёмочные кадры снимать, как раньше, свежим `-Bench` или пакетным прогоном.

### Что пришлось исправить, чтобы кадры совпали

Числа a1 ↔ b2 по проходам (средняя / доля > 24 / вне шума).

1. Без `fresh`. K1 после K2-видов резче: в памяти остались мипы карты от K2, лапласиан 17,5 против 15,5. Sarpedon K1
   0,99 / 0,127 %.
   Решение — `r.Streaming.DropMips=1` до снимка первого вида и `r.LumenScene.SurfaceCache.Reset`. Стало 0,50 / 0,065 / 0,0003 %.
2. Часы анимаций: сдвиг от времени спавна. После reload позы отставали на 0,1 с: первый кадр после старта длинный, и клип
   получает его dt при спавне. Sarpedon K2x2,5 вне шума 0,089 %.
   Решение — смещение калибруется на старте сессии, позиция клипа выставляется абсолютно. Стало 0,031 %.
3. Паузы «снимок → следующий вид» по живому замеру. Фриз записи PNG в live меняется от кадра к кадру: 0,36–0,62 с. Cobble
   K2x2,5 вне шума 0,30 %.
   Решение — фиксированные паузы бенча: перебор (`calibration.json`) дал 0,55–0,60 с после первого снимка и 0,40–0,45 с после
   следующих; взяты 0,57 / 0,41. Стало 0,0004 % (Cobble) и 0,0001 % (Sarpedon).

## Ограничения

- Reload не покрывает:
  - C++;
  - меши, текстуры, материалы и инстансы (`ue_scene_material.py`, `ue_import_*`);
  - новые ассеты пакета;
  - `zoneStyles` / `glyphMeshes` / `zoneKeyline` — их загружает только BeginPlay, `reload` об этом предупреждает.

  Для всего этого нужен перезапуск.
- Позы и время мира совпадают с бенчем, если список видов кадра совпадает со списком видов бенча, с которым сравнивают.
  Порядок и паузы видов входят в модель.
- Паузы 0,57 / 0,41 с откалиброваны на этой машине в editor `-game`. На другом железе или для пакетного бенча их надо
  перепроверить: `--bench-gap`, `--bench-gap-later`, затем `compare`.
- `shot --live` (fx, мерцание, ветер включены) не воспроизводим по определению. Часы в этом режиме выключены.
